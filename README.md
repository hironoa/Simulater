# Simulater

RL78 向け組み込みソフトを、CC-RL の `.abs` または CA78K0R の `.lmf`のまま PC 上で実行するシミュレータ。

- WinAMS 用のテスト CSV を読み込み、同じ書式の結果 CSV を出力する（バッチ実行）
- ブラウザの画面で入力信号を変えながら、結果を波形でリアルタイムに見る（GUI 実行）
- 機械語をそのまま解釈実行するので、`int` 16 ビット、ポインタ幅、SFR のアドレス、アセンブラで書かれた処理は実機と同じに動く

仕様の詳細は [docs/DESIGN.md](docs/DESIGN.md)。

## 用意するもの

- **WinAMS に読み込ませている CC-RL の `.abs` または CA78K0R の `.lmf`**（テストドライバとスタブを含めて CS+ でビルドしたもの。デバッグ情報つき）
- WinAMS 用のテスト CSV
- `sim.exe`。次のどちらかで入手する
  - GitHub Actions の成果物 `sim-windows-x64`（`sim.exe`、`sim_gui.html`、`xlate` フォルダ、`sim.cfg` の見本）
  - リポジトリの `dist/sim-windows-x64/` フォルダ（CI を使えないときに手元でビルドして置いたもの。フォルダごと取り出して使う。ビルド元と確認の範囲は `dist/README.md`）
  - 自分でビルドする: MinGW-w64 gcc を PATH に入れ、`set CC=gcc` のあと `build.bat`（`build\sim\sim.exe` ができる）

Windows の配布物は速度を優先して MinGW-w64 gcc でビルドする（gcc のランタイムは静的リンク）。
GitHub のランナーの遅い機種で、コア単体のベンチマークは clang が 272、gcc が 350 百万命令/秒（速い機種ではほぼ同じ）。
どちらのビルドにも `-O2 -fno-unroll-loops` を付ける（[速度](docs/DESIGN.md#41-速度) を参照）。
LLVM の clang でもビルドできる。`CC` 未設定の既定は従来どおり clang（MSVC の C ランタイムと Windows SDK も要る）。

macOS / Linux では `./build.sh`（`build/sim/sim` ができる）。CMake、Python、Node は使わない。

## 最初に試す手順

```
sim info --abs DefaultBuild\project.abs -v     # 読み込めるか、main まで走るか、警告
sim list --abs DefaultBuild\project.abs g_     # 変数と関数の一覧（名前の一部で絞り込み）
sim run  --abs DefaultBuild\project.abs test.csv -o result
```

`--abs` は `.lmf` も受け付ける（上の `project.abs` を `project.lmf` に置き換える）。種類はファイル先頭で判定し、ABIを自動選択する。`sim info` で選択結果を確認できる。

`sim run` は結果 CSV を `result` フォルダに入力と同じ名前で作り、最後に件数（OK / NG / NO Check）と
実行した命令数・所要時間・命令/秒を表示する。NG が 1 つでもあれば終了コード 1、実行できないエラーは 2。
複数入力の出力先が同名（ASCII の大小文字違い・同一入力の重複を含む）なら、何も実行・出力せずエラー 2。別々に実行するか出力フォルダを分ける。
結果の出力先が入力の CSV そのもの（`./` や相対パスなど書き方が違っても同じファイル）になるときは、上書きせずにエラー 2。

スタートアップが止まったら `sim info --abs project.lmf --trace-startup`（ELF でも同じ）で調べる。
呼び出し履歴、停止位置と直前の命令、推定バックトレース、ループ候補と読んだ番地、書き込み前に読んだ SFR が出る。
周辺機能の状態は模擬しないため、実機では立つビットが 0 のままで、待ち続けたりリセット処理へ進んだりする場合がある。
`sim.cfg` の `poke = 0xFFFA2:1` で必要な初期値を与えるか、`skip = 関数名[:戻り値]` で待ち関数を即時復帰させる。
処理そのものの置換は `stub`、起動を止める位置の変更は `init_end` を使う。
ブレークポイントは先頭オペコードのフェッチ時だけ検出し、ROM/RAM のバイト列を変更しない。
ROM チェックサム、ミラーや `ES:` 経由のデータ読み出しにも元の値が見える。
プログラム自身の `FFH` を実行したときは停止し、実機では不正命令による内部リセットになることと、
ソフトが意図的にリセットした可能性を表示する（自動的なリセット・再実行はしない）。
具体的な読み方と制限は [スタートアップが通らないときの調べ方](docs/DESIGN.md#スタートアップが通らないときの調べ方) を参照。

## テスト CSV と結果 CSV

WinAMS の書式をそのまま使う。

```
mod,func1,func1単体テスト,3,2
#COMMENT,@enable,@mode,@input,gb_result.data,gb_result.ret_code
;,自由なコメント
,1,1,10,100,1
```

- 1 行が対象関数 1 回の呼び出し。変数は行をまたいで保持される
- 変数名: グローバル、`file.c/name`（ファイル内 static）、`file.c/func@name`（関数内 static）、`@引数`、`func@@`（戻り値）、
  `a.b` `a[2]` `p[0].m`、`$ptr`（実体の確保）、`&arr` / `*ptr`（`'文字列'` や `1|2|3`）、`0xFFF01:2`（アドレス直接指定）
- 結果 CSV: 出力セルに実測値、期待値と違えば `実測?(期待)`。右に判定（`OK` / `NG` / `NO Check`）と実行時間
- 入力の空セルは「設定しない」、出力の空セルは期待値なし。空文字列 `''` は書く（終端の 0）／比べる（空文字列か）
- 期待値は入力と同じ規則で解釈し、対象のビット幅に収まらない期待値は `NG` にする
- 文字コード（Shift_JIS / UTF-8。UTF-8 の BOM 付きも可）と改行コードは入力のまま保つ。UTF-16 は対応外（エラー）
- フォルダ名・ファイル名に日本語を使える（Windows でも。コマンドラインの引数と `sim.cfg` の中のパスのどちらも可。
  `sim.cfg` は UTF-8 でも Shift_JIS でもよい）
- `mod` 行がないファイルはエラー（終了コード 2）、実行するデータ行が 0 行のブロックは警告。`mod` / `#COMMENT` の
  大文字小文字・前後の空白・`"mod"` のような引用は受け付ける（詳しくは `docs/DESIGN.md` の 3 節）
- 結果 CSV を入力として読み直せる。**WinAMS の結果 CSV を入力にすると、WinAMS の実測値を期待値として
  このシミュレータの結果と突き合わせられる**（`--expect-actual` を付ける）

`modi` は初期化つきのブロックです。`#InitWheneverCall,変数名,...` と次の初期値行
（先頭セルはコメント欄）の後に `#COMMENT` と通常のデータ行を置きます。
`csv_init = auto | once | every`（既定 `auto`）、CLI の `--csv-init=...` で初期化時機を選べます。
`auto` は `#InitWheneverCall` なら毎行、それ以外の `#Init...` なら最初の行の前だけ。
書き込み順は初期値 → 行の入力 → 関数呼び出しで、空の初期値は書き込みません。
GUI の再生は初期化を独立した入力列へ展開して記録するので、保存した `mod` CSV を `sim run` で再実行しても順序を再現します。

`%,スタブ関数,元の関数`（例: `%,"AMSTB_read_adc","read_adc"`）の行は、WinAMS が書く置換（スタブ）の指定です。
`mod` / `modi` 行から最初のデータ行までの間（`#COMMENT` の前でも後でも可）に置けます。そのブロックを実行する間だけ
元の関数をスタブへ置き換え、ブロックが終われば解除します。`sim.cfg` の `stub` / `skip` と同じ関数なら `%` 行を優先します。
関数は `ファイル名/関数名`（例: `%,"AMSTB_xx","XXX.c/xx"`）でも書けます。ファイル名の大文字小文字は区別しません。
関数がロードモジュールに見つからなければ、そのブロックはエラーにして実行しません。
GUI で読み込んだ CSV の `%` 行も同じく有効になり、保存する CSV に書き出します。

## ヘッダからの直アドレス定義

`exec = native` では、`defines_scope` を明示しなければ、コンパイルするソースとそのヘッダーの直アドレス定義を自動で読み、CSV で名前を使えます。
`defines =` / `--defines` で追加のフォルダも読め、`defines_auto = off` で自動読み込みを止められます（既定 on）。
`defines_scope` を明示した場合はその指定に従い、`interp` / `xlate` の動きは変わりません。

ロードモジュールに載らない SFR マクロも、CSV の初期化・入出力、GUI の検索・監視・入力、`sim list` で使えます。

```ini
# sim.cfg からの相対パス。既定でサブフォルダの .h / .c / .inc も読む
 defines = ../product
 defines_exclude = .git
 ctype = u1 : u8
 ctype = typeBit : bits8
```

`--defines パス` でも追加できます。`(*((volatile u1*)0xFFFA4))` や
`(((volatile typeBit*)0xFFFA4)->b4)` を取り込みます。基本型・ヘッダの typedef と限定的な構造体宣言・
デバッグ情報のタグ・`ctype` の順に型を解決します。解決できない型の `b4` などは既定で8ビット内の
ビット番号と推定します（`defines_guess_bits = off` で停止）。推定・未解決・重複・値の式の対象外（`value-excluded`）の件数を `sim info` で確認してください。
直アドレスの左辺値だけを登録し、マスク・シフト・比較など値を加工するマクロは登録しません。
定数添字は要素サイズを掛けて番地を求め、`const`付きの型は読み取り専用にします。
キャストの外側のポインタ加減算は対象外です。番地計算は`(型*)(BASE + 2)`のように括弧内へ書いてください。
**SFR の周辺機能は模擬しません**。通常のSFRメモリで監視できるのはプログラムが書いた値で、入力として書けば
プログラムが読む値になります。PSW・SP・乗除算器など、CPUコアが模擬するレジスタは例外です。
品種やビルド構成を `#if` / `#ifdef` で切り替えているヘッダは、コンパイル時と同じ定義マクロを与えると、有効な枝だけを取り込みます。

```ini
 cdef = PRODUCT=2                 # 名前=値（複数行可。値を省くと 1）。コマンドラインは --cdef PRODUCT=2
 cundef = OLD_SWITCH              # 定義を外す
 mtpj = ../product/project.mtpj   # CS+ のプロジェクトファイルの「定義マクロ」を読む（--mtpj でも可）
 mtpj_mode = DefaultBuild         # ビルド・モード（省くと CS+ で選択中のモード）
 defines_cond = on                # off なら #if を評価せず、すべての枝を読む
```

### 読むファイルをプロジェクトに合わせる（defines_scope = mtpj）

既定では `defines =` のフォルダの下をすべて読みます。品種ごとに同じ名前のファイルをフォルダで切り替えている
プロジェクトでは、ビルドしない品種のファイルまで読んで「異なる重複」になります。次の設定で、読む範囲を
CS+ のプロジェクトと同じにできます（`defines =` のフォルダ指定は外してください。残すとその下も読みます）。

```ini
 mtpj = ../product/project.mtpj
 mtpj_mode = DefaultBuild         # 省くと CS+ で選択中のモード
 defines_scope = mtpj             # 既定は folder（defines のフォルダの下すべて）
 defines_include = ../product/inc # インクルード・パスを足す（複数行可。mtpj から読めなかったとき用）
```

- 起点にするのは、プロジェクトに登録されていて、選んだビルド・モードでビルド対象の `.h` / `.c` / `.inc` だけです。
- `#include` は、インクルード元のフォルダ、インクルード・パス（mtpj の「追加のインクルード・パス」、`defines_include`）の順に探し、
  見つけたファイルを読みます。登録されていないヘッダも、インクルードされていれば読みます。無効な `#if` の枝の `#include` は読みません。
- `sim info` に、登録ファイルの数（読んだ数、ビルド対象外、見つからないもの）、使ったインクルード・パス、
  上の順番で見つからなかった `#include` の数を表示します。**ビルド対象の判定とインクルード・パスの書式は実例からの推定**なので、
  CS+ の画面と見比べ、足りないパスは `defines_include` で足してください。

`sim info` に、読み取った定義マクロ、評価した `#if` の数、判定不能だった数、**条件に使われたがどこにも定義がなく
0 とみなした識別子**（スイッチの指定漏れの候補）を表示します。`mtpj` の定義マクロの書式は実例からの推定を含むので、
表示された一覧を CS+ のコンパイル・オプションの画面と見比べてください。`sim list --where` は、取り込んだ定義ごとに
定義元のファイル名と行番号を表示します。評価の規則と限界は [docs/HEADER_DEFINES.md](docs/HEADER_DEFINES.md) を参照。
明示定義は `var = P1 : u8 @ 0xFFF01`、`varfile = registers.txt` でも追加できます。
`u8[16]` の配列や `u8.4-6` のビット範囲も指定でき、明示定義が同名シンボルより優先します。
対応する構文と制限は [ヘッダ取り込み](docs/HEADER_DEFINES.md) を参照してください。

LMF の未対応型は、`sim info` または `--verbose` で記憶クラス・型コード・派生型・セクション種別ごとの件数を
名前なしの表にまとめます。`-v -v` / `--lmf-names` では各組み合わせの名前を最大3個表示します。
型情報がないアセンブラ等のシンボルは別の件数表示です。有効な絶対アドレスの未知型も `名前:バイト数` で使用できます。

## GUI

対象関数が未設定の間は実行・ステップと未記録の CSV 保存を拒否します。画面で対象関数を選ぶか `--func` で指定してください。

```
sim gui --abs DefaultBuild\project.abs --func <周期関数> --period-ms 5
```

既定のブラウザ（Chrome / Edge）で画面が開く。1 周期ごとに指定した関数を 1 回呼ぶ。

- 実行 / 一時停止 / ステップ実行 / リセット、速度の倍率
- 入力パネル: 変数を検索して追加し、数値・スライダ・トグル・押している間だけ 1 のボタンで値を変える。固定（毎周期書き続ける）もできる。
  書いた値は一時停止中でもすぐにはメモリに入らず、次の周期（ステップ）の初めに入る。それまでは「反映待ち」として表示し、
  同じ変数に書き直せば最後の値だけが入る
- 変数モニタ: 現在値を 10 進 / 16 進で表示。構造体や配列は展開して選べる
- 波形: 実行中は直近の点を流し、一時停止すると全区間をズームやカーソルで調べられる
- 記録を WinAMS 形式の CSV で保存、テスト CSV の読み込みと再生。保存した CSV は `sim run` でそのまま再実行できる
  （入力は書いた値の表記のまま残す）。1 周期の入力は、`sim run` が CSV の 1 行を処理するのと同じく、周期の初めに
  保存する CSV の入力列の順に、列ごとに最後の 1 個だけ書くので、同じメモリを指す固定と単発書き込みを併用しても、
  停止中に何度か書き直しても再実行と合う。監視も入力もない周期の行は、1 列目（コメント欄）に `step N` を入れて
  保存するので、再実行でも同じ回数だけ関数を呼ぶ。テスト CSV の再生は読み込んだ CSV の入力列の順に書く。
  `#Init...` にだけ現れる変数は監視に自動追加せず、通常の入力列・出力列にもある名前は一度だけ追加する。
  同じ名前の入力列が複数あるテスト CSV は GUI では読み込めない（`sim run` で実行する）。`mod` ブロックが複数あれば
  先頭のブロックだけを再生する。
  周期関数を切り替えるとリセットして記録を始め直す。
  切り替えた先の関数にない引数（`@rpm` など）や前の関数の戻り値の固定・監視は外す

### 仕向（ライブモードの初期化の値）

テスト CSV の `#InitWheneverCall` などで書いている初期化の値（コンフィグ値）を、仕向（出荷先）ごとに登録して、
CSV を再生しないライブモードでも入れられる。右側の「仕向」で選ぶと、その値を sim に送る。

- 書き方は値ごとに「最初だけ」（リセット後の最初の周期の前に 1 回）か「毎回」（毎周期の初め）を選ぶ。
  `csv_init = once` / `every` で CSV を再生したときと同じ。同じ変数に入力パネルの書き込み・固定・CSV の再生があれば、そちらが勝つ。
- 「最初だけ」の値を変えたときや仕向を切り替えたときは「リセットして反映」を押す（次のリセットまで書かない）。
- 値の表で、変数の検索の「行を追加」、値の入力（Enter か欄を離れると送る）、書き方の選択、行の削除ができる。
- 「CSV から取り込み」で選んだテスト CSV の `#Init...` の見出しと次の 1 行から、仕向を 1 つ作る（名前はファイル名）。
  テスト CSV の再生（「テスト CSV 再生」）では仕向を変えない。
- 「ファイルに保存」で `sim.cfg` と同じフォルダの `sim_gui_variants.json` に保存し、次に `sim gui` を起動すると自動で読み込む。
  保存先は sim.cfg の `gui_variants = パス`（相対なら sim.cfg のフォルダから）で変えられる。ファイルが読めないときは表示だけして、
  勝手に上書きしない。ファイルは手で書いてもよい:

```json
{
  "version": 1,
  "selected": "国内",
  "variants": [
    { "name": "国内", "values": [ { "name": "g_cfg_dest", "value": "1", "mode": "once" } ] },
    { "name": "北米", "values": [ { "name": "g_cfg_dest", "value": "2", "mode": "once" } ] }
  ]
}
```

画面は [SignalViewer2](https://github.com/hironoa/SignalViewer2) を取り込んで作っている。
`sim_gui.html` を直接開けば、従来どおり CSV を読む Viewer として使える。

## 速い実行方式（C への変換）

既定では、ロードモジュールの命令を 1 つずつ解釈して実行します（解釈実行）。`exec = xlate` にすると、
ロードモジュールの機械語を C に変換し、PC 用にコンパイルしたもので実行します。結果は解釈実行と同じで、数倍速くなります。

```
sim run --exec xlate --abs X.lmf テスト.csv        （または sim.cfg に exec = xlate）
```

- **必要なもの**: clang（LLVM の配布物 `clang+llvm-…-x86_64-pc-windows-msvc.tar.xz` を展開したもので可。インストールも
  Windows SDK も要りません）。`sim.cfg` に `xlate_cc = C:\tools\clang+llvm-18.1.8-x86_64-pc-windows-msvc\bin\clang.exe`
  のように書くか、`clang` に PATH を通します。`sim` の実行ファイルの隣の `xlate` フォルダも必要です（配布物に入っています）。
- **初回**: 変換結果がまだないので、解釈実行で動かします（速さは今までどおり）。このとき通った関数を記録し、実行が終わってから
  その関数だけを変換・コンパイルします（結果の CSV はその前に出ています）。
- **2 回目以降**: 変換結果を読み込んで実行します。変換していない関数に入ったら、そこだけ解釈実行します（結果は同じ）。
  新しく通った関数は、実行が終わってから追加で変換します。
- **変換結果の置き場所**: ロードモジュールの隣の `.simxl` フォルダ。ロードモジュールや `sim` を作り直すと自動で作り直し、
  古いものは消します。フォルダごと消しても構いません（次の実行で作り直します）。
- **先に全部変換しておく**: `sim xlate --abs X.lmf`（関数が多いと数分かかります）。GUI（`sim gui`）は終了時に変換しないので、
  GUI で速い方式を使うときは、先に `sim xlate` か `sim run --exec xlate` で変換しておいてください。
- **コンパイルの進み具合**: 長くかかるときは、完了したファイル数・経過秒数・実行中のファイルを表示します（`--quiet` では非表示）。
  キャッシュ内の `cc_times.txt` に今回コンパイルしたファイルの秒数を長い順に記録し、30 秒以上かかったものは終了後にも表示します。
- **確かめる**: `--exec verify`（`exec = verify`）は、呼び出しごとに変換したコードと解釈実行の両方で実行し、レジスタ・命令数・
  クロック数・メモリ全体が一致することを確かめます（遅くなります）。食い違ったらその行をエラーにします。
- 実行の最後に `変換したコードで実行: N 命令（P%）` と表示します。`sim info --exec xlate` で変換済みの関数の数が分かります。
- clang を起動できない、コンパイルに失敗した、といった場合は理由を表示して解釈実行のまま続けます（結果には影響しません）。
- `rom_size` を指定していなければ、0xF0000 より下（コードフラッシュ）を書き込み禁止として扱います（プログラムからの書き込みを無視）。

## 製品の C ソースを PC 用にコンパイルして実行する方式（exec = native、作成中）

ロードモジュールの命令を使わず、製品の C のソースを clang で PC 用にコンパイルした DLL を呼ぶ方式です。RL78 の命令を再現しない
ので速い代わりに、実機と同じ結果にはなりません（下の「変わること」）。**段階 3（スタブへの置換まで）は完了し、Windows でだけ動きます。**
GUI は、これから足します。

番地を書いた `#define`（レジスタなど）の名前は、コンパイルするソースとそのヘッダーから自動で読み、CSV で使えます。
`defines =` を足せば追加のフォルダも読め、`defines_auto = off` で自動読み込みを止められます。
`defines_scope` を明示した場合はその指定に従います。

```ini
# sim.cfg（ドライバやスタブの側に置く）
exec = native
mtpj = ../product/project.mtpj          # 製品のプロジェクト。入れ替えるときはここだけ変える
native_src = .                          # 製品とは別に管理する .c（ドライバ、スタブ）。ファイルかフォルダ。複数行可
native_opt = 0                          # 最適化。0（既定）または 2
native_near = on                        # 1〜0xFFFF の整数をポインタにするとき 0xF0000 を足す。on（既定）または off
native_layout = ../product/DefaultBuild/project.lmf   # 変数のマイコンでの番地を読む（RAM の範囲のクリアに使う。下の説明）
native_cc = C:\tools\clang+llvm-18.1.8-x86_64-pc-windows-msvc\bin\clang.exe
```

```
sim info --cfg sim.cfg                  ソースの数、アセンブラの一覧、DLL の場所、呼べる関数
sim run  --cfg sim.cfg テスト.csv -o result
```

- **必要なもの**: clang（変換方式と同じく、LLVM の配布物を展開したもので可。Windows SDK は要りません）と、
  `sim` の実行ファイルの隣の `native` フォルダ（配布物に入っています）。`native_cc` を書かなければ `xlate_cc`、
  環境変数 `SIM_XLATE_CC`、PATH の `clang` の順に探します。
- **コンパイルするもの**: mtpj の登録ファイルのうちビルド対象の `.c` と、`native_src` の `.c`。インクルード・パスと
  定義マクロは mtpj から取ります（`native_include`、`cdef`、`cundef` で足せます）。`.asm` はコンパイルせず、
  `sim info` に一覧を出します。
- **どの .c にも定義がない関数・変数**（アセンブラの中にあるものなど）: sim が代わりを自動で作ってリンクします。
  関数は何もせず 0 を返し、変数は 0 で埋めた領域（C の宣言の大きさ。`extern u1 t[];` のように大きさが分からないものは
  4096 バイト）になります。関数か変数かは、その名前を使っているソースの宣言から決めます。代わりを作った名前は
  `sim info` に一覧で出ます。本来ならリンクでエラーになる打ち間違いもリンクが通るので、一覧で確かめてください。
  動きが必要なものは、同じ名前の関数（変数）を C で書いたファイルを `native_src` に置くと、そちらが使われます。
  C の識別子にできない名前は代わりを作らず、リンクでエラーになります。代わりはデバッグ情報を持たないので、
  CSV の対象関数には指定できません。`float` / `double` を返す関数の代わりは 0.0 を返します。
  構造体を返す関数など、代わりが 0 を返せないものは警告を出し、一覧に「（戻り値は 0 になりません）」と添えます。
- **初回と 2 回目以降**: 初回に全部コンパイルして DLL を作ります。結果は `sim.cfg` の隣の `.simnative` フォルダに置き、
  次からは、変わったソース（インクルードしているヘッダーが変わったものを含む）だけコンパイルし直します。
  コンパイルし直すときは、ソース名と理由を最大 20 件表示します。依存ファイルが変わったときや読めないときは、
  そのパスも表示します。`--verbose` を付けると初回の理由も表示し、`sim info` では理由ごとの件数を確認できます。
  コンパイル後に依存ファイルや依存一覧を読めないか、署名を保存できないときは、警告を出し、次回もそのソースを
  コンパイルし直します。旧書式の署名は一度コンパイルし直して更新します。
  フォルダごと消しても構いません。場所は `native_dir`、並列数は `native_jobs` で変えられます。
- **変数と関数**: 型は DLL のデバッグ情報から取ります。static の関数も呼べます。
  変数はグローバル名、`file.c/name`（ファイル内 static）、`file.c/func@name`（関数内 static）で読み書きできます。
  構造体の `a.b`、配列の `a[2]` / `a[1][2]`、ビットフィールドのメンバも指定できます。ポインタは 64 ビットで読みます。
  `native_opt` は既定 0。2 にすると速くなりますが、書き換えない static 変数などが定数に畳まれ、CSV から
  読み書きできなくなることがあります。どこからも使われない static 変数は、0 でも DLL に入りません。
- **スタブへの置換**: `stub`、`stub_auto`、`skip`、CSV の `%` 行が使え、書き方とブロックごとの切り替えは今の方式と同じです。
  DLL 内の元の関数の入口を書き換え、スタブへの分岐または戻り値を返す処理に置き換えます。
  `ファイル名/関数名` で static 関数も指定でき、アセンブラの関数（sim が代わりを作ったもの）も置き換えられます。
  浮動小数を返す関数の `skip` は戻り値 0（省略可）だけ指定できます。
  `native_opt = 2` では、同じファイルの中から呼ぶ関数が呼び出し元に埋め込まれて置換が効かなかったり、
  static 関数が DLL に残らず見つからない（エラーになる）ことがあります。置換を使うときは `native_opt = 0`（既定）にしてください。
- **CA78K0R 独自の書き方**: `__far`、`sreg`、`callt`、`norec`、`boolean`、`bit`、`DI()` などは、sim が各ソースの先頭に
  差し込むヘッダーで吸収します。`__asm("…")` は関数の内外とも空にし、数を `sim info` に表示します。製品のソースは書き換えません。
- **番地**: 0xF0000〜0xFFFFF は同じ番地にメモリを確保するので、`#define REG (*(volatile unsigned char *)0xFFF01)` の形の
  レジスタや、番地を直接書いた RAM がそのまま動きます。CSV では `0xFFF01:1` の形で読み書きできます。
  **0x10000 より下の番地は再現できません**（読み書きすると、その番地を表示してその行がエラーになり、次の行へ進みます）。
- **整数からポインタへの変換（near の番地）**: RL78 の near のポインタは 16 ビットで、実際の番地は 0xF0000 を補ったものです。
  そこで、整数をポインタに変えるときは、値が 1〜0xFFFF なら 0xF0000 を足した番地として扱います（`native_near = on`、既定）。
  0（NULL）と 0x10000 以上（5 桁で書いた番地や、PC の本物のポインタ）は変えません。次のように 16 ビットに切り詰めてから
  ポインタにする書き方も、0xFFFD4 を読み書きします。

  ```c
  #define BASE_ADR   0x0FFFD4u
  #define ADDR(v)    ((unsigned int)(v))          /* マイコンでは 16 ビット */
  #define BLK        ((volatile tBlk __near *) ADDR(BASE_ADR))
  BLK->reg = 1;                                   /* 0xFFFD4 に書く */
  ```

  番地が実行時に決まるもの（表に入れた 16 ビットの番地など）も同じ規則で読み替えます。関数へのポインタに変える場合
  （`((void (*)(void))0x1234)()` など）にも同じ規則がかかります（PC ではどのみち呼べない番地です）。
  PC の変数の番地を `unsigned short` に入れて戻したものは、上位が失われているので直せません。
  読み替えた数は `sim info` の「整数からポインタへの変換」に出ます。`native_near = off` で読み替えをやめられます。
- **実行中のエラー**: 0 での割り算は、マイコンとは異なり PC では例外になります。例外が起きた行は NG になり、次の行へ進みます。
  戻ってこない関数は `native_timeout_ms`（既定 10000 ミリ秒 = 10 秒）で止めます。0 なら無効、0〜86400000 を指定できます。
  周辺機能は模擬しないので、レジスタのビットが変わるのを待つループには、CSV で値を入れるかスタブを用意してください。
  例外や時間切れのあと、DLL の変数は途中の状態のまま残ります。次の行もその状態から実行し、mod のブロックが変わればリセットします。
- **止まった場所**: 例外の行と時間切れの行には、止まったソースのファイル名と行番号を表示します
  （例: `止まった場所: io.c の 24 行目（C:\proj\src\io.c:24）`。時間切れは「止めたときに実行していた場所」）。
  呼んだ関数の先の関数で止まったときはその関数名、`native_opt = 2` でインライン展開された関数の中ならその呼び出し元も出ます。
  ヘッダーのマクロ（レジスタの定義など）の中で止まったときは、マクロを使った行になります。`native_opt = 2` では行が少しずれることがあります。
  調べるのに LLVM の配布物の `llvm-symbolizer` を使います。clang と同じフォルダにあれば（LLVM の配布物には入っています）
  追加の設定は要りません。別の場所なら `native_symbolizer = <パス>` で指定します。見つからないときは DLL の中の位置だけを出します。
  場所を調べるのは 1 回の実行で 20 件までです（1 件に数十ミリ秒かかり、その行の実行時間に含まれます）。
- **番地の小さい読み書き（0x10000 より下）で止まるときの主な原因**:
  4 桁で書いた near の番地（`0xFE00` など）は、上の読み替えで 0xF0000 台になるので止まりません（`native_near = off` では止まります）。
  残る主な原因は、ポインタが 0 のまま（0 は NULL のままにします。番地 0 からの小さなずれ、たとえば NULL の構造体のメンバを
  読むと止まります。マイコンではスタートアップや別の初期化の関数で設定されます）と、PC の変数の番地を 16 ビットの整数
  （`unsigned short` など）に入れたもの（PC のポインタは 64 ビットなので、下位だけが残り、読み替えても別の番地になります）です。
  スタックの使い切りだけは復帰できず、sim が終了コード 2 で終了します。呼び出し失敗の行は既存方式と同じ NG 集計で、終了コードは 1 です。
- **マイコンの番地の範囲で RAM をクリアする処理（アセンブラの関数など）**: native では、C の変数はマイコンの RAM の番地ではなく、
  DLL の中の別の場所に置かれます。そのため、番地を数字で渡して範囲をクリアする関数（`ram_clear((u2 *)0xFD700, (u2 *)0xFD7FF)`
  など。アセンブラで書かれていれば、sim が「何もせず 0 を返す」代わりを作ります）を呼んでも、C の変数は 0 になりません。
  `native_layout = <ロードモジュール>`（CA78K0R の `.lmf` か CC-RL の `.abs`。`sim.cfg` のフォルダからの相対パス可）を書くと、
  sim がロードモジュールから変数のマイコンでの番地と大きさを読み（今の方式と同じ読み取り）、DLL の変数と名前で対応づけます。
  グローバルの変数は名前だけで、static の変数（ファイル内、関数内）は関数名と、ファイルのパスの末尾から同じ部分がいくつ続くか
  （区切りの / と \ の違いと、Windows では大文字小文字の違いは吸収）で相手を選びます。製品と `native_src` の両方の変数から、
  一致の強いものを先に決め、同じ強さの相手が複数あるときは、どれとも対応づけません（あいまい）。
  CA78K0R の `.lmf` は、変数のファイルをパスなしの名前（`app.c`）で持つので、**同じファイル名のソースが製品と
  テストドライバ（`native_src`）の両方にあり、同じ名前の static の変数があると、その変数は対応づけられず、クリアされません**
  （`sim info -v` の「あいまい」の一覧に候補のファイルと一緒に出ます）。
  そのうえで、関数の代わりから DLL に入っている部品を呼ぶと、範囲の中の変数と、毎回クリアする native_src の変数を 0 にします。

  ```c
  void sim_native_clear_range(unsigned long long first, unsigned long long end);       /* [first, end)。end は含まない */
  void sim_native_clear_range_incl(unsigned long long first, unsigned long long last); /* [first, last]。last の 1 バイトまで */
  ```

  宣言は sim が各ソースの先頭に差し込むヘッダーにあるので、`#include` は要りません。ひな形
  [example/native_ram_clear.c](example/native_ram_clear.c)（配布物では `sim` の隣の `native_ram_clear.c`）を `native_src` の
  フォルダにコピーし、関数名と引数を製品のアセンブラの関数に合わせて書き換え、終わりの番地を含むかどうかで 2 つのどちらかを
  使ってください。番地は `(unsigned long long)(unsigned long)first` のように整数にして渡します。呼ぶ側が `(u2 *)0xD700` と
  16 ビットで書いていても、上の読み替え（`native_near`）で 0xFD700 になっています（`native_near = off` でも、部品が 1〜0xFFFF に
  0xF0000 を足します）。

  | 変数・データ | クリアする条件 |
  |---|---|
  | ロードモジュールと対応づいた C の変数（製品のプロジェクト（mtpj）と `native_src`） | 番地が範囲に入るとき |
  | 番地を直接書いたデータ（0xF0000〜0xFFFFF。製品のソースの `#define` でも、`native_src` のテストドライバの `#define` でも、CSV の `0xF….:1` でも） | 番地が範囲に入るとき |
  | ロードモジュールと対応づかなかった `native_src` の C の変数 | 範囲にかかわらず、有効な呼び出しのたび |
  | const の変数・読み取り専用の変数 | クリアしない |

  - 毎回クリアするのは、対応づけに使われず、あいまいな組の候補にもならなかった、大きさが分かる書き込み可能な `native_src` の変数です。
  - 対応づいた変数のうち範囲に全部入っているものは、PC の側の大きさで全体を 0 にします。配列や構造体が範囲の境界を
    またぐときは、マイコンと PC で大きさが同じなら、重なっているバイトだけを 0 にします。大きさが違う（ポインタを含む構造体、
    `long` を含む構造体のすき間、`enum`、`double` など）ときはクリアせず、変数の名前を添えて警告を 1 度出します。
  - 番地を直接書いたデータのためのメモリ（0xF0000〜0xFFFFF）は、範囲に入っていればどこでも 0 にします。テストドライバが
    番地の指定で読み書きする領域も、範囲に入っていれば 0 になります。
  - `native_layout` がないときに呼ばれると、番地を直接書いたデータだけを 0 にし、C の変数はクリアできない旨の警告を 1 度出します。
    先頭 ≧ 終わり、0x100000 を超える範囲などは、何もせず警告を 1 度出します。
  - ロードモジュールは、**製品のソースと同じビルドのもの**を使ってください。違うと番地がずれて、別の変数をクリアします。
    製品だけをビルドしたものでも、テストドライバを含めてビルドしたものでもかまいません。WinAMS の結果と比べるなら、
    WinAMS に読み込ませているもの（製品の変数の番地が、比べる相手と同じになる）を勧めます。読めなければエラー（終了コード 2）です。
  - `sim info` に対応づけの数が出ます（`native layout vars=… matched=… unmatched=… size_diff=… dll_only=… src_always=… ambiguous=…`）。
    `matched` には `native_src` の変数との対応も含みます。
    `unmatched` はロードモジュールにだけある変数（アセンブラで確保した RAM、PC 側で使われずに消えた変数など）、`dll_only` は
    製品のソースにあってロードモジュールと対応づかなかった変数、`src_always` は毎回クリアする `native_src` の変数、`ambiguous` は同じ強さの相手が複数あって対応づけなかったものです。`-v` を付けると、それぞれの名前を 50 個まで出します
    （関数内 static は `ファイル名/関数名@変数名`）。
  - `native_opt = 2` では、書き換えない static 変数（関数の中の static を含む）が最適化で消えたり定数に畳まれたりして、
    対応なし（`unmatched`）になることがあります。対応なしの変数は、DLL に実体がないのでクリアもされません。
  - アセンブラで確保した RAM の変数は、sim が作る代わり（どの .c にも定義がない変数）にデバッグ情報がないので、対応づけられず、
    クリアされません。
- **変わること**: プリプロセス後の書き直しで `int` を 16 ビットにします。`long int` / `short int` や、`unsigned` / `signed` だけの宣言にも対応します。
  計算の途中の桁は PC の規則（32 ビット）になります。
  `unsigned short` の 40000 + 40000 を比較に使うと、マイコンでは 14464、PC では 80000 です。ポインタは 64 ビット、
  構造体のすき間とビットフィールドの並びは clang のものです。実行クロック数は出ません。
- **まだできないこと**: `#asm`〜`#endasm` と `__asm { … }` の形には対応しません。
  型を書かない宣言（`static x;`、戻り値の型を省いた関数）は PC の `int`（32 ビット）のままです。
  標準ヘッダーは clang に付いてくるもの（`stdint.h`、`stddef.h`、`limits.h` など）だけが読めます（`string.h` など
  C ライブラリのヘッダーはありません）。システムヘッダーは書き直さないので、`uint32_t` などは正しい幅になりますが、
  `INT_MAX` など標準ヘッダーの値は PC のものです。
  コンパイルのエラーのときはコンパイラの出力の場所（`cc.log`）を表示して、終了コード 2 で止まります（解釈実行には切り替えません）。

仕組みは [docs/DESIGN.md](docs/DESIGN.md#43-pc-用-dll-の方式exec--native) を参照。

## 設定ファイル sim.cfg

`--cfg` で指定したファイルを優先する。指定がなければ、ロードモジュール（`.abs` / `.lmf`）と同じフォルダの `sim.cfg`、
開けなければ実行したフォルダの `sim.cfg` の順に探し、最初に開けたものだけを読む。
`sim info` の「設定ファイル:」行で読まれたファイルが分かる（読んでいなければ「なし」）。
見本は [example/sim.cfg](example/sim.cfg)。読めない値（数値でない、範囲外など）は、
既定値に置き換えずにエラー（終了コード 2）で止まる。主な項目:

| キー | 内容 |
|---|---|
| `char_unsigned = on \| off` | LMFのchar/signed charをunsignedにする（既定off、-qu相当） |
| `abi = auto \| ccrl \| ca78k0r` | 呼び出し規約。auto は ELF→CC-RL、LMF→CA78K0R |
| `stub = 元の関数:スタブ関数` | 元の関数が呼ばれたらスタブへ飛ばす（WinAMS の「置換」）。複数書ける |
| `skip = 関数名[:戻り値]` | 中身を実行せず通常の RET と同じように戻る。複数指定可 |
| `poke = 番地:値[:バイト数]` | リセット直後に物理番地へ初期値を書く。バイト数は既定1、1〜4。複数指定可 |
| `stub_auto = on` | `AMSTB_<関数名>` がある関数をすべて置換する |
| `core = auto \| S1 \| S2 \| S3` | CPU コア種別。品種が分からなければ `auto`（既定） |
| `cpu_hz` | CPU クロック。結果 CSV の実行時間の換算に使う |
| `exec` | 実行方式。`interp`（既定）/ `xlate` / `verify` / `native`（作成中） |
| `init_end` | 初期設定終了アドレス（既定 `main`） |
| `func` | GUI の既定の周期関数 |
| `halt` / `stop` | HALT / STOP 命令を読み飛ばすか、エラーにするか |
| `max_insns` | 1 回の呼び出しの命令数の上限（暴走の検出） |

## 制限

- CA78K0R の LMF は基本型（float/doubleは4バイト）、構造体・共用体・enum・ビットフィールド、最大4次元配列、
  near/far・多重ポインタ・関数ポインタ、static、関数の引数と戻り値の型を復元する。typedef名は展開される。
  signed int のビットフィールドはunsignedと区別できずunsignedとして扱う。char/signed charも同じコードで、
  既定はsigned、`char_unsigned = on`で両方unsignedに切り替える。
  bit変数、5次元以上の配列、関数の派生型戻り値など不明な形は型不明として警告する。
  構造体の値渡し・戻り値と浮動小数の引数は対応外。関数ポインタの引数型はLMFに残らない。
  ミディアムモデルの4バイト第1引数（AX/BC）と4バイト戻り値（BC/DE）に対応。スモール/ラージモデルは未確認。
  同名 `.sym` は照合用、およびデバッグ情報が全くないLMFのアドレス補助として読む。HEX単独入力は未対応。

- 周辺機能（タイマ、シリアル、A/D など）は模擬しない。SFR は読み書きできるメモリとして扱う。
  割り込みは、テストドライバがハンドラ関数を直接呼ぶ前提
- 対象関数の引数は整数 / ポインタ 8 個まで。浮動小数や構造体の値渡しの引数は使えない
- 結果 CSV の実行時間は、実行したクロック数からの換算値。WinAMS の値と一致するとは限らない
- CPU コアは、ルネサスのソフトウェアマニュアルと GNU の RL78 シミュレータとの差分テストで検証している。
  実機や WinAMS との突き合わせはしていないので、最初は WinAMS の結果 CSV と比べて確かめること。
  マニュアルの解釈が分かれる点は [rl78/README.md](rl78/README.md) にまとめてある
