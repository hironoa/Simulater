# CA78K0R `.lmf` 形式仕様（実測ベース）

対象: CA78K0R が出力するロード・モジュール・ファイル。解析スクリプト: `tools/lmfdump.py`（本仕様のリファレンス実装。`python3 -I` で実行する）。

確度の凡例:
- **【多】** 公開サンプル 5 件すべてで確認（バイト列・件数が一致）
- **【P】** 試験用ソース `tests/ca78k0r_probe/probe.c` のビルド結果（probe）で確認。初期値・`.map`・`.sym`・C の宣言と突き合わせ済み（§9）
- **【1】** 公開サンプル 1 件のみで確認
- **【推】** 実測値と整合するが他の根拠が薄い推測
- **【不】** 不明 / サンプルに現れなかった

材料:
- 公開サンプル 5 件: rongkunxue/XJTU-Automation-share（BSD-3-Clause）。すべて RL78/G13 R5F100LG、CA78K0R V1.60、リンカ W1.70、small モデル（末尾の一覧）。構造体などの型は含まない。
- probe: 利用者が `probe.c` を CA78K0R V1.60（リンカ V1.70）で `-g`、リンクに `-kp -kl`、ミディアムモデル（`-bcl78m -bcl78mf`）、RL78/F14 R5F10PGH（lmf のデバイス名は `dr5f10pgh.dvf`）向けにビルドした結果。`.lmf` `.map` `.sym` `.mot`（Motorola S レコード）つき。構造体・共用体・enum・ビットフィールド・多次元配列・near/far ポインタ・関数ポインタ・typedef・const・volatile・各種 static・各種引数と戻り値の関数を含む。
- 78K0R 品種の lmf は入手できず未確認（§10）。エンディアンはすべてリトル。

## 1. 全体配置【多】
```
0x00   ファイルヘッダ     20 B
0x14   オプションヘッダ   f_opthdr B（68）
0x58   セクションヘッダ   52 B × f_nscns
       …                  セクション内容・行番号表など（§3、§7）
f_symptr                  シンボル表: 20 B × f_nsyms（補助エントリも 1 個と数える）
f_symptr + 20·f_nsyms     文字列表: 先頭 u32 = 表全体の長さ（この 4 B を含む）、以降 NUL 終端文字列。ファイル末尾まで
```
標準 COFF との違い: シンボル・補助エントリが **18 B ではなく 20 B**、セクションヘッダが 40 B ではなく **52 B**、再配置表なし。
`.map` の「N output segment(s)」= f_nscns、「N symbol(s) defined」= f_nsyms【多】【P: 24 と 508】。
**シンボル番号**（後述のタグ参照・`.bf` の補助エントリなどが使う番号）は、補助エントリも 1 個と数えた 0 始まりのエントリ番号（`f_nsyms` と同じ数え方）【P】。

## 2. ヘッダ
### ファイルヘッダ（20 B）【多】
| off | 幅 | 名前 | 値 |
|---|---|---|---|
| 0 | u16 | f_magic | 0x1148 |
| 2 | u16 | f_nscns | 出力セグメント数 |
| 4 | u32 | f_timdat | Unix 時刻（ビルド日時） |
| 8 | u32 | f_symptr | シンボル表のファイル位置 |
| 12 | u32 | f_nsyms | シンボルエントリ総数（補助込み） |
| 16 | u16 | f_opthdr | 68 |
| 18 | u16 | f_flags | 0x0003 |

### オプションヘッダ（68 B）
意味は【不】。判明分のみ: オフセット 24 から 16 B にデバイスファイル名（NUL 詰め。`dr5f100lg.dvf`、probe は `dr5f10pgh.dvf`）【多】【P】。
他のバイトは `XX9a0000 00000001 00000000 08000000 28000000 30000000 | 名前16B | 60020000 70017001 YY010200 00000000 ZZ000000 00400000 00000000`。**デバイスごとに XX（先頭 1 B。0x7e / 0xb9）、YY（0x12 / 0x11）、ZZ（0x00 / 0x02）が違う**【P】が意味は【不】。読み飛ばしてよい（f_opthdr で長さを取る）。

## 3. セクションヘッダ（52 B）【多】【P】
リンカの「出力セグメント」1 つにつき 1 個。**同名が複数並ぶ**（`@@CNSTL` は PAGE64KP のためモジュールごとに 1 個）。番号（scnum）は 1 始まりの並び順。
| off | 幅 | 意味 |
|---|---|---|
| 0 | char[8] | 名前（NUL 詰め） |
| 8 | u32 | paddr: 開始アドレス（RAM は 0xFxxxx の 20 ビットアドレス） |
| 12 | u32 | vaddr（paddr と同値） |
| 16 | u32 | size: メモリ上の大きさ（`.map` の SIZE と一致） |
| 20 | u32 | fsize: ファイル中の内容の大きさ。ROM 側は size と同じ、RAM 側は 0 |
| 24 | u32 | ptr_A: 12 B レコード表の位置（fsize>0 のとき。0 なら無し） |
| 28 | u32 | ptr_B: 内容（生データ）の位置。fsize を 4 の倍数に切り上げて次の内容が続く |
| 32 | u32 | ptr_C: 常に 0 |
| 36 | u32 | ptr_D: 行番号表の位置（nlnno>0 のとき） |
| 40 | u32 | nA: ptr_A のレコード数（内容があれば 1） |
| 44 | u16 | nlnno: 行番号エントリ数 |
| 46 | u8 | k1: 0x20=ROM 側（コード・定数・ベクタ・オプションバイト） 0x40=RAM データ 0x60=ビット（@@BITS） |
| 47 | u8 | k2: 0x10=絶対配置(CSEG AT / DSEG AT / OPT_BYTE / 無名の CSEG) 0x20=コード(BASE 等) 0x80=データ・定数。@@BITS は 0x20 |
| 48 | u32 | z: `@@CNST`（`CSEG MIRRORP`）のみ 0x10、他は 0 |
ptr_A のレコード（12 B）= `u32 addr, u32 0, u32 size`（セグメント範囲の複写）。実装には不要。
k1/k2 と `.map` の属性の対応は FunctionDemoCode の全 40 セグメントで目視確認【1】。メモリに置くかどうかは **fsize>0 かどうかだけ**で判定できる（k1/k2 に依存しない）。

### メモリイメージの作り方
```
for sec in sections:
    if sec.fsize > 0:  image[sec.paddr + i] = file[sec.ptr_B + i]   (i < fsize)
```
- ROM 側（k1=0x20）のみが内容を持つ。コード `@@LCODE/@@BASE/@@CODEL/@@LCODEL`、ベクタ `@@VECTnn`（`CSEG AT`）、`?CSEGOB0`（0xC0 オプションバイト 4B）、`?CSEGSI`（0xC4 10B）、`?OCDSTAD`（0xCE 10B。サンプルのみ）、定数 `@@CNST`（フラッシュ上の実アドレス。probe は 0x3000 から。CPU からはミラー 0xF3000 で見える）、**初期値つきデータの ROM 側 `@@R_INIT`**（`@@RLINIT`/`@@R_INIS` も同種）。
- RAM セグメント（`@@DATA`, `@@INIT`, `@@DATAL`, `@@INITL`, `@@DATS`, `@@INIS`, `@@SEGREG`, `@@RTARG0`, `@@BITS`）は内容を持たない。`@@INIT` の初期値は `@@R_INIT` に、同じ順・同じ長さで格納されている（`_?R_INIT` − `@@R_INIT` 先頭 = `@@INIT` のサイズ）。**変数 `v`（`@@INIT` 内）の初期値は `@@R_INIT.paddr + (v.addr − @@INIT.paddr)` から読める**【P: 初期値つき 45 個で確認】。スタートアップ（`_@cstart`）が実行時にコピーするので、**`_@cstart` から走らせれば初期化は自動**。
- lmf に無いアドレスは未書き込み（hex/mot は 0xFF で埋めた全域: probe の `.mot` は 0x00000〜0x2FFFF の 196608 B）。

## 4. シンボルエントリ（20 B）【多】【P】
| off | 幅 | 名前 | 意味 |
|---|---|---|---|
| 0 | char[8] | name | 8 文字以下ならインライン（NUL 詰め、ちょうど 8 文字なら NUL 無し）。先頭 4 B が 0 なら、次の u32 が文字列表内オフセット（表の先頭=長さ欄を 0 として。文字列は offset 4 以降） |
| 8 | u32 | value | アドレス（20 ビット）など。クラスで意味が違う |
| 12 | i16 | scnum | セクション番号（1 始まり）、-1=絶対/なし、-2=デバッグ(.file/モジュール/タグ) |
| 14 | u16 | typ | 基本型(下位 4 ビット)＋修飾ビット（§5） |
| 16 | u8 | sclass | 記憶クラス（§4.1） |
| 17 | u8 | naux | 補助エントリ数（0 または 1 のみ観測） |
| 18 | u16 | x | **派生型の鎖**（2 ビットずつ、シンボルに近い側から。1=ポインタ 2=関数 3=配列）。標準 COFF では n_type の上位に入る部分が別フィールドになっている |
補助エントリも 20 B。**C の識別子には `_` が前置される**（`main`→`_main`、構造体メンバ `ia`→`_ia`、タグ `inner`→`_inner`、列挙子 `SE_A`→`_SE_A`）【P】。ランタイム/アセンブラのシンボルは `_@cstart`、`@@lsmul` などそのまま。**無名の構造体・共用体のタグ名は `.0fake` `.1fake`（`.<通し番号>fake`、`_` なし）**【P】。

### 4.1 記憶クラス（実測）
| sclass | 意味 | 確度 |
|---|---|---|
| 0x01 | 自動変数（関数内ローカル）。value = フレーム内オフセット（§6.2）、scnum=-1 | 多/P |
| 0x03 | **static**。ファイル内 static の関数、ファイル内 static 変数、関数内 static 変数（ブロック内も）、コンパイラ生成の定数ラベル `L0020` 形式、コンパイラ生成の一時領域 `L0027`（構造体を返す関数の戻り値用）。変数は value=RAM（またはフラッシュ）上の実アドレス、scnum=その変数のセクション（`@@INIT`/`@@DATA`）。所属の決め方は §6.1 | 多/P |
| 0x04 | レジスタ変数。value = レジスタ番号（6=L, 7=H のみ観測。RL78 の 8 ビットレジスタ番号 X=0,A=1,C=2,B=3,E=4,D=5,L=6,H=7 と整合）【推】 | 多 |
| 0x08 | 構造体のメンバ（標準 COFF の C_MOS）。**value = 構造体先頭からのバイトオフセット**、scnum=-1 | P |
| 0x09 | スタック渡しの引数。value = フレーム内オフセット（§6.2） | 多/P |
| 0x0A | 構造体タグ（C_STRTAG）。typ=8、scnum=-2、補助 1 個（§5.1） | P |
| 0x0B | 共用体のメンバ（C_MOU）。value は常に 0 | P |
| 0x0C | 共用体タグ（C_UNTAG）。typ=9 | P |
| 0x0F | enum タグ（C_ENTAG）。typ=10 | P |
| 0x10 | enum の列挙子（C_MOE）。typ=4（int）、value = 値（§5.4） | P |
| 0x11 | レジスタ渡しの引数（value=レジスタ番号。1 バイト=0x06(L)、2 バイトのポインタ=0x103(HL)＝0x100＋レジスタ対番号 AX=0,BC=1,DE=2,HL=3）。関数の入口で AX から L/HL へ載せ替えた先（§6.2） | 多/P |
| 0x12 | **ビットフィールド**（C_FIELD）。value = 構造体先頭からの**ビット位置**、補助エントリの [6] = 幅（§5.3） | P |
| 0x20 | 定数（EQU）。`_@STBEG` `_@STEND` `_@SADSIZ` `_@MAA`、scnum=-1 | 多/P |
| 0x26 | 公開シンボル（関数、グローバル変数、ラベル）。value=アドレス | 多/P |
| 0x27 | 公開ビット変数（`bit x;`）。value=バイトアドレス（0xFFE20）、scnum=@@BITS、typ=0x034C。**ビット位置の符号化は【不】**（唯一の例は 0 番ビット。`.sym` では `03` + ((addr−0xFFE00)<<3 \| bit)） | 1 |

| 0x66 | **`.eos`**（タグの終端、C_EOS）。value=タグの大きさ。補助は §5.1 | P |
| 0x67 | `.file`。モジュールの先頭（§6） | 多/P |
| 0x77 | モジュール名エントリ（`.file` の直後。name=リンカのモジュール名 `r_main`、`probe`、`@cstart` など） | 多/P |
| 0x78 | モジュールが各出力セグメントに寄与する先頭アドレス（name=セグメント名、scnum=出力セグメント番号、value=そのモジュールの寄与の開始アドレス） | 多/P |
標準 COFF の **C_TPDEF（typedef 名）は probe にも出現しない**（typedef は展開され、名前は残らない）【P】。probe で出現したクラスは上表ですべて（`tools/lmfdump.py --check-types` が「未知のクラスなし」を確認する）。値は標準 COFF と同じ（C_MOS=8、C_STRTAG=10、C_MOU=11、C_UNTAG=12、C_ENTAG=15、C_MOE=16、C_FIELD=18、C_EOS=102）。

### 4.2 補助エントリ（20 B）
**変数・メンバ・引数など型を持つシンボル（関数以外）の補助エントリ**【P】:
| off | 幅 | 意味 |
|---|---|---|
| 0 | u32 | **タグのシンボル番号**（typ の基本型が 8/9/10 のとき。それ以外は 0）。ポインタ・配列・関数の戻り値の基本型が構造体のときもこの欄 |
| 4 | u16 | 宣言の行（関数の `.bf` を 1 とする相対値）。**ブロックの中で宣言された static 変数（`nested`）にだけ付き**、他は 0。ブロック内の自動変数は未観測【不】 |
| 6 | u16 | **全体のバイト数**（構造体=タグの大きさ、配列=全要素、ポインタ=そのポインタ自身の 2/4、enum=タグの大きさ、ビットフィールドは [6] が幅で別。下記） |
| 8 | u16×4 | 配列の各次元の要素数。外側（宣言の最初の `[]`）から順に最大 4 個（§5.5） |
| 16 | u16 | 0（未使用と思われる） |
| 18 | u16 | **ポインタ種別**。派生型の鎖の k 番目の段に対する 2 ビット（`(v >> 2k) & 3`）。ポインタの段は 1=near（2 B）、2=far（4 B）、他の段は 0（§5.6） |
補助エントリを持つのは: 配列・ポインタ・構造体/共用体/enum 型の変数・メンバ・引数と、ブロック内 static。**単純なスカラ（char や int の変数・メンバ）は補助エントリなし**（naux=0）【P】。
- **関数（x の最下位が 2）** 【多】【P】: `[0] u32 戻り値が構造体/enum のときタグのシンボル番号（他は 0）` / `[4] u32 関数のバイト長` / `[8] u32 行番号表内の位置（ファイルオフセット）` / `[12] u32 この関数の .ef の次のシンボル番号` / `[16] u32 1=通常関数、0=割り込み関数（typ の 0xE000 付き）`。長さ=次の同セクション関数の先頭アドレスとの差、は公開サンプル 5 件計 101 関数中 91 で一致（残り 10 件=各セクションの最後の関数など。不一致の原因は未調査【不】）。probe では 17 関数すべて、`.map` の関数アドレスの差と一致【P】。
- **`.file`**: ファイル名。14 文字以下ならインライン（先頭 14 B、NUL 詰め）、それより長いと先頭 4 B が 0、次の u32 が文字列表オフセット【多】【P】。`.file` エントリ自身の value は連鎖用の値と思われるが使わない【不】。typ=0x3F は C ソース由来、0 はアセンブラ由来【多】【P】。
- **`.bf`**: `[4] u16 = 開始行（`{` の絶対行）` 【P: f_void は 153 行目の `{`】、`[6] u16 = 第 1 引数の退避（AX/BC を push する分。レジスタ渡しの 1 バイト引数でも 2）とローカルのバイト数【推】。HL の退避は含まない（f_void=0、add2=2、f_u32=4、f_ptr=6、f_locals=18、main=6）`、`[12] u32 = 次の関数のシンボル番号`。
- **`.ef`**: `[4] u32 = 終了行の相対値`（`.bf` の行を 1 として数える。終了行 = bf行 + 値 − 1。f_void: 153 + 3 − 1 = 155 の `}`【P】）。
- **`.bb` `.eb`**: `[4] u32` に行（相対）【P: f_static2 の `{` は 5、`}` は 8】。他は【不】。
- タグの補助・`.eos` の補助は §5.1。nAux>1 は観測していない。

## 5. 型【多】【P】
`typ` 下位 4 ビット = 基本型。標準 COFF と同じ番号を使っていることを実測確認:
| 値 | 型 | サイズ | 観測 |
|---|---|---|---|
| 1 | void | – | 多/P（`g_fn_tbl` の戻り値、関数の戻り値） |
| 2 | char / signed char（**同じコード**。無修飾 char は signed。lmf から両者は区別できない） | 1 | P |
| 3 | short / signed short | 2 | P |
| 4 | int / signed int（`short` と `int` は別コード。`signed` の有無は区別できない） | 2 | 多/P |
| 5 | long / signed long | 4 | 多/P |
| 6 | float | 4 | P |
| 7 | double（**4 B**。CA78K0R は double も単精度） | 4 | P |
| 8 | struct | タグの大きさ（§5.1） | P |
| 9 | union | タグの大きさ | P |
| 10 | enum | タグの大きさ（1 または 2、§5.4） | P |
| 11 | enum メンバ（C_MOE のエントリの typ は 11 ではなく **4=int**） | – | 値 11 は出現せず |
| 12 | unsigned char | 1 | 多/P |
| 13 | unsigned short | 2 | 多/P |
| 14 | unsigned int | 2 | 多/P |
| 15 | unsigned long | 4 | P |
0 は型なし（ランタイムの記号）。`signed char` の有無（値 2 のみ）、`signed int` のビットフィールド（§5.3）は符号付き指定が lmf に残らない【P】。typedef は元の型に解決された値が入る（`U8 g_td_u8` は typ=0x000C、`POINT_T g_td_pt` は typ=8 とタグ番号）。

`typ` の上位ビット（実測）:
- `0x0100`: C_REG(0x04)/C_REGPARM(0x11) のシンボルにだけ付く。レジスタ割付けの印と思われる。型には無関係として無視してよい【多】【P】。
- `0x1000`: **オブジェクト自身が `volatile`**（`volatile unsigned char g_vol` → 0x100C）【多】【P】。`volatile uint8_t *p`（指す先が volatile）は印が残らない【1】。
- `0x5000`: **オブジェクト自身が `const`**（`const unsigned char c_tbl[4]`→0x500C、`const struct inner c_inner`→0x5008、`uint8_t * const p`→0x500C）。`0x4000` だけの値は未観測で、const は 0x5000（0x1000 を含む）として現れる【P】。`const unsigned char *g_p_const`（指す先が const）は 0x000C のまま、**指す先の const は残らない**【P】。`const volatile` の組は未観測【不】。const のグローバルは `@@CNST`（フラッシュ）に置かれ、アドレスはフラッシュ上の値（probe は 0x3000）。
- `0xE001`（void ＋ 0xE000）: `__interrupt static void f(void)` の割り込み関数。補助の末尾 u32 が 0【多】。
- `0x034C`: `bit` 変数（0x27）【1】。

### 5.1 タグ（構造体・共用体・enum）の定義【P】
タグは次の並びで、**1 個のタグが連続したエントリ列**になる（標準 COFF と同じ構造）:
```
タグ    (sclass 0x0A/0x0C/0x0F, name=_タグ名 または .Nfake, scnum=-2, typ=8/9/10, naux=1, value=0)
   aux  [0]=0  [6] u16=タグの大きさ(バイト)  [12] u32=この .eos の補助エントリの次のシンボル番号
メンバ  (sclass 0x08/0x0B/0x10/0x12 …) を宣言順に（メンバ自身が補助を持つならその直後に補助）
.eos    (sclass 0x66, scnum=-1, typ=0, naux=1, value=タグの大きさ)
   aux  [0] u32=タグのシンボル番号  [6] u16=タグの大きさ
```
- タグの「次のシンボル番号」（`[12]`）は **`.eos` と補助の直後**を指す（`end_ok`）。つまり直後に別のタグが来れば次のタグだが、最後のタグは次の非タグ（ファイル内 static 変数、関数）を指す。probe の 11 タグすべてで `[12]` = `.eos` の番号 + 2、`.eos` の `[0]`=タグの番号、`.eos` の `[6]` と value = タグの大きさ【P】。
- **タグはモジュールの先頭部分（`.file`、モジュール名、0x78 エントリの後、ファイル内 static 変数・関数ブロックの前）に、ソースでの宣言順**に並ぶ。入れ子の無名の構造体（共用体の中の `struct {…} parts`）は**外側のタグより前**に出る（`.0fake` が `uni` の前）【P】。関数の中で宣言したタグの位置は未確認【不】。使われていないタグが出力されるかは未確認【不】。
- **無名の構造体・共用体の名前**は `.0fake` `.1fake`…（先頭に `.`、0 から始まる出現順の通し番号 + `fake`）。typedef された無名構造体（`typedef struct {…} POINT_T;`）も同じ `.Nfake`（typedef 名 `POINT_T` は残らない）【P】。複数モジュールで番号が 0 から数え直されるかは未確認【不】。
- **メンバのオフセット**: 構造体のメンバ（0x08）の value = 構造体先頭からのバイトオフセット。共用体のメンバ（0x0B）は value=0。ビットフィールド（0x12）は §5.3。
- メンバの型は変数と同じ規則で、typ/x/補助エントリに入る（§4.2）。入れ子の構造体メンバ（`struct inner in`）は typ=8、補助 `[0]` = 入れ子のタグのシンボル番号、`[6]` = その大きさ。配列メンバ（`unsigned char arr[3]`）は x=3、補助 `[6]`=3、`[8]`=3。構造体の配列メンバ（`struct inner ins[2]`）は typ=8、x=3、補助 `[0]`=タグ、`[6]`=12、`[8]`=2【P】。

### 5.2 構造体の配置規則（probe の 7 構造体・1 共用体で確認）【P】
- 1 バイト型（`char` 系、1 バイトの enum）は 1 バイト境界、**それ以外（`short`/`int`/`long`/`float`/`double`/ポインタ/2 バイトの enum）は 2 バイト境界**。4 バイト型も 2 バイト境界（4 の倍数にはならない。根拠: `long ol` を含む `struct outer` の変数 `g_bss_outer` が 0xFC032 = 4 で割って 2 余るアドレスに置かれ、`ol` は 0xFC03A に来る）。
- 入れ子の構造体も（2 バイト境界の型を含むなら）2 バイト境界。`outer` = oa@0, in@2(6 B), ol@8, arr@12(3 B), warr@16, ins@20(12 B), tail@32、大きさ 34（33 を偶数に切り上げ）。
- 構造体の大きさ = 最後のメンバの後を、**2 バイト境界の型を含む構造体は偶数に**切り上げる。`char` 系のビットフィールドだけの `bits8` は大きさ 1（切り上げない）。`char` だけの通常の構造体・`char` 配列の整列は未観測【不】。
- 共用体の大きさ = 最大メンバ（同上で偶数に切り上げ）。

### 5.3 ビットフィールド【P】
メンバのエントリ: **sclass=0x12、value = 構造体先頭からのビット位置（バイトオフセット×8 + バイト内ビット）、補助エントリの `[6]` u16 = 幅（ビット数）**、typ = 宣言した型（`unsigned char`=0x0C、`unsigned int`=0x0E）、scnum=-1。補助のその他は 0。
- **格納は下位ビットから**（ビット位置 0 が先頭バイトの最下位ビット）。値は、構造体先頭から数えたリトルエンディアンのビット列の `[位置, 位置+幅)` 【`g_bits8`/`g_bits16`/`g_bitsm` の全 16 フィールドの初期値で確認】。
- 読み取り: `b0 = pos >> 3; nb = ((pos & 7) + 幅 + 7) >> 3; v = (LE整数(image[base + b0 .. +nb]) >> (pos & 7)) & ((1 << 幅) − 1)`（格納単位を知らなくてよい）。
- 格納単位の置き方（`unsigned char` は 1 バイト、`unsigned int`/`signed int` は 2 バイト単位）【P】:
  - `bits8`（uchar×4: 幅 1,1,3,3）: 位置 0,1,2,5。1 バイトに詰める。大きさ 1。
  - `bits16`（uint: 幅 1,4,7,4,9,3）: 位置 0,1,5,12 で 16 ビットちょうど、次の `g0` は位置 16（次の 16 ビット単位の先頭）、`g9` は 25。大きさ 4。
  - `bits_mixed`: `head`（通常の uchar、byte 0）→`m0`(幅 2) `m2`(幅 6) は位置 8、10（byte 1 を使い切る）→`w0`(uint, 幅 5)=16、`w5`(幅 11)=21（16 ビット単位 byte 2–3 を使い切る）→`s0`(signed int, 幅 4)=32（byte 4–5 の単位の先頭）→次の通常メンバ `tail` は **byte 6**（`s0` の格納単位 2 バイトの後。ビット 36 の次の byte 5 ではない）。大きさ 8。`char` 型の幅 8 の合計が 1 バイトを超えるときと、`int` 型のフィールドが 16 ビット境界をまたぐときにどう詰めるか（ずらして次の単位に置くのか）は **probe に該当例がなく【不】**（マニュアルは「またがない」と記述。[CODING]）。
  - `uchar` フィールドの後に `uint` フィールドが続く例（`m2`→`w0`）は、前の単位がちょうど埋まっているので、境界の扱いは区別できない【不】。
- **`signed int s0 : 4` の typ は `unsigned int`（0x0E）で、符号付きかどうかが lmf に残らない**【P】。メモリ上の初期値 `-3` は `0xD`（4 ビットの 2 の補数）で正しく入っている。符号拡張が要るかは C ソース/コンパイラの規則に頼る（CA78K0R の「型指定子なしの int は unsigned」は [CODING]。`signed` 指定の扱いは lmf から【不】）。

### 5.4 enum【P】
- タグ（0x0F、typ=10）の補助 `[6]` = **enum の大きさ**: `enum small_e { SE_A, SE_B, SE_C=100 }` → 1、`neg_e {-3,0,7}` → 1、`big_e {0, 1000}` → 2。変数 `g_se`/`g_ne`/`g_be` は 1/1/2 バイトで、初期値 100、0xFD、0x03E8 が値どおりに入っている。規則は [CODING] の「全列挙定数を表せる最初の型: signed char → unsigned char → signed int」と整合（unsigned char になる場合 = 例えば 0〜200 は未観測【不】）。コード上でも 1 バイト enum は符号拡張して読まれる（`sarw ax,8`）。
- 列挙子（0x10）: typ=4（int）、scnum=-1、**value = 値（u32 の下位 16 ビットに 2 の補数、上位は 0）**。`NE_M = -3` は 0x0000FFFD。復元は `v = value & 0xFFFF; if v >= 0x8000: v -= 0x10000`（`long` 範囲の列挙子は未観測【不】）。補助エントリなし。
- enum 型の変数・引数・戻り値: typ=10、補助 `[0]` = enum タグ、`[6]` = 大きさ（`.eos` も同形）。引数の `_e`（`f_enum`）は typ=0x010A、sclass=0x11（レジスタ渡し）、戻り値は関数補助 `[0]` にタグ【P】。

### 5.5 配列（多次元を含む）【P】
- 派生型の鎖（`x`）の 3 が配列の 1 段。**配列の段ごとに、補助エントリ `[8]` から u16 を 1 個ずつ、鎖の中でシンボルに近い（外側の）段から順に消費する**。`g_mat2[2][3]` は x=0x000F（鎖 3,3）、補助 `[6]`=6、`[8]`=2、`[10]`=3。`g_mat3[2][3][4]` は x=0x003F（鎖 3,3,3）、`[6]`=48、`[8,10,12]`=2,3,4。宣言の最初の次元が最初【P】。
- 補助エントリ `[8..15]` は u16 が 4 個分なので**配列の段は 4 つまで**表せる。5 次元以上の扱いは不明【不】（`x` は 16 ビットなので鎖は最大 8 段）。
- 構造体の配列（`struct outer g_outer_arr[2]`）: typ=8、x=3、補助 `[0]`=タグ、`[6]`=68、`[8]`=2【P】。`[6]` は常に型全体のバイト数（要素数 × 要素の大きさ）。

### 5.6 ポインタ・関数ポインタ【P】
- 鎖の 1=ポインタ。**near か far かは補助エントリ `[18]` の、その段に対応する 2 ビット**（1=near 2 B、2=far 4 B）。`unsigned char *g_p_uc`: x=1、`[6]`=2、`[18]`=1。`unsigned char __far *g_fp_uc`: x=1、`[6]`=4、`[18]`=2。前回の「補助末尾=1」は near の印だった。
- 段ごとの対応（鎖の 0 番目 = シンボルに最も近い段が下位 2 ビット）: `unsigned char **g_pp_uc` x=0x5、`[18]`=0x5（near,near）。`unsigned char *g_parr[3]` x=0x7（配列,ポインタ）、`[6]`=6、`[8]`=3、`[18]`=0x4（配列=0, ポインタ=near）。`unsigned char (*g_p_arr)[3]` x=0xD（ポインタ,配列）、`[6]`=2、`[8]`=3、`[18]`=0x1。
- **関数ポインタ**（ミディアムモデル）: `unsigned int (*g_fn)(unsigned int, unsigned int)` は x=0x9（ポインタ,関数）、typ=0x0E（戻り値の型）、`[6]`=4、`[18]`=0x2（far）。`void (*g_fn_tbl[2])(void)` は x=0x27（配列,ポインタ,関数）、typ=1(void)、`[6]`=8、`[8]`=2、`[18]`=0x8（鎖の 1 番目＝ポインタの段のビット 2–3 が 2=far、他の段は 0）。**引数の型は lmf に残らない**（関数ポインタの引数並びは不明）。コードポインタが far（4 B）なのは `-mm`（ミディアム）のため。スモールの関数ポインタが near かは未観測【不】（[CODING] では near）。
- **far ポインタ / 関数ポインタのメモリ上の形**（4 B）: `{u16 オフセット（下位 16 ビット）, u8 ページ（20 ビットアドレスの上位 4 ビット = ES/CS の値）, u8 0}`。`g_fp_uc = &g_uc`（0xFC06A）は `6A C0 0F 00`、`g_fn = add2`（0x004A3）は `A3 04 00 00`【P】。near ポインタは 2 B のオフセットだけ（RAM の 0xFxxxx は下位 16 ビット）。初期値の near ポインタ（`g_p_uc=&g_uc` は `6A C0`）11 個、far ポインタ 2 個、関数ポインタ 1 個が、すべて指す先のアドレスと一致【P】。
- `const unsigned char *g_p_const`: ポインタ自身は const でも volatile でもなく（0x000C）、**指す先の const は残らない**【P】。const ポインタ自身は 0x5000 が付く（§5）。typedef されたポインタ（`POINT_P`）は typedef が展開されて通常のポインタ（`struct .1fake *`）になる【P】。

### 5.7 typedef【P】
typedef 名のエントリは出ない（sclass 0x0D なし）。typedef を使った変数は**元の型に解決された typ/x/補助**を持つ: `U8`→0x0C、`U16`→0x0E、`U32`→0x0F、`POINT_T`→typ=8＋`.1fake` タグ、`POINT_P`→typ=8 x=1 の near ポインタ。したがって typedef 名は復元できない。

### 型の復元アルゴリズム【P】
```
# 1. タグ表（シンボル表の走査で。タグは sclass 0x0A/0x0C/0x0F）
tags = {}                                   # キー = タグのシンボル番号
for i, s in enumerate_entries(symbols):     # エントリ番号は補助エントリも数える
    if s.sclass in (0x0A, 0x0C, 0x0F):
        t = Tag(index=s.index, name=s.name, kind={0x0A:'struct', 0x0C:'union', 0x0F:'enum'}[s.sclass],
                size=s.aux.u16(6))
        j = next entry
        while symbols[j].sclass != 0x66:    # .eos まで
            t.members.append(symbols[j]); j += 1
        tags[t.index] = t                   # 補助つきのメンバは 2 エントリ分進む

# 2. シンボルの型
def type_of(sym):
    base = sym.typ & 0xF; quals = sym.typ & 0xFFF0
    levels = []                             # シンボルに近い側から
    x = sym.x
    while x: levels.append(x & 3); x >>= 2
    aux = sym.aux[0] if sym.naux else None
    chain = []; ai = 0
    for k, lv in enumerate(levels):
        if lv == 1:   far = ((aux.u16(18) >> 2*k) & 3) == 2;  chain.append(('ptr', far))
        elif lv == 3: chain.append(('array', aux.u16(8 + 2*ai))); ai += 1
        else:         chain.append(('func',))
    tag = tags[aux.u32(0)] if base in (8, 9, 10) and aux else None   # 関数の戻り値も aux[0]
    return Type(base, quals, chain, tag)

def sizeof(t):
    n = tag.size if base in (8, 9, 10) else {2:1, 3:2, 4:2, 5:4, 6:4, 7:4, 12:1, 13:2, 14:2, 15:4}[base]
    for el in reversed(t.chain):            # 基本型に近い段から外側へ
        if el.kind == 'ptr':    n = 4 if el.far else 2
        elif el.kind == 'array': n *= el.count
        else:                   n = None    # 関数そのものに大きさはない（ポインタが付けば 2/4）
    return n                                # 補助 [6] と一致する（検証済み）

def expand(t, base_off, path):              # メンバ・配列要素の展開
    if t.chain and t.chain[0].kind == 'array':
        for i in range(t.chain[0].count): expand(t.chain[1:], base_off + i * sizeof(t.chain[1:]), path + [i])
    elif t.chain and t.chain[0].kind == 'ptr':  yield (path, base_off, sizeof(t))        # ポインタは葉
    elif t.base in (8, 9):                  # 構造体/共用体: メンバを展開
        for m in t.tag.members:             # sclass 0x08 / 0x0B / 0x12
            mt = type_of(m)
            if m.sclass == 0x12:  yield (path + [m.name], base_off, ビット位置 = m.value, 幅 = m.aux.u16(6))
            else:  expand(mt, base_off + (m.value if m.sclass == 0x08 else 0), path + [m.name])
    else:  yield (path, base_off, sizeof(t))

def declaration(t, name):                   # C の宣言文字列
    s = name; prev = None
    for el in t.chain:                      # シンボルに近い段から
        if el.kind == 'ptr':    s = ('__far *' if el.far else '*') + s
        elif el.kind == 'array': s = ('(%s)' % s if prev == 'ptr' else s) + '[%d]' % el.count
        else:                   s = ('(%s)' % s if prev == 'ptr' else s) + '()'
        prev = el.kind
    return qualifiers + basename(t) + ' ' + s
```
`tools/lmfdump.py --tags` / `--vars` が、この規則で probe の全タグ・全変数を展開して表示する（`probe.c` の宣言文字列と一致を `--check-types` が確認: 変数 47、static 10、関数 17）。

## 6. モジュール構造とシンボル表の走査【多】【P】
シンボル表は次の順に並ぶ:
1. **モジュールごとのブロック**（リンク順。`.map` の入力モジュール順、`.sym` の `;FF モジュール名` の順と一致【多】【P: 13 モジュール】）

```
<module> (0x77)         name = モジュール名（`.file` の名前から拡張子を取ったもの。長いと文字列表）
@@xxx (0x78) × k        このモジュールが寄与するセグメント（scnum, 開始アドレス）。モジュールの寄与量=次の寄与モジュールの開始 − この開始（`.map` の入力モジュール行と開始アドレスが全件一致【多】【P: 49 行】）
[タグ定義] × m          C モジュールのみ。ソースでの宣言順（§5.1）
[ファイル内 static 変数] 0x03
[関数ブロック] × n      C モジュールのみ

```
   関数ブロック:
```
_func (0x26 公開 | 0x03 static, x 最下位=2, aux あり)   value=関数の先頭アドレス、scnum=@@BASE/@@CODEL 等
.bf (0x65, aux)
  引数 (0x09/0x11) …    宣言順
  ローカル (0x01/0x04) と 関数内 static 変数 (0x03) …   宣言順
  .bb (0x64) … [ブロック内の static 変数 0x03] … .eb       ブロックの境界

```
   ブロック内の static 変数（`nested`）は **`.bb` と `.eb` の間に出る**【P】。ブロック内の自動変数がどこに出るかは probe に例がなく【不】（公開サンプルでは `.bb`/`.eb` の間に変数は無かった）。
   型の変数エントリ（typ/x/aux 付き）の `name` は `_` 付き、引数名は元の名前に `_` が付く（`_cmd_name`）。
2. **公開シンボル群**（クラス 0x26/0x27/0x20）。順序は名前順ではなくリンカ内部順。ここに**グローバル変数**（typ/x/補助付き。構造体なら typ=8 と補助 `[0]`=タグ）、ランタイム記号（`_@cstart`、`_@STBEG`、`_?R_INIT` …）、アセンブラ公開名（`_exit`、`_stkinit`、`@@lsmul`）が入る。**公開関数は関数ブロック側にだけあり、この群には無い**。probe では公開関数 16 個（関数ブロック側）を含めて 128 個（うち公開変数 47、残りはランタイム/EQU）で `.sym` PUBLIC・`.map` Public symbol list と件数・名前・アドレスが全一致【P】。
3. 末尾に `L0020` 形式の 0x03 ラベル（公開サンプル FunctionDemoCode 4 件、`.sym` では所属モジュールが付く/公開のものが混在し、lmf からは区別できない）【1】。

### 6.1 変数をソースファイル・関数に結びつける
- **関数ローカル/引数**: 関数ブロック内のエントリ（`f.params` / `f.locals`）で関数に結びつく。関数→ファイルはブロックの `.file`。
- **ファイル内 static 関数**: モジュールのブロック内で sclass=0x03（`<` つきの `.sym` ローカルと一致【多】【P】）。
- **ファイル内 static 変数**: モジュールのブロックの、関数ブロックの**外**にある sclass=0x03、scnum>0 のエントリ（`_s_file_uc` など）。value は実アドレス【P】。
- **関数内 static 変数**: **その関数の `.bf` と `.ef` の間にある sclass=0x03 のエントリ**（同名 `cnt` が `f_static1` と `f_static2` にあり、それぞれの関数ブロックの中に出る。アドレスが違う: 0xFC108 と 0xFC10A）。ブロック内なら `.bb`〜`.eb` の間（`nested` は深さ 1）。value=実アドレス、scnum=`@@INIT`（初期値あり）/`@@DATA`（なし）。名前は修飾されず `_cnt` のまま【P】。**`.sym` のローカル群と `.map` のローカルシンボル一覧にも、名前は修飾されずにそのモジュールの項目として出る**（`_cnt` が 2 件）。
- **グローバル変数のファイル**: lmf は変数にモジュールを記録していない。所属は「変数のアドレスが、同じ scnum のどのモジュールの寄与範囲に入るか」で決める（0x78 エントリの開始アドレス以上で最大のもの。同じ開始が複数あるときはリンク順で最後）。CSI の全 20 変数で C ソースの定義位置と一致【1】。probe では公開データ変数 44 個すべてで `.map` の MODULE 欄と一致【P】。
- **コンパイラ生成の一時領域**: `L0027`（sclass 0x03、typ=8、`@@DATA`、6 B）は `f_ret_struct`（6 バイト構造体を返す関数）の戻り値用バッファ（§CA78K0R_NOTES 3 節）。番号 `0027` の決まり方は【不】。

### 6.2 引数・ローカルの value（フレーム内オフセット）【P】
RL78 のコードは、関数の入口で `push hl; [push ax / push bc]; [subw sp,#ローカルの大きさ]; movw hl,sp`（`movw hl,!0xFFF8` で SP を HL に写す）としてフレームを作り、`[HL+n]` で自動変数・スピルした引数・スタック引数にアクセスする。**sclass 0x01 と 0x09 の value は、この `HL`（＝プロローグ直後の SP）からのバイトオフセット `n`**:
- 自動変数 0x01: ローカル領域の中（`f_locals` の `r`=0, `ls`=2..7, `l32`=8..11, `l16`=12..13, `l8`=15）。
- スタック渡しの引数 0x09: 第 1 引数（AX、4 バイトなら AX+BC）は入口で push されて `[HL+0]`（4 バイトなら `[HL+0..3]`、AX が +0..1、BC が +2..3）。第 2 引数以降は呼び出し側が積んだ位置で、`ローカル領域の大きさ + 第 1 引数の退避(2 または 4) + 退避した HL(2) + 戻り番地(4) + それまでのスタック引数の大きさ`。`add2(a,b)`: a=0、b=8。`f_mix(a,b,c,d)`: a=0、b=8、c=12、d=14。`f_long2(a,b)`: a=0、b=10。`f_locals` の a=16（ローカル 16 B の次）。
- レジスタ渡しの引数 0x11: 入口で AX を L/HL に載せ替えて使い、スタックには残さない（value=レジスタ番号。1 バイト = 6（L）、2 バイトのポインタ = 0x103（HL））。
- `HL` をフレームに使わない関数（`f_void`、`f_static1` など。引数もローカルも無い）は value を持つエントリがない。`.bf` の補助 `[6]` はこのフレームのうち HL の退避を除いた大きさ【推】。

### スタートアップ/ランタイムのシンボル【多】【P】
`_@cstart`（リセットベクタ `@@VECT00` の指す先、`@@LCODE` 先頭）、`_@cend`、`_main`、`_hdwinit`、`_exit`、`_stkinit`、`_@STBEG`（スタック先頭、EQU）、`_@STEND`、`_@SADBEG`、`_@SADSIZ`、`_@MAA`、`_@MEMBTM`/`_@MEMTOP`/`_@BRKADR`/`_@FNCTBL`/`_@FNCENT`/`_@SEED`/`_@DIVR`/`_@LDIVR`/`_@TOKPTR`/`_errno`（ランタイム RAM）、`_?R_INIT`/`_?INIT`/`_?DATA`…（各セグメントの末尾アドレス）、`_@vectNN`（ベクタ）、`_@RTARGn`/`@@FPR*`（レジスタ領域）、浮動小数点ランタイム `@@fmul` `@@fnor`…（probe の float 演算用 `m_fmul` `m_fcom1…6`）、`@@luadd` `@@lssub`（32 ビット加減算）。型なし（typ=0）。

## 7. 行番号【多】（優先度低）
セクションの ptr_D から nlnno 個、8 B（`u32, u32`）:
- `(関数のシンボル番号, 0)` = 関数の開始。
- `(アドレス, 行)` = 文の先頭アドレスと行。**行は関数の `.bf` の行（`{`）を 1 とする相対値**（絶対行 = bf行 + 値 − 1。LED の main: bf=63 に対し相対 2,3,6 は実ソースの 64,65,68 行）。

## 8. `.sym` と `.map` との対応
### `.sym`（`lmfdump.py --sym`）
- PUBLIC 群 = lmf の「公開関数（関数ブロックの 0x26）＋ 0x26/0x27/0x20」。
- 属性: 0x20→`00`、0x27→`03`、セクションが ROM 側(k1=0x20)→`01`、RAM 側→`02`、scnum=-1 の 0x26（`_@SADBEG`）→`01`。アドレス = value（20 ビット）、ビットは (value−0xFFE00)<<3。
- `;FF モジュール名` の並び = lmf のモジュール順。モジュールのローカル群 = 0x03 のうち **scnum>0 のもの**（static 関数、ファイル内 static 変数、**関数内 static 変数**、`L0027` などのラベル）。`<` は先頭行だけに付き、以降の行も同じモジュールのローカル。ローカルは名前順（同名は順不同）。タグ・メンバ・引数・ローカルは `.sym` に出ない。`L0020` 形式のラベルは全体で照合（所属は区別不能）。
- `.sym` は `_` 付きの名前をそのまま持つ（`_main`）。
### `.map` のシンボル一覧（リンカ `-kp -kl`）【P】
- `*** Public symbol list ***`: モジュール名の行（先頭から）の下に `ATTR VALUE NAME` の行（ATTR は `ADDR` / `NUM` / 空白）。`*** Local symbol list ***`: モジュールごとに `MOD <名前>`、続く `CSEG/DSEG/BSEG <セグメント名>` の行（= そのモジュールの 0x78 エントリの名前列と一致）、続いて**ローカルシンボルがシンボル表の出現順**に並ぶ。
- ローカルの一覧に出るのは、タグ・メンバ・列挙子（value=オフセット/値）、ファイル内 static（ADDR）、引数・自動変数・関数内 static（value=オフセット/アドレス）、static 関数。出ないもの: `.eos`、`.bf` 等、公開関数。**`.eos` と補助エントリは一覧に出ない**。
- probe では、13 モジュールすべてで「モジュールの 0x78 の名前列＋モジュールブロック内のシンボル（名前と value）の並び」が一覧と**完全に同じ順**で一致（シンボル 96 個、セグメント 51 個）。公開 128 個は件数・名前・アドレスとも一致。

## 12. 実装担当への注意（標準 COFF との違い）
1. エントリは 18 B ではなく **20 B**、セクションヘッダは **52 B**、オプションヘッダは 68 B、再配置表なし（§1）。
2. **派生型の鎖は `n_type` に入らず別フィールド `x`（u16、2 ビットずつ、シンボルに近い側から）**。基本型は `typ` の下位 4 ビット、上位は修飾ビット（register 0x0100、volatile 0x1000、const 0x5000）。
3. 配列の次元と near/far は**補助エントリ**（`[8]` に u16×4、`[18]` に段ごとの 2 ビット）。標準 COFF の `x_dimen`（u16×4 だが位置が違う）と `x_tagndx` は `[0]`（u32）。**配列の次元はシンボルに近い段から順**に、`x` の鎖の配列の段と対応づける。
4. 構造体のメンバのオフセットは value（バイト）、**ビットフィールドの value は構造体先頭からのビット位置**で、幅は補助の `[6]`（標準 COFF では value はバイトオフセットで、ビット位置は補助の別欄）。
5. **メンバの大きさは補助 `[6]`**（全体サイズ）。`tagndx` が参照するのは「タグのシンボルのエントリ番号（補助込み）」。
6. `char` と `signed char`、`signed int` と `int`（ビットフィールド）は区別できない。`typedef` 名は残らない。無名タグは `.Nfake`。
7. 変数の置き場所は value=実アドレス（20 ビット）。**関数内 static はその関数の `.bf`〜`.ef` の中の sclass 0x03**。ファイル内 static 変数は関数ブロックの外。
8. ローカル/引数の value は SP（プロローグ後の HL）相対（§6.2）。
9. far ポインタ/関数ポインタは 4 B で、メモリ上は `{offset16, page8, 0}`（リトルエンディアンの 32 ビット整数としては `page<<16 | offset`）。
