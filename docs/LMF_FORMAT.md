# CA78K0R `.lmf` 形式仕様（実測ベース）

対象: CA78K0R が出力するロード・モジュール・ファイル。解析スクリプト: `scratchpad/lmf_tools/lmfdump.py`（本仕様のリファレンス実装。`python3 -I` で実行）。

確度の凡例:
- **【多】** 5 サンプルすべてで確認（バイト列・件数が一致）
- **【1】** 1 サンプルのみで確認
- **【推】** 実測値と整合するが他の根拠が薄い推測
- **【不】** 不明 / サンプルに現れなかった

材料: rongkunxue/XJTU-Automation-share（BSD-3-Clause）の 5 サンプル（末尾の一覧）。すべて RL78/G13 R5F100LG、CA78K0R V1.60、リンカ W1.70、small モデル。
**78K0R 品種の lmf、構造体・共用体・enum・ビットフィールド・多次元配列・関数ポインタ・far ポインタ・関数内 static・ファイル内 static 変数を含むサンプルは入手できず未確認**（§9）。
エンディアンはすべてリトル。

---
## 1. 全体配置【多】
```
0x00   ファイルヘッダ     20 B
0x14   オプションヘッダ   f_opthdr B（68）
0x58   セクションヘッダ   52 B × f_nscns
       …                  セクション内容・行番号表など（§3、§7）
f_symptr                  シンボル表: 20 B × f_nsyms（補助エントリも 1 個と数える）
f_symptr + 20·f_nsyms     文字列表: 先頭 u32 = 表全体の長さ（この 4 B を含む）、以降 NUL 終端文字列。ファイル末尾まで
```
標準 COFF との違い: シンボル・補助エントリが **18 B ではなく 20 B**、セクションヘッダが 40 B ではなく **52 B**、再配置表なし。
`.map` の「N output segment(s)」= f_nscns、「N symbol(s) defined」= f_nsyms【多】。

## 2. ヘッダ
### ファイルヘッダ（20 B）【多】
| off | 幅 | 名前 | 値 |
|---|---|---|---|
| 0 | u16 | f_magic | 0x1148 |
| 2 | u16 | f_nscns | 出力セグメント数 |
| 4 | u32 | f_timdat | Unix 時刻（ビルド日時） |
| 8 | u32 | f_symptr | シンボル表のファイル位置 |
| 12 | u32 | f_nsyms | シンボルエントリ総数（補助込み） |
| 16 | u16 | f_opthdr | 68 |
| 18 | u16 | f_flags | 0x0003 |

### オプションヘッダ（68 B）
5 サンプルでバイト単位で同一（同一デバイス）。意味は【不】。判明分のみ: オフセット 24 から 16 B にデバイスファイル名（NUL 詰め。`dr5f100lg.dvf`）【多】。
他のバイトは `7e9a0000 00000001 00000000 08000000 28000000 30000000 | 名前16B | 60020000 70017001 12010200 00000000 00000000 00400000 00000000`。読み飛ばしてよい（f_opthdr で長さを取る）。

## 3. セクションヘッダ（52 B）【多】
リンカの「出力セグメント」1 つにつき 1 個。**同名が複数並ぶ**（`@@CNSTL` は PAGE64KP のためモジュールごとに 1 個）。番号（scnum）は 1 始まりの並び順。
| off | 幅 | 意味 |
|---|---|---|
| 0 | char[8] | 名前（NUL 詰め） |
| 8 | u32 | paddr: 開始アドレス（RAM は 0xFxxxx の 20 ビットアドレス） |
| 12 | u32 | vaddr（paddr と同値） |
| 16 | u32 | size: メモリ上の大きさ（`.map` の SIZE と一致） |
| 20 | u32 | fsize: ファイル中の内容の大きさ。ROM 側は size と同じ、RAM 側は 0 |
| 24 | u32 | ptr_A: 12 B レコード表の位置（fsize>0 のとき。0 なら無し） |
| 28 | u32 | ptr_B: 内容（生データ）の位置。fsize を 4 の倍数に切り上げて次の内容が続く |
| 32 | u32 | ptr_C: 常に 0 |
| 36 | u32 | ptr_D: 行番号表の位置（nlnno>0 のとき） |
| 40 | u32 | nA: ptr_A のレコード数（内容があれば 1） |
| 44 | u16 | nlnno: 行番号エントリ数 |
| 46 | u8 | k1: 0x20=ROM 側（コード・定数・ベクタ・オプションバイト） 0x40=RAM データ 0x60=ビット（@@BITS） |
| 47 | u8 | k2: 0x10=絶対配置(CSEG AT / DSEG AT / OPT_BYTE / 無名の CSEG) 0x20=コード(BASE 等) 0x80=データ・定数。@@BITS は 0x20 |
| 48 | u32 | z: `@@CNST`（`CSEG MIRRORP`）のみ 0x10、他は 0 |
ptr_A のレコード（12 B）= `u32 addr, u32 0, u32 size`（セグメント範囲の複写）。実装には不要。
k1/k2 と `.map` の属性の対応は FunctionDemoCode の全 40 セグメントで目視確認【1】。メモリに置くかどうかは **fsize>0 かどうかだけ**で判定できる（k1/k2 に依存しない）。

### メモリイメージの作り方
```
for sec in sections:
    if sec.fsize > 0:  image[sec.paddr + i] = file[sec.ptr_B + i]   (i < fsize)
```
- ROM 側（k1=0x20）のみが内容を持つ。コード `@@LCODE/@@BASE/@@CODEL/@@LCODEL`、ベクタ `@@VECTnn`（`CSEG AT`）、`?CSEGOB0`（0xC0 オプションバイト 4B）、`?CSEGSI`（0xC4 10B）、`?OCDSTAD`（0xCE 10B）、定数 `@@CNST`（フラッシュ上の実アドレス。FunctionDemoCode では 0x3000 から。CPU からはミラー 0xF3000 で見える）、**初期値つきデータの ROM 側 `@@R_INIT`**（`@@RLINIT`/`@@R_INIS` も同種）。
- RAM セグメント（`@@DATA`, `@@INIT`, `@@DATAL`, `@@INITL`, `@@DATS`, `@@INIS`, `@@SEGREG`, `@@RTARG0`, `@@BITS`）は内容を持たない。`@@INIT` の初期値は `@@R_INIT` に、同じ順・同じ長さで格納されている（`_?R_INIT` − `@@R_INIT` 先頭 = `@@INIT` のサイズ）。スタートアップ（`_@cstart`）が実行時にコピーするので、**`_@cstart` から走らせれば初期化は自動**。
- lmf に無いアドレスは未書き込み（hex は 0xFF で埋めた 0x00000〜0x1FFFF の全域）。

## 4. シンボルエントリ（20 B）【多】
| off | 幅 | 名前 | 意味 |
|---|---|---|---|
| 0 | char[8] | name | 8 文字以下ならインライン（NUL 詰め、ちょうど 8 文字なら NUL 無し）。先頭 4 B が 0 なら、次の u32 が文字列表内オフセット（表の先頭=長さ欄を 0 として。文字列は offset 4 以降） |
| 8 | u32 | value | アドレス（20 ビット）など。クラスで意味が違う |
| 12 | i16 | scnum | セクション番号（1 始まり）、-1=絶対/なし、-2=デバッグ(.file/モジュール) |
| 14 | u16 | typ | 基本型(下位 4 ビット)＋修飾ビット（§5） |
| 16 | u8 | sclass | 記憶クラス（§4.1） |
| 17 | u8 | naux | 補助エントリ数（0 または 1 のみ観測） |
| 18 | u16 | x | **派生型の鎖**（2 ビットずつ、シンボルに近い側から。1=ポインタ 2=関数 3=配列）。標準 COFF では n_type の上位に入る部分が別フィールドになっている |
補助エントリも 20 B。**C の識別子には `_` が前置される**（`main`→`_main`）。ランタイム/アセンブラのシンボルは `_@cstart`、`@@lsmul` などそのまま。

### 4.1 記憶クラス（実測）
| sclass | 意味 | 出現 |
|---|---|---|
| 0x01 | 自動変数（関数内ローカル）。value = スタック上のオフセット【推: §6】、scnum=-1 | 多 |
| 0x03 | ファイル内 static の**関数**、およびコンパイラ生成の定数ラベル `L0020` 形式（scnum=セクション、value=フラッシュ上アドレス、型なし）。static 変数にもこの値が使われると推測するが未観測 | 関数・ラベル=多 / 変数=不 |
| 0x04 | レジスタ変数。value = レジスタ番号（6=L, 7=H のみ観測。RL78 の 8 ビットレジスタ番号 X=0,A=1,C=2,B=3,E=4,D=5,L=6,H=7 と整合）【推】 | 多 |
| 0x09 | スタック渡しの引数（value=スタック上のオフセット） | 多 |
| 0x11 | レジスタ渡しの引数（value=レジスタ番号、関数の入口で L/H 等へ載せ替えた先）【推】 | 多 |
| 0x20 | 定数（EQU）。`_@STBEG` `_@STEND` `_@SADSIZ` `_@MAA`、scnum=-1 | 多 |
| 0x26 | 公開シンボル（関数、グローバル変数、ラベル）。value=アドレス | 多 |
| 0x27 | 公開ビット変数（`bit x;`）。value=バイトアドレス（0xFFE20）、scnum=@@BITS、typ=0x034C。**ビット位置の符号化は【不】**（唯一の例は 0 番ビット。`.sym` では `03` + ((addr−0xFFE00)<<3 \| bit)） | 1 |
| 0x64 | `.bb` / `.eb`（ブロック開始/終了）。補助=行番号 | 多 |
| 0x65 | `.bf` / `.ef`（関数本体の開始/終了）。補助=行番号など | 多 |
| 0x67 | `.file`。モジュールの先頭（§6） | 多 |
| 0x77 | モジュール名エントリ（`.file` の直後。name=リンカのモジュール名 `r_main`、`@cstart` など） | 多 |
| 0x78 | モジュールが各出力セグメントに寄与する先頭アドレス（name=セグメント名、scnum=出力セグメント番号、value=そのモジュールの寄与の開始アドレス） | 多 |
標準 COFF の C_STRTAG/C_MOS/C_EOS/C_UNTAG/C_MOU/C_ENTAG/C_MOE/C_FIELD/C_TPDEF は **5 サンプルのどこにも出現しない**（typedef は展開され、名前は残らない）【不】。

### 4.2 補助エントリ（20 B）
共通: 先頭 u32 = 0（標準 COFF の tagndx。構造体タグ参照になると思われるが【不】）。
- **関数（x の最下位が 2）** 【多】: `[4] u32 関数のバイト長` / `[8] u32 行番号表内の位置（ファイルオフセット）` / `[12] u32 この関数の .ef の次のシンボル番号` / `[16] u32 1=通常関数、0=割り込み関数（typ の 0xE000 付き）`。長さ=次の同セクション関数の先頭アドレスとの差、は 5 サンプル計 101 関数中 91 で一致（残り 10 件=各サンプル 2 件は、各セクションの最後の関数など次の関数との差が取れない/ランタイムが挟まるもので、不一致の原因は未調査【不】）。
- **ポインタ（x 最下位が 1）** 【多】: `[6] u16 = 2`（ポインタ自身のバイト数、near）、`[18] u16 = 1`（意味不明: near/far の区別と推測【推】）。残りは 0。
- **配列（x 最下位が 3）** 【多】: `[6] u16 = 配列全体のバイト数`、`[8] u16×4 = 各次元の要素数`（観測は 1 次元のみ。標準 COFF の x_dimen と同位置）。残りは 0。
- **`.file`**: ファイル名。14 文字以下ならインライン（先頭 14 B、NUL 詰め）、それより長いと先頭 4 B が 0、次の u32 が文字列表オフセット【多】。`.file` エントリ自身の value は連鎖用の値と思われるが使わない【不】。typ=0x3F は C ソース由来、0 はアセンブラ由来【多】。
- **`.bf`**: `[4] u16 = 開始行(`{` の行)`、`[6] u16 = ローカル/引数が占めるバイト数と思われる値【推】`、`[12] u32 = 次の関数のシンボル番号`。
- **`.ef`**: `[4] u32 = 終了行の相対値`（`.bf` の行を 1 として数える。終了行 = bf行 + 値 − 1。AD_delay: 開始 41、値 4、実際の `}` は 44）。
- **`.bb` `.eb`**: `[4] u32` に行（相対）。他は【不】。
- 補助エントリを持たない `.bf/.ef` や、nAux>1 は観測していない。

## 5. 型【多】（観測した範囲）
`typ` 下位 4 ビット = 基本型。標準 COFF と同じ番号を使っていることを実測確認:
| 値 | 型 | サイズ | 観測 |
|---|---|---|---|
| 1 | void | – | 多 |
| 2 | char（符号付き。無修飾 char は signed） | 1 | 不 |
| 3 | short | 2 | 不 |
| 4 | int | 2 | 多 |
| 5 | long | 4 | 多（`long s` ローカル） |
| 6 | float | 4 | 不 |
| 7 | double | 4（CA78K0R は double も 4B） | 不 |
| 8/9/10/11 | struct / union / enum / enum メンバ | – | 不（標準値の外挿） |
| 12 | unsigned char（`uint8_t`） | 1 | 多 |
| 13 | unsigned short（`uint16_t`） | 2 | 多 |
| 14 | unsigned int | 2 | 多 |
| 15 | unsigned long（`uint32_t` は `unsigned long`） | 4 | 不 |
`signed char`/`int8_t` が 2 か別コードかは未観測。0 は型なし（ランタイムの記号）。

`typ` の上位ビット（実測）:
- `0x0100`: C_REG(0x04)/C_REGPARM(0x11) のシンボルにだけ付く。レジスタ割付けの印と思われる。型には無関係として無視してよい【多】。
- `0x1000`: **`volatile` の非ポインタ変数**に付く（`volatile uint8_t`→0x100C、`volatile uint16_t`→0x100D。`volatile` でない同型には付かない）【多】。
- `volatile uint8_t *p`（ポインタの指す先が volatile）は typ=0x000C のまま、**指す先の volatile は残らない**【1: CSI の 6 変数】。
- `uint8_t * const p`（const ポインタ）の引数は typ=0x500C、`uint16_t * const` は 0x510D（0x0100 はレジスタ印）。つまり `0x5000` = const ポインタ。0x1000 と 0x4000 の個別の意味は区別できない【1 サンプル 3 件】。
- `0xE001`（void ＋ 0xE000）: `__interrupt static void f(void)` の割り込み関数。補助の末尾 u32 が 0【多】。
- `0x034C`: `bit` 変数（上記 0x27）【1】。

### 型の復元アルゴリズム
```
def decl(sym, name):
    base = sym.typ & 0xF
    levels = [(sym.x >> (2*i)) & 3 for i in range(8) if (sym.x >> (2*i)) != 0 or i == 0 and sym.x]   # 下位から、0 になったら終わり
    # levels[0] がシンボルに最も近い派生
    d = name; dims = array_dims(sym.aux[0]) ; k = 0
    for i, lv in enumerate(levels):
        if lv == 1: d = '*' + d                      # ポインタ
        elif lv == 3: d = wrap_if_prev_is_ptr(d) + '[%d]' % dims[k]; k += 1
        elif lv == 2: d = wrap_if_prev_is_ptr(d) + '()'
    return base_name[base] + ' ' + d
size(sym):  ポインタ=2(near、far は【不】)、配列= aux[6..7]（= 要素数×要素サイズ）、スカラ= §5 の表
```
派生型は 1 段しか観測していない（ポインタのポインタ、ポインタの配列、関数ポインタは【不】）。複数段が上の鎖で正しく表れるかは標準 COFF 流の外挿。

## 6. モジュール構造とシンボル表の走査【多】
シンボル表は次の順に並ぶ:
1. **モジュールごとのブロック**（リンク順。`.map` の入力モジュール順、`.sym` の `;FF モジュール名` の順と一致【多】）
```
.file (0x67)            aux = ソースファイル名（C は typ=0x3F、asm は 0）
<module> (0x77)         name = モジュール名（`.file` の名前から拡張子を取ったもの。長いと文字列表）
@@xxx (0x78) × k        このモジュールが寄与するセグメント（scnum, 開始アドレス）。モジュールの寄与量=次の寄与モジュールの開始 − この開始（`.map` の入力モジュール行と開始アドレスが全件一致【多】）
[関数ブロック] × n      C モジュールのみ
```
   関数ブロック:
```
_func (0x26 公開 | 0x03 static, x 最下位=2, aux あり)   value=関数の先頭アドレス、scnum=@@BASE/@@CODEL 等
.bf (0x65, aux)
  引数 (0x09/0x11) …    宣言順
  ローカル (0x01/0x04) …
  .bb (0x64) … .eb       ブロックの境界（ローカルはブロックの前にまとめて出る。ブロックごとの所属は【不】）
.ef (0x65, aux)
```
   型の変数エントリ（typ/x/aux 付き）の `name` は `_` 付き、引数名は元の名前に `_` が付く（`_cmd_name`）。
2. **公開シンボル群**（クラス 0x26/0x27/0x20）。順序は名前順ではなくリンカ内部順。ここに**グローバル変数**（typ/x/補助付き）、ランタイム記号（`_@cstart`、`_@STBEG`、`_?R_INIT` …）、アセンブラ公開名（`_exit`、`_stkinit`、`@@lsmul`）が入る。**公開関数は関数ブロック側にだけあり、この群には無い**。
3. 末尾に `L0020` 形式の 0x03 ラベル（FunctionDemoCode 4 件、`.sym` では所属モジュールが付く/公開のものが混在し、lmf からは区別できない）。

### 変数をソースファイル・関数に結びつける
- **関数ローカル/引数**: 関数ブロック内のエントリ（`f.params` / `f.locals`）で関数に結びつく。関数→ファイルはブロックの `.file`。
- **ファイル内 static 関数**: モジュールのブロック内で sclass=0x03（`<` つきの `.sym` ローカルと一致【多】）。
- **グローバル変数のファイル**: lmf は変数にモジュールを記録していない。所属は「変数のアドレスが、同じ scnum のどのモジュールの寄与範囲に入るか」で決める（0x78 エントリの開始アドレス以上で最大のもの。同じ開始が複数あるときはリンク順で最後）。CSI の全 20 変数で C ソースの定義位置と一致【1 サンプルを目視】（`lmfdump.py --symbols` の `mod=`）。
- **関数内 static / ファイル内 static 変数**: サンプルに無く【不】。

### スタートアップ/ランタイムのシンボル【多】
`_@cstart`（リセットベクタ `@@VECT00` の指す先、`@@LCODE` 先頭）、`_@cend`、`_main`、`_hdwinit`、`_exit`、`_stkinit`、`_@STBEG`（スタック先頭、EQU）、`_@STEND`、`_@SADBEG`、`_@SADSIZ`、`_@MAA`、`_@MEMBTM`/`_@MEMTOP`/`_@BRKADR`/`_@FNCTBL`/`_@FNCENT`/`_@SEED`/`_@DIVR`/`_@LDIVR`/`_@TOKPTR`/`_errno`（ランタイム RAM）、`_?R_INIT`/`_?INIT`/`_?DATA`…（各セグメントの末尾アドレス）、`_@vectNN`（ベクタ）、`_@RTARGn`/`@@FPR*`（レジスタ領域）。型なし（typ=0）。

## 7. 行番号【多】（優先度低）
セクションの ptr_D から nlnno 個、8 B（`u32, u32`）:
- `(関数のシンボル番号, 0)` = 関数の開始。
- `(アドレス, 行)` = 文の先頭アドレスと行。**行は関数の `.bf` の行（`{`）を 1 とする相対値**（絶対行 = bf行 + 値 − 1。LED の main: bf=63 に対し相対 2,3,6 は実ソースの 64,65,68 行）。
- 関数補助エントリ `[8]` が該当関数の開始エントリ位置を指す（5 サンプルで範囲内）。
ソースファイルのパスは持たない（`.file` はファイル名のみ）。

## 8. `.sym` との対応（`lmfdump.py --sym`）
- PUBLIC 群 = lmf の「公開関数（関数ブロックの 0x26）＋ 0x26/0x27/0x20」。
- 属性: 0x20→`00`、0x27→`03`、セクションが ROM 側(k1=0x20)→`01`、RAM 側→`02`、scnum=-1 の 0x26（`_@SADBEG`）→`01`。アドレス = value（20 ビット）、ビットは (value−0xFFE00)<<3。
- `;FF モジュール名` の並び = lmf のモジュール順。モジュールのローカル群 = 0x03 の関数（`<` は先頭行だけに付き、以降の行も同じモジュールのローカル）。`L0020` 形式のラベルは全体で照合（所属は区別不能）。
- `.sym` は `_` 付きの名前をそのまま持つ（`_main`）。
