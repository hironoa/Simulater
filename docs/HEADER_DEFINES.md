# ヘッダからの直アドレス定義

`defines = パス` は複数指定でき、`--defines パス` で追加できる。設定の相対パスはsim.cfgのあるフォルダ基準。
ファイル、フォルダ、`*` パターンを受け付ける。フォルダでは既定でサブフォルダまで.h/.c/.incを大小文字を問わず走査し、
ドットで始まる名前とディレクトリリンクはたどらない。`defines_recursive = off` なら直接のファイルだけ。
`defines_exclude = 文字列または*パターン` を複数指定できる。文字列はパスの部分一致、パターンは全パスまたはファイル名へ照合する。

## 取り込む形

- `#define REG (*((volatile unsigned char*)0xFF91C))`、`(*(型*)番地)`。
- `#define BIT (((volatile typeBit*)0xFFFA4)->b4)`、`((*(型*)番地).メンバ)`、複数階層のメンバ。
- オブジェクト形式の定数マクロを参照した番地計算。整数式の演算子とトークン展開は下記の共通評価器に従う（展開32段まで）。
- ポインタ定数だけのマクロは登録せず、pointer-skipped件数へ入れる。

マクロ本体を左辺値として最後まで読めた場合だけ登録する。`*`、括弧、`.` / `->`、定数添字を扱う。
キャストの番地は整数定数、定数マクロ、または括弧で閉じた定数式に限る。
裸の整数の後ろの二項演算子はキャストの被演算子に含めない。

| 形 | 扱い |
|---|---|
| `(*((volatile unsigned char*)0xFF91C))`、`(*((volatile u1*)0xFFFA4))` | 登録（u8） |
| `(((volatile typeBit*)0xFFFA4)->b4)` | 登録（解決したビット型、または既存の推定規則） |
| `*(unsigned short*)(BASE + 2)` | 登録（括弧内を番地として計算） |
| `((unsigned short*)0xF900)[2]` | 登録（要素サイズ2を掛け、near補正前の番地は0xF904） |
| `((*(Record*)番地).配列)[N]` | 登録（メンバのオフセットと要素サイズを適用。配列範囲外は未解決） |
| `*(const u1*)番地`、const付きtypedef | 登録（読み取り専用）。`(u1* const)`は指す先が非constなら書込み可 |
| `(*(unsigned short*)0xF900 & 0xFF)`、`(*(unsigned short*)0xF900 + 1)` | 値の式として対象外（登録しない） |
| `((*(volatile u1*)0xFFFA4) >> 4 & 1)`、`(((*(u1*)0xFFFA4) & 0x10) != 0)` | 値の式として対象外 |
| 左辺値の後ろの比較、条件演算、カンマ、代入、関数呼出し | 値の式として対象外 |
| 前置の`~` / `!` / `-` / `&` / `sizeof`、値型へのキャスト | 値の式として対象外 |
| `(*((unsigned short*)0xF900 + 1))`など、キャストの外側のポインタ加減算 | 対象外（要素サイズを掛ける演算は未対応。バイト加算で代用しない） |
| 型不明、番地の定数式が解決不能、二重キャスト、複雑なポインタ宣言子 | 未解決（登録しない） |

修飾子volatile/const/__near/__far/__sreg/__saddr、余分な括弧、バックスラッシュ改行、行末・複数行コメントを扱う。
文字コードはファイルごとに判定する。UTF-8 BOM があれば UTF-8、なければファイル全体が妥当な
UTF-8（過長符号化・サロゲート・範囲外コードポイントを除く）なら UTF-8、それ以外は Shift_JIS。
ASCII のみは別に数える。同じフォルダに異なる文字コードのファイルを置ける。
Shift_JIS の先行バイトは、有効な後続バイト（0x40〜0x7E、0x80〜0xFC）がある場合だけ2バイトとして扱う。
半角カナは1バイト。改行・CR・終端は後続バイトにしない。
コメント、行継続、文字列・文字定数、条件指令、typedef / struct に共通の前処理を適用する。
有効な2バイト文字の後続 0x5C を継続やエスケープと解釈しない。
`*`・`/`・`"` は有効な後続バイトではないので、不正な先行バイトの直後でも構文記号として扱う。
UTF-16 BOM（FF FE / FE FF）または NUL が全体の1/4以上あるファイルは読まず、`sim info` に件数を表示する。
`sim info --verbose` に UTF-8 / Shift_JIS / ASCII のファイル数も表示する。
ブロックコメント・文字列・文字定数、条件系列、括弧・角括弧・波括弧が閉じないファイルは
「構文を追えなかったファイル」として数え、verbose ではファイル名と開始行を表示する。
行コメントが改行なしでファイル終端に達するのは正常。この診断は字句上の対応検査であり、C構文全体の検証ではない。
数値番地が0xFFFF以下なら既定で0xF0000を足す。`defines_near_base = 0` で加算を無効にできる。
加算と型推定はverboseで表示する。20ビット範囲外の番地・アクセス全体、負の番地は未解決（ロード自体は継続）。

配列長・番地・ビット幅の定数マクロは、`#if` と同じく値ではなくトークン列として展開する。
例えば `#define COUNT 1+2` の `COUNT*2` は5（`(COUNT)*2` は6）。
入れ子32段、展開後1024トークン、走査16384ステップ、式の構文入れ子128段で打ち切る。
展開中の名前は再展開せず、`#if` では残った識別子を0、定数式では未解決にする。
定数式の未定義名・関数形式マクロ、構文の不一致・余分なトークン、負の結果は未解決。
定数式は64ビットで評価し、`#if` の32/64ビット真偽一致の規則とは区別する。

## 型

Cのchar/short/int/long/float/doubleと符号指定、uint8_t/int8_t等、およびu8/s8/u16/s16/u32/s32/f32を扱う。
char=1、short/int=2、long/float/double=4バイト。charの符号はchar_unsigned=on/offに従う。
long long / unsigned long long はCC-RLで8バイト（s64/u64）。CA78K0Rでは未解決。
ロードモジュールのないモックでも8バイトとして扱う。
全ファイルの収集後に型とマクロを解決するため、typedefが別フォルダにあっても読み込み順に依存しない。
基本型、ヘッダのtypedef（別名の別名、限定的なstruct/union）、変数のデバッグ型から到達できる同名タグ、ctypeの順。

構造体は基本型・別名・固定長配列・ビットフィールド・入れ子のstruct/union・無名メンバを扱う。
char系の整列は1、他は2。配列は要素の整列、構造体はメンバの最大整列。
ビットは下位から、宣言型の格納単位内へ配置し、型が変わるか収まらなければ次の単位へ進む。
名前のないビットフィールドも領域を消費し、`:0` は格納単位を区切る。
解決できないメンバが1つでもあれば、構造体・共用体全体を未解決にする。前方のメンバやビット番号らしい名前も登録しない。
ヘッダで定義された型の解釈に失敗した場合は、同名のデバッグ型やctypeへ置き換えない。

| 形 | 扱い |
|---|---|
| `unsigned` / `signed`、`short int`、`unsigned short int` | 正しく解釈（int/shortは2バイト） |
| `long int`、`long unsigned int`、`int unsigned` | 正しく解釈（longは4バイト） |
| `signed char` / `char signed` | 正しく解釈（符号つき1バイト） |
| `long double`、`_Bool` / `bool`、値型の`void` | 未解決 |
| `((void*)番地)` | ポインタ定数としてpointer-skippedへ集計（値型の変数にはしない） |
| 配列typedef、配列を含む構造体、配列メンバ、多次元`[2][3]` | 正しく解釈（最大33次元、総サイズは1MiB以下） |
| 配列長の整数定数・定数マクロ・単純式 | `#if` と共通の整数式評価器を使う。解決不能、空`[]`、0、負数、サイズ超過は未解決 |
| `typedef unsigned char u1, *pu1, a4[4];` | u1とa4は正しく解釈、pu1は未解決。それぞれの宣言子を独立に扱う |
| ポインタtypedef（near/far）、関数ポインタtypedef | 未解決。指す先のサイズで登録しない |
| `const` / `volatile` / `__near` / `__far` / `__sreg` / `__saddr` | 基本型・typedef名の前後と基本型の語の間で受け付ける。ポインタ幅の推定には使わない |
| 同一行の通常メンバと配列メンバ、名前のないビット詰め物、`:0` | 正しく解釈 |
| 名前つき・無名の入れ子struct/union、別定義の`struct tag`メンバ | 正しく解釈 |
| ポインタメンバ・関数ポインタメンバ・enumメンバ・不明型メンバ | 構造体全体を未解決（enumのサイズは推定しない） |
| `(*(ArrayTypedef*)番地)` | 配列として登録。CSVで`&名前`に`1|2|3|4`を書ける |
| `((型*)番地)[N]` | 定数添字と要素サイズから番地を計算して登録 |
| `(*(型(*)[N])番地)`、二重キャストの番地 | 未解決 |
| `#pragma pack`、`__packed`、`__attribute__` | 未対応。走査対象のどこかに存在すれば、全ヘッダのstruct/unionを保守的に未解決とする。無効な条件枝の指定も含む |

詰め指定はincludeをまたいで作用し得るため、ファイル単位では安全を保証できない。
上記の拒否はタグ名・typedef名の両方に適用する。`defines_guess_bits`でも既知の未対応型を救済しない。

```ini
ctype = u1 : u8
ctype = typeBit : bits8
```

bits8/bits16のメンバは英字列+数字（b4/bit4/no4/B4等）をビット番号として解釈する。
型が解決できない構造体の同じ形式のメンバも、既定で8ビット内のビットと推定する。
`defines_guess_bits = off` なら推定せず未解決とする。推定であることをverboseで表示する。

## 優先順位と表示

ロードモジュールの同名シンボルはヘッダより優先する。明示的なvarは両方より優先する。
同名で同じトークン列の定義は重複させない。異なる定義はファイル名順（同じファイルでは行順）で最初のものを採り、件数を表示する。
左辺値と値の式の同名定義もこの規則に従う。最初が値の式なら、後の左辺値で救済せず対象外にする。
対象外・未解決の件数は選択した定義について数え、採用されなかった定義は重複件数だけに含める。
verboseでは両方のファイル名・行番号とdefines_excludeの案内を出す。
`sim info` はファイル数、変数・ビット・配列・推定・未解決・重複・見送ったポインタ定数・値の式の対象外（`value-excluded`）・所要時間を表示する。
値の式の対象外は未解決と別に数え、`--verbose`で名前、ファイル名と行番号を表示する。
未解決の名前はverboseだけに表示する。sim listは取り込んだ変数と定義元ファイルを表示し、
`sim list --where` は定義元の行番号も添える（`[パス:行]`。`var` / `varfile` の定義も同じ）。
同じ名前で内容の違う定義は、verboseで両方のファイル名・行番号を表示する（typedef / structも行番号つき）。

## コンパイルスイッチ（#if / #ifdef の評価）

品種やビルド構成で番地・型が変わるヘッダは、コンパイル時と同じ定義マクロを与えると、有効な枝だけを取り込む。

```ini
defines = ../product
cdef = PRODUCT=2          # 名前=値。複数行書ける
cdef = SIM                # 値を省くと 1
cundef = __K0R__          # 定義を外す（暗黙の定義、mtpj、cdef のどれでも）
mtpj = ../product/project.mtpj   # CS+ のプロジェクトファイルから定義マクロを読む
mtpj_mode = DefaultBuild         # ビルド・モード（省くと CS+ で選択中のモード）
defines_cond = on                # off なら #if を評価せず、すべての枝を読む（従来の動作）
```

コマンドラインでは `--cdef 名前[=値]`（複数回）と `--mtpj パス`。
適用の順は、暗黙の定義 → mtpj の定義マクロ・定義解除マクロ → sim.cfg の `cdef` → `--cdef` → `cundef`。
後のものが前のものを上書きする。`cundef` は書いた位置に関係なく最後に効く。

### 評価の規則

- 対応する指令: `#if` `#ifdef` `#ifndef` `#elif` `#else` `#endif` `#define` `#undef` `#include "…"` / `#include <…>`。
  `#pragma pack` は上記の構造体拒否に使う。それ以外の `#pragma`、`#error`、`#line` などは無視する。関数形式のマクロは、定義されていることだけを覚える（`defined(X)` は真）。
- 式: 整数定数（10進・16進・8進・2進 `0b`、`U` / `L` 接尾辞）、文字定数、`defined(X)` / `defined X`、
  単項 `! ~ - +`、二項 `* / % + - << >> < <= > >= == != & ^ | && ||`、`?:`、括弧。
  オブジェクト形式のマクロはトークン列として展開する（入れ子32段まで。自己参照は展開せず0）。未定義の識別子はCと同じく0。
- **判定不能**: 0除算、関数形式マクロの呼び出し、文字列、浮動小数、値のない（空の）マクロ、符号付きの桁あふれ、
  構文の誤りなど、評価できない式。その `#if` 〜 `#endif` の系列は**すべての枝を読む**（内容が違えば重複として数える）。
  `&&` `||` `?:` で選ばれない側が評価できなくても、判定不能にはならない（`defined(X) && 8 / X == 4`）。
- 式の幅はコンパイラで違う（C90はlong = 32ビット、C99はintmax_t = 64ビット）ので、32ビットと64ビットの両方で評価し、
  真偽が一致したときだけ採る。`0xFFFFFFFF + 1` や `-2147483648 < 0` のように幅で真偽が変わる式は判定不能にする。
  左シフトは幅で切り捨て、符号付きの右シフトは算術シフトとする。
- 処理の単位: 走査で見つけた各ファイルを起点として上から順に読む。マクロの状態は**起点ごと**に、
  上の定義マクロから始める。`#include` は、走査したファイルの中からファイル名で探して、その場で読む
  （パスの末尾一致、大文字小文字は区別しない、先頭の `./` `../` は無視。同名が複数あれば、インクルード元と共通する
  フォルダの階層が深いもの）。インクルードガードは通常の `#ifndef` / `#define` として効く。
  走査した中にない `#include`（標準ヘッダなど）は無視する。入れ子は64段までで、ガードのない循環はそこで打ち切る。
- どこからもインクルードされていないファイルを先に起点にし、どの起点からも読まれなかったファイルを追加の起点にする。
  各起点の有効な枝にある直アドレスのマクロ・定数マクロ・typedef・structを集め、名前でまとめる。
  同じ内容は1つにし、違う内容が残れば最初のものを使って件数を警告する。

### 限界と注意

- Cのプリプロセッサ全体ではない。関数形式マクロの展開、`#`/`##`、`__FILE__` などの組み込みマクロ、
  `#include` のマクロ展開（`#include HEADER`）は扱わない。インクルード・パスの設定は読まず、ファイル名だけで探す。
- **起点ごとの評価である**: あるヘッダが、インクルードする `.c` によって違う状態で読まれると、両方の結果が集まる
  （違えば重複になる）。`.c` の中で `#define` してからインクルードする形のスイッチ、どこからもインクルードされない
  ヘッダが前提にしているスイッチは、`cdef` で与える必要がある。
- 番地の計算に使う定数マクロは、全起点でまとめた後の定義（最初のもの）を使う。
- `defines_exclude` などで走査から外したファイルは、`#include` されていても読まない。
- 条件が `#if` 〜 `#endif` の途中でファイルをまたぐ書き方（`#if` と `#endif` が別のファイル）は扱わない。
  ファイルの終わりまでに `#endif` がなければ、そこで系列を閉じる。

### 暗黙に定義するマクロ

コンパイラが最初から定義しているマクロのうち、品種・メモリモデル・オプションに依らないものだけを定義する
（`sim info --verbose` に一覧。`cundef` で外せる）。ロードモジュールの種類（`abi =` の指定があればそちら）で選ぶ。

| ロードモジュール | 定義するマクロ（値は1） | 定義しないもの（必要なら `cdef` で） |
|---|---|---|
| lmf（CA78K0R） | `__K0R__` `__CA78K0R__`。`char_unsigned = on` のとき `__CHAR_UNSIGNED__` | `__RL78__` `__RL78_1__`〜`__RL78_3__`（品種）、`__K0R_SMALL__` `__K0R_MEDIUM__` `__K0R_LARGE__`（メモリモデル）、品種名のマクロ、`__STDC__` |
| abs（CC-RL、ELF） | `__CCRL__` `__CCRL` `__RL78__` `__RENESAS__` | `__RL78_S1__`〜`__RL78_S3__`、`__RL78_SMALL__` `__RL78_MEDIUM__`、`__RENESAS_VERSION__`、`__DBL4` / `__DBL8`、`__UCHAR` / `__SCHAR` など |

CA78K0Rの分は [CA78K0R_NOTES.md](CA78K0R_NOTES.md) 6節の調査による。CC-RLの分はユーザーズマニュアルの「定義済みマクロ」の記憶に
基づき、この実装のときに資料で再確認はしていない。モック（ロードモジュールなし）では何も定義しない。

### CS+ のプロジェクトファイル（mtpj）

`mtpj = パス` / `--mtpj パス` は、CS+ のプロジェクトファイル（XML、UTF-8）からコンパイル・オプションの
「定義マクロ」と「定義解除マクロ」を読む。実例（`tests/ca78k0r_probe/ca78k0r_probe.mtpj`、CS+ 5.02 / CA78K0R V1.60）で
分かったことと、推定していることは次のとおり。

| 項目 | 内容 | 確度 |
|---|---|---|
| ビルド・モードの一覧 | `<BuildModeCount>`、`<BuildMode0>`…（名前をUTF-16LEにしてBase64にしたもの） | 実例で確認 |
| 選択中のモード | `<CurrentBuildMode>`（そのままの文字列） | 実例で確認 |
| 定義マクロの要素 | コンパイラのオプションを持つ `<Instance>` の `<MacroDefinitions-N>`（Nはモードの番号、0始まり） | 要素は実例で確認（中身は空だった） |
| 定義解除マクロの要素 | 同じ `<Instance>` の `<MacroUndefinitions-N>` | 要素は実例で確認（中身は空だった） |
| アセンブラとの区別 | アセンブラの `<Instance>` にも `<MacroDefinitions-N>` があるが `<MacroUndefinitions-N>` はない。両方を持つ方をコンパイラとする | 実例の構造からの推定 |
| 中身の書式 | 1行に1個、`名前` または `名前=値`、改行区切り、XMLのエスケープ（`&lt;` など） | **推定**（同じファイルの複数行の項目 `StandardLibraryFileNames` が改行区切りでそのまま入っていることから） |
| ファイルごとの個別オプション | 読まない（それらしい要素があれば件数を `sim info` に出す） | 未確認 |
| CC-RL のプロジェクト | 要素名が違うはずで、読めない（`sim info` に「要素が見つかりません」と出る） | 未確認 |

推定を含むので、**読み取った定義マクロの一覧を `sim info` に必ず表示する**。CS+ の画面の内容と見比べ、
違っていれば `cdef` / `cundef` で直すか、`mtpj` を使わずに `cdef` だけで与える。
確定するには、定義マクロに `PROBE_SWITCH=1` と `PROBE_FLAG`（値なし）を足して保存したプロジェクトファイルが1つあればよい。
`mtpj_mode` を省くと選択中のモード、それが一覧になければ最初のモードを使う。名前として読めない行は無視して表示する。

### 結果の確かめ方

`sim info` に次を表示する。

- `defines cond=on roots=… includes=… include-reused=… include-missing=… include-cut=… if-evaluated=… if-indeterminate=…`:
  起点の数、展開した `#include` の数（うち前回の結果を再利用した数）、走査した中に見つからなかった `#include` の箇所数、
  深さの上限で打ち切った数、評価した条件の箇所数、判定不能だった箇所数。
- `cdef implicit=… mtpj=… cfg=… cli=… cundef=…` と、有効な定義マクロの一覧（暗黙の分は `--verbose`）。
- **条件の判定に使われたが、どこにも定義がなく0（未定義）とみなした識別子**の一覧。参照の多い順に上位20個
  （`--verbose` で全部）。括弧の中は参照した回数（条件の箇所ごとに1回目の評価だけ数える）。
  スイッチの指定漏れはここに出る。インクルードガード（`#ifndef X` の直後に `#define X`）は除く。
- `--verbose` では、走査したファイルのどこかに `#define` はあるがその場所からは見えなかった識別子と、
  判定不能だった条件のファイル名・行番号・式も出す。
- `defines time: scan=… read=… cond=… resolve=…`: フォルダの走査、読み込みと行・指令の切り出し、
  条件の評価と収集、型と番地の解決の所要時間。

### 速度

ファイルは1回だけ読み、コメントを除いて行と指令に分けておく。読まない枝は1回で飛び越す。マクロの状態は
名前の番号で引く配列に持ち、起点を替えるときは世代を進めるだけにする。あるファイルを読んだ結果は
「読む前の状態のうち実際に参照したマクロ」だけで決まるので、同じ状態で再び `#include` されたときは、
`#define` / `#undef` の結果を再生するだけで読み直さない（全ヘッダを取り込む共通ヘッダを各 `.c` が読む構成でも
ファイル数の2乗にならない）。
合成データ（`tests/tools/gen_defines_bench.c`。2000ファイル・42.7MB・直アドレスのマクロ14.4万個、
半分の `.c` が全ヘッダを取り込む）で約0.75秒、5000ファイル・108MB・36万個で約2.8秒（Apple シリコンの Mac、-O2、
ファイルがOSのキャッシュに載った状態。初回は読み込みの分だけ0.3〜0.8秒ほど増える）。
共通ヘッダの `#define` の再生は「起点の数 × 定義の数」に比例するので、これより大幅に大きいと秒単位で伸びる。
実際のソースでの所要時間は `sim info` の `defines time:` で確認できる。

## var / varfile

```ini
var = P1 : u8 @ 0xFFF01
var = ADCR : u16 @ 0xFFF1E
var = TBL : u8[16] @ 0xFE900
var = P1_0 : u8.0 @ 0xFFF01
var = FLAGS : u8.4-6 @ 0xFE800
varfile = registers.txt
```

varfileは1行に`名前 : 型 @ 番地`、#以降はコメント。設定のフォルダ基準で読む。
UTF-8 BOMを除き、ASCIIの構文を解釈する。型・配列長・ビット範囲・番地を検証し、不正な行は終了コード2。
型はu8/s8/u16/s16/u32/s32/f32。入力、初期化、GUIの検索・監視・入力、sim listで同じ名前を使う。
ビット／ビット範囲への書き込みは他のビットを保持する。同名の明示定義が複数あれば後のものが優先する。
モックは元の64KBメモリの範囲内の番地を使う（例えば0xFF01）。実体のRL78は20ビット物理番地を使う。

## 現時点の限界

Cプリプロセッサ全体ではない（条件の評価の規則と限界は「コンパイルスイッチ」の節）。
スイッチを与えないと `#else` 側の枝を読むので、`sim info` の未定義の識別子の一覧を確かめること。
関数形式マクロの展開、ポインタ定数の配列化、ポインタメンバ、複雑な宣言子、可変長配列、関数型のtypedef、
変数添字、任意のC式やアドレス以外のオブジェクト定数の公開は対象外。
iodefine専用の__bitf_T.no0〜no7自動生成は未実装。取り込める通常の形はdefinesから読み、必要ならctype=bits8を使う。
Windowsのフォルダ走査は既存方針と同じANSI APIで、実行確認はしていない。

通常のSFRは周辺機能を模擬しないメモリで、監視はプログラムが書いた値、入力はプログラムが読む値を扱う。
SP/PSWや乗除算器などコアが模擬しているレジスタの動作は別に適用される。
