# 設計書

RL78 向け組み込みソフトを、CS+ / CC-RL でビルドしたロードモジュール（`.abs`）のまま PC 上で実行するシミュレータ。
WinAMS と同じ命令シミュレータ方式だが、CPU コアを速度優先で自作し、テスト CSV の実行と結果 CSV の出力、
リアルタイム GUI を備える。

機械語をそのまま解釈実行するので、`int` 16 ビット、ポインタ幅、構造体の配置、SFR のアドレス、
アセンブラで書かれた処理は、すべて実機と同じに動く。対象ソフトの再ビルドやスタブの追加は要らない。
WinAMS 用にビルドした `.abs`（テストドライバとスタブ入り）をそのまま使う。

## 1. 全体構成

```
rl78/           RL78 CPU コア（命令デコードと実行、1MB メモリ、ミラー領域、乗除算器）。単体でテストできる
runtime/        シミュレータ本体（C11、外部依存なし）
  src/            CSV の読み書き、変数名式、HTTP/SSE サーバ、周期実行ループ、sim.cfg、バックエンド抽象（include/sim_backend.h）
  backends/rl78/  本物のバックエンド: .abs（ELF/DWARF）と .map の読み込み、CC-RL の呼び出し規約での関数呼び出し、
                  スタブ、CPU コアとの接続
  backends/mock/  共通部分のテスト用のモック
build.bat       Windows 用ビルドスクリプト（clang を直接呼ぶ。CMake も Python も使わない）
build.sh        macOS / Linux 用の同じもの
example/        sim.cfg の見本など
gui/            リアルタイム GUI（SignalViewer2 を取り込んだ React アプリ）。単一 HTML にビルドしてコミットする
tests/          自動テスト（run_tests.sh / run_tests.bat）。rl78/ に本物のバックエンドのテスト、
                fixtures/renesas/ にルネサス公式サンプルの .abs（BSD-3）、tools/mkabs.c にテスト用 .abs の生成器
docs/
```

ビルドすると実行ファイル `sim`（Windows では `sim.exe`）と、その隣に `sim_gui.html` ができる。

- バッチ: `sim run --abs <ロードモジュール.abs> [--cfg sim.cfg] <テスト.csv>... [-o 出力フォルダ]`
- GUI: `sim gui --abs <ロードモジュール.abs> [--port 8765] [--period-ms 5] [--speed 1] [--record-max 200000]`。
  数値は文字列全体を読み、`--port` は 1〜65535、`--period-ms` は 0.01〜60000、`--speed` は 0（最速）か 0.1〜100、
  `--record-max` は 1 以上の整数。範囲外や `8765x` のような末尾のごみは終了コード 2 のエラー。
- 一覧: `sim list --abs <X.abs> [文字列]`（変数と関数、アドレス、型、定義ファイル）
- 概要: `sim info --abs <X.abs>`（ELF/DWARF の概要、コア種別、ミラー・RAM・スタック・ヒープ、セクション、
  スタートアップの命令数、リンクマップとの照合）
- 共通オプション `--verbose`（`-v`）で読み込み中の警告（知らない DWARF 属性など）を表示する。
- 設定ファイル `sim.cfg`（KEY=VALUE、`#` 以降はコメント）。`--cfg` で指定するか、`.abs` と同じフォルダの
  `sim.cfg` を自動で読む。`abs =` を書けば `--abs` を省ける。キーの一覧と説明は `example/sim.cfg`。
  数値の設定は 10 進、`0x` 16 進、末尾 `H` の 16 進（`0FFF0H`）で書き、値全体を読む。符号付き（`-1`）、単位付き（`32MHz`）、
  0 で始まる 10 進（`010`。8 進と紛れる）、64 ビットや各設定の範囲（アドレスは 0x00000〜0xFFFFF、`ram_fill` は 1 バイト、
  `sentinel`・`call_sp` は偶数）を超える値は、既定値や自動の値に置き換えたり下位ビットに切り詰めたりせず、
  `sim.cfg: KEY = 値 を読めません` のエラー（終了コード 2）にする。`cpu_hz` は正の 10 進の数（指数可）。
- ビルドは `build.sh` / `build.bat`（既定は本物のバックエンド。`mock` を付けるとモック版）。

シミュレータ自体のビルドに必要なのは Clang だけ（Windows は LLVM 公式配布の `clang+llvm-18.1.8-x86_64-pc-windows-msvc`、
macOS は Apple clang）。GUI はビルド済みの単一 HTML をコミットしておく（作り直すときだけ Node が要る）。

## 2. 実行モデルと変数名の解決

WinAMS と同じ流れで動かす。

1. `.abs` を読み込み（PT_LOAD の物理アドレスへ。RAM はその前に `ram_fill` の値で埋める）、リセットベクタから
   スタートアップルーチンを実行する。
2. 初期設定終了アドレス（既定 `main` の先頭、`init_end` で変更可）に達したら止める。この時点の CPU とメモリを
   「初期状態」として控える（リセット用。mod ブロックごと、GUI の reset で戻す）。
   上限（`startup_max_insns`、既定 2 億命令）までに着かなければ、PC と逆アセンブルを添えたエラーで終わる。
3. CSV の 1 行ごとに、入力変数を書き込み、対象関数を CC-RL の呼び出し規約で呼び出し、戻ってきたら出力変数を読む。

### 関数の呼び出し（CC-RL の呼び出し規約）

- SP は初期設定終了時の SP（`call_sp` で変更可）から積む。AX/BC/DE/HL は 0 から始める。
- 引数は左から順に空いている最優先のレジスタへ（1 バイト: A, X, C, B, E, D、2 バイト: AX, BC, DE、
  far ポインタ: A-DE, X-DE, C-DE, B-DE, X-BC（上位レジスタの下位 4 ビットがページ）、4 バイト: BC-AX, DE-BC）。
  入らなければスタック（左ほど低いアドレス、2 バイト境界）。8 バイト型と 5 バイト以上はスタック。
- 戻り値: 1 バイト A、2 バイト AX、3 バイト C-AX、far ポインタ A-DE、4 バイト（float を含む）BC-AX。
  5 バイト以上（long long など）は呼び出し側の領域への near ポインタを第 1 引数として渡し、そこから読む。
- 戻り番地（4 バイト）には番兵アドレス（既定 0xEFFF0、プログラムと重ならない場所を自動で選ぶ）を積み、
  そこに置いたブレークポイントで戻りを検出する。4 バイト目には PSW を入れるので、RETI で終わる割り込み関数も呼べる。
- 1 回の呼び出しは `max_insns`（既定 1 億命令）が上限。超えたとき、未定義命令、`halt = stop` で HALT に当たったときは、
  PC と逆アセンブル（またはバイト列）を添えたエラーにし、その行を NG にして次の行へ進む。
- ポインタの値はアドレスに換算して参照する: near データポインタ（2 バイト）は 0xF0000 + 値、far（4 バイト）は下位 20 ビット。
  `$ptr` のヒープは、ELF のセクションとスタック（`__STACK_ADDR_START/END`）が使っていない RAM から選ぶ
  （なければスタックの底から最大 2KB。`heap` で指定可）。確保は 2 バイト境界に揃え、ヒープの終端（排他的。奇数でもよい）を
  越える確保は「ヒープが足りません」のエラーにする。`heap` / `ram` の範囲が RL78 のアドレス空間（0x00000〜0xFFFFF）に
  収まらなければ、読めない設定として警告し、`heap` は自動の選び方に戻す。
- アドレス直接指定の書き込みは、0xFFFF8〜0xFFFFF（SP/PSW/CS/ES/PMC）だけ CPU のレジスタとして書き、
  ほかはメモリへそのまま書く（ROM も書ける。SFR の副作用は起こさない）。

### デバッグ情報の読み取り

- DWARF 2〜4（CC-RL は 2 と 3 が混在）。5 は見出しだけ読み、文字列の一部（strx）は読めない。
- 型: 基本型、typedef（名前を残す）、const/volatile（剥がす。const の変数と const 要素の配列は書き込み不可）、
  ポインタ（大きさは DW_AT_byte_size、なければ DW_AT_address_class。CC-RL の near データポインタは 4 → 2 バイト。
  知らない値は 4 バイトとして警告し、`addr_class.N = 2|4` で変えられる）、配列（多次元、DW_AT_count / upper_bound）、
  構造体・共用体（匿名メンバを含む）、enum（負の値がなければ符号なし）。
- ビットフィールドは構造体先頭からのビット位置（LSB = 0）に換算する。DWARF4 の DW_AT_data_bit_offset はそのまま、
  DWARF2/3 の DW_AT_bit_offset は記憶単位（DW_AT_byte_size）の MSB から数える標準どおりに
  `単位の先頭 * 8 + 単位のビット数 - bit_offset - bit_size`。CC-RL が非標準なら `bitfield_order = lsb`。
- 変数: DW_AT_location が DW_OP_addr（＋ DW_OP_plus_uconst）のもの。関数内（lexical_block の中を含む）なら関数内 static。
  ロケーションリストの局所変数は対象外。別の CU に同じ変数（extern 宣言）があれば 1 つにまとめる。
- 関数: low_pc のある subprogram。CC-RL の static 関数名に付く `(void)` などは除く。アセンブラの外部ラベル
  （DW_TAG_label）と、.symtab の FUNC / 実行セクションのグローバルラベルも引数なしの関数として加える。
- 知らない属性・タグは読み飛ばし、`--verbose` で警告する。大きさの分からない form があればその CU だけ飛ばす。
- DWARF にない変数は .symtab（`_name`、ファイル内 static は `_name@N`、関数内 static は `_name@N@func`）と
  .map の Symbol List から、型なしで加える（`name:バイト数` で使う。ファイル名は .map の FILE= から）。
  .map は ELF のセクションと照合して `sim info` に結果を出す。

変数と関数は `.abs` のデバッグ情報（DWARF）から解決する。DWARF の読み取りは自前で行い、外部ツールを使わない。

- 対象: グローバル変数、ファイル内 static、関数内 static、関数（アドレス、引数の名前と型、戻り値の型）。
- 型: 基本型（サイズ、符号、浮動小数か）、near/far ポインタ、配列、構造体/共用体（メンバのオフセット、
  ビットフィールド）、enum。typedef/const/volatile は剥がす。
- デバッグ情報がない場合の補助として、リンクマップ（`.map`）からシンボルのアドレスを読む（型は CSV 側で `名前:バイト数` と指定）。

### スタブへの置換

WinAMS の「置換」と同じく、元の関数が呼ばれたらスタブへ飛ばす。対象ソフトは書き換えない。
置換する関数は `sim.cfg` に書く（CSV 実行でも GUI 実行でも同じ設定が効く）。

```
stub = func3_sub_read_io:AMSTB_func3_sub_read_io
stub = read_adc:AMSTB_read_adc
stub_auto = off     # on にすると、AMSTB_<関数名> がある関数をすべて置換する
```

### CPU コア種別

品種が分からなくても動くよう、既定は `core = auto`（S3 の命令と S2 の乗除算器 SFR の両方を有効にした上位互換。
CPU コアに上位互換モードはないので、S3 を選んで乗除算器 SFR（`mdu`）を有効にしている。S3 の MACR（FFFF0H〜）と
乗除算器の MDAL/MDAH は同じアドレスなので、MACH/MACHU の結果を書くと MDB が掛け算の結果で上書きされる）。
`sim.cfg` の `core = S1|S2|S3` で固定できる（S2 は乗除算器あり、S1/S3 はなし。`mdu = on|off` で変更可）。
ミラー領域は PMC.MAA に従う。範囲は既定で `.const` の置き場所（その手前はデータフラッシュとみなす）から RAM の先頭まで
（S1 は F8000H〜）。`mirror = 開始-終了[@写し元]` か `off` で変えられる。

名前の書式は WinAMS に合わせる。

| 書式 | 意味 |
|---|---|
| `name` | グローバル変数。見つからなければ一意なファイル内 static |
| `file.c/name` | ファイル内 static |
| `file.c/func@name`、`func@name` | 関数内 static。引数名と一致すれば引数 |
| `@name` | テスト対象関数の引数 |
| `func@@` | テスト対象関数の戻り値 |
| `a.b`、`a[2]`、`p[0].m`、`a->b` | メンバ、配列要素、ポインタの先 |
| `$ptr` | 値の個数だけ実体を確保してポインタに設定。0 なら NULL |
| `&arr`、`*ptr` | 1 セルに `'文字列'` または `1|2|3` で複数要素（個数に上限はなく、書き込みも期待値の比較も全要素を対象にする） |
| `0xFFF01`、`0xFFF01:2` | アドレス直接指定（`:バイト数`、既定 1）。SFR などデバッグ情報にない場所用 |
| `name:2` | 型を「2 バイトの符号なし整数」として読み書きする（デバッグ情報がなく型の分からないシンボル用） |

`パス/` の部分はファイル名の末尾一致で照合する。

添字（`a[2]`）とアドレス直接指定（`0xFFF01`）の数は、10 進か `0x` の 16 進で書く。`010` のように 0 で始まる 10 進は、
C の 8 進（8）と 10 進（10）のどちらの意味か決められないのでエラーにする（以前は 8 進として読んでいた）。
64 ビットを超える添字・アドレス、要素の大きさを掛けると 64 ビットを超える添字もエラー（飽和や桁あふれで別の場所にしない）。

## 3. テスト CSV と結果 CSV

WinAMS チュートリアルの記述に合わせる。バイト列をそのまま扱い、文字コード（Shift_JIS/UTF-8）と改行コードは入力のまま保つ。

```
mod,func1,func1単体テスト,3,2
#COMMENT,@enable,@mode,@input,gb_result.data,gb_result.ret_code
;,自由なコメント
,1,1,10,100,1
```

- 1 行目: `mod`、対象関数名、題名、入力数、出力数。それより右のセルはそのまま保つ。
- 2 行目: `#COMMENT` に続けて入力変数、出力変数の順。
- データ行: 1 列目が `;` で始まる行（`;$L$`、`;$D$`、`;$C$` を含む）は実行せずそのまま出力へ写す。
- 値: 10 進、`0x` 16 進、`0b` 2 進、負数（`-0x10` も可）、先頭の `+`、浮動小数（`1.5`、`1e3`）、`'文字列'`、`|` 区切り。
  10 進の `007` は 7（値のセルでは 8 進と読まない）。整数の末尾の `u`/`l` は読み飛ばす。
  `nan`・`inf`・16 進の浮動小数・`12abc` や `0x`・`1e`・`--5` のような途中までしか数でないもの・空白だけは読めない（入力ならエラー）。
- 値が大きすぎて別の値にならないようにする（入力なら終了コード 2 のエラー、期待値なら下記と同じく不一致）。
  - 64 ビットを超える整数（`18446744073709551616`、`-0x8000000000000001` より小さい負数）。飽和した値（-1 と同じビット列）や
    折り返した値にしない。
  - `INT64_MAX` を超える 10 進・2 進（`18446744073709551615` など）は 16 進と同じく 64 ビットの符号なしとして扱う。
    64 ビットの変数には書けるが、8 ビットの変数には収まらない（-1 として 255 にしない）。
  - double であふれる浮動小数（`1e400`）や、0 でないのに 0 になるほど小さいもの（`1e-400`）。float の変数では
    float であふれる値（`1e39`）も収まらない（inf にしない）。
- 入力の空セルは「設定しない」（前の値を保つ）。出力の空セルは期待値なし（`NO Check`）。
- 空文字列 `''` は空セルとは別の値。入力なら終端の 0 だけを書き（前の文字列を消す）、期待値なら先頭の要素が 0
  （空文字列）かを比べる。空でない `'文字列'` の期待値は書いた文字の数だけ比べる（終端は比べない）。
- 期待値は入力と同じ規則で解釈する（負の値を符号なしの型に書く、16 進、`1.0` のような整数値の小数、ビットフィールド、
  enum、bool、`|` 区切りの各要素）。例えば uint8 の入力に `-1` を書くと 255 になるので、期待値の `-1` も 255 と比べる。
  入力ならエラーになる値（対象のビット幅に収まらない値、整数の型への `0.5` など）は、下位ビットだけで比べずに不一致
  （`NG`、結果セルは `実測?(期待)`）にする。期待値の書き間違いで他の行を止めないよう、テスト全体のエラーにはしない。
- 1 行 = 対象関数 1 回の呼び出し。行をまたいで変数は保持される。
- 1 つのファイルに `mod` 行が複数あれば、それぞれを別のテストとして順に実行する。

### 文字コードと行の識別

WinAMS がどこまで表記揺れを許すかは分からないので、`mod` 行・`#COMMENT` 行を見落としてブロックが黙って
実行されない（0 件で成功扱いになる）ことがないよう、次のどちらかにする: 寛容に受け付ける、または分かるエラー・警告にする。
`sim gui` の `/api/load-csv` も同じ規則で読む（エラーなら 400）。

| ケース | 扱い |
|---|---|
| 先頭の UTF-8 BOM（EF BB BF） | 受け付ける。行の識別では読み飛ばし、結果 CSV には BOM を含めて元のバイト列のまま写す（結果を読み直しても同じ） |
| 先頭の UTF-16 BOM（FF FE / FE FF） | エラー（終了コード 2）「UTF-16 の CSV には対応していません」。結果 CSV は書かない |
| NUL バイト（0x00）を含む行 | エラー（終了コード 2、行番号付き）。BOM のない UTF-16 もここで止まる。結果 CSV は書かない |
| `mod` 行が 1 つもない（空のファイルを含む） | エラー（終了コード 2）「mod 行がありません」。結果 CSV は書かない |
| `mod` 行の後に `#COMMENT` 行がない | エラー（終了コード 2）。`#COMMENT` 行の前に `;` 行・`#` 行・空行以外の行があってもエラー |
| ブロックはあるが実行するデータ行が 0 行（すべて `;` 行・`#` 行・空行） | 警告（標準エラー）。コメントアウトだけの雛形 CSV を壊さないよう、エラーにはせず終了コードも変えない |
| 最初の `mod` 行より前に `;` 行・空行以外の行がある | 警告（標準エラー、行番号の範囲付き）。その行は実行せずにそのまま写す |
| 大文字小文字（`MOD`、`Mod`、`#Comment`、`#comment`） | 受け付ける |
| 1 列目の前後の空白・タブ（` mod `、`\t#COMMENT\t`） | 受け付ける |
| 二重引用符で囲んだセル（`"mod"`、`" #comment "`） | 受け付ける（引用を外し、内側の空白も除く） |
| 1 列目の前後の全角空白（UTF-8 の E3 80 80、Shift_JIS の 81 40） | 受け付ける（Shift_JIS の全角空白は 2 バイト文字の 2 バイト目と区別できないので、行頭側だけ） |
| 末尾の余分なカンマ（`mod,f,t,2,1,,,`、`#COMMENT,a,b,,`） | 受け付ける。`mod` 行の右のセルはそのまま保つ |
| CR だけの改行（古い Mac 形式）、改行のない最終行 | 受け付ける。改行コードは入力のまま保つ |

`;` 行・`#` 行・空行の判定も同じく 1 列目の前後の空白（全角空白を含む）と引用を除いてから行う。
警告は `警告: ファイル:行: ...`、エラーは `エラー: ファイル:行: ...` の形で標準エラーに出す。
複数のファイルを渡したときは、エラーのファイルがあってもほかのファイルの実行を続け、最後の終了コードに反映する
（エラーが 1 つでもあれば 2、なければ NG があれば 1、どちらもなければ 0。警告は終了コードを変えない）。

結果 CSV は入力と同名で出力フォルダに作る。出力先が入力のファイル（同じ実行で渡したどの入力でも）と同じなら、
書かずにエラー（終了コード 2）にする。同じかどうかはパスの文字列ではなくファイルそのもの（POSIX は st_dev/st_ino、
Windows はボリュームシリアルとファイルインデックス）で判定するので、`./`・`..`・相対と絶対・リンク・大文字小文字の
違いがあっても入力を上書きしない。

- 入力セルはそのまま（元のバイト列を変えない）。出力セルは実測値。期待値と違えば `実測?(期待)`。出力セルは組み立てた
  セル全体を CSV として書く（`,`・`"`・前後の空白を含めば `"..."` で囲み、`"` は二重にする）。期待値の文字列は読み込むときに
  引用を外すので、そのまま `?(...)` に足すと `'A,B'` のような期待値で列が割れる。
- 出力列の右に判定（`OK` / `NG` / `NO Check`）と実行時間（`0.0003ms`）。実行時間は対象関数の実行クロック数を
  `cpu_hz`（既定 32000000）で割ったもの（モックでは実時間）。
- 呼び出しが暴走・未定義命令などで失敗した行は、出力セルを入力のまま写して `NG` にし、次の行へ進む。
- 結果 CSV を入力として読み直せる（判定・時間の列は無視し、`実測?(期待)` は既定で期待側を採る。
  `--expect-actual` で実測側を採る）。WinAMS の結果を期待値にして、このシミュレータとの差を調べる用途。
- 整数は 10 進で出す。期待値セルが `0x` 表記ならその列は同じ桁数の 16 進で出す。

終了コード: NG が 1 つでもあれば 1、実行できないエラーは 2。標準出力に件数（総数、OK、NG、NO Check）を出す。
本物のバックエンドでは最後に、実行命令数（スタートアップを除く）、呼び出し回数、対象関数の所要時間、命令/秒を出す。

対象関数の呼び出しは、整数/ポインタ引数 8 個までと、戻り値 void/整数/ポインタ/float/double に対応する。
浮動小数や構造体の値渡し引数は対応外とし、分かるエラーにする。

## 4. CPU コアと周辺機能

- 対応コア: RL78-S1 / S2 / S3。全命令、レジスタバンク、ES/CS、ミラー領域、S2 の乗除算器・積和演算器 SFR、S3 の乗除積和命令。
- 周辺機能（タイマ、シリアル、A/D など）は模擬しない。SFR は読み書きできるただのメモリとして扱う（WinAMS と同じ）。
  割り込みは、テストドライバがハンドラ関数を直接呼ぶ前提。
- `HALT` / `STOP` は読み飛ばす（設定で停止にもできる）。未定義命令、暴走（命令数の上限超過）、
  対象関数から戻らない場合は、PC と逆アセンブル結果を添えたエラーにして、その行を NG とする。
- 結果 CSV の実行時間列は、実行したクロック数と `sim.cfg` の CPU クロック周波数から換算する。

## 4.1 速度

CPU コアは 1 億命令/秒以上を目標にする。`sim run` は終了時に、実行した命令数、所要時間、命令/秒を表示する。

## 5. GUI モード

`sim gui` は 127.0.0.1 だけで待ち受ける HTTP サーバを立て、既定のブラウザを開く。
1 行 = 1 周期の対象関数（既定はテストドライバの関数。`--func` または画面で指定）を、周期タイマで呼び続ける。

### HTTP API

すべて JSON。文字コードは UTF-8。double であふれる数（`1e400`）や 0 になるほど小さい数は壊れた JSON として 400。
`Content-Length` が 10 進の数字でなければ 400。

| メソッド パス | 内容 |
|---|---|
| `GET /` | `sim_gui.html` を返す |
| `GET /api/info` | `{"version","periodMs","func","functions":[名前...],"state":{...}}` |
| `GET /api/symbols?q=文字列&limit=200` | 名前の部分一致検索（`limit` は 1 以上の整数で、5000 を超える指定は 5000 件まで。数値でなければ 400）。`[{"name","type","size","kind":"int|uint|float|ptr|struct|array","writable":bool,"members":[...子の名前]}]`。`members` は子の**完全名**（`g_cmd.mode`、`arr[2]`。配列は最大 256 要素、匿名メンバは親の名前に続けて展開） |
| `POST /api/control` | `{"cmd":"run"|"pause"|"step"|"reset","steps":N,"speed":倍率,"periodMs":周期,"func":"関数名"}`。不明な `cmd` や対象にできない関数（浮動小数・構造体の引数など）は 400 で、そのときは関数・引数・速度・周期を何も変えない。`steps` は 1 以上の整数、`speed` は 0（最速）か 0.1〜100、`periodMs` は 0.01〜60000 で、範囲外・数値でない値は丸めずに 400（何も変えない）。`func` で対象関数が実際に変わったときは、`cmd` の前に `reset` と同じことをする（下記）。応答は `state` と同じ形で、解決し直せずに外した固定・監視を `dropped` に載せる（下記「関数を変えたときの固定と監視」） |
| `POST /api/watch` | `{"names":["変数",...]}` 監視する変数の一覧を置き換える。解決できなかった名前は `{"errors":[{"name","message"}]}` で返す |
| `POST /api/write` | `{"name":"変数","value":数値または文字列,"hold":bool}` 次の周期の開始時に書き込む（止まっているときもすぐには書かない）。`hold` が偽なら単発（反映待ち。同じ名前に書き直すと置き換わる）、真なら毎周期書き続ける（入力の固定。同じ名前の反映待ちは捨てる）。`{"name","release":true}` で固定を解除し、その名前の反映待ちも捨てる。`value` の整数は書いた表記のまま読む（2^53 を超える整数を double に丸めない）。名前が解決できない・書き込めない、型に収まらない、`$` の値が 0 以上の整数でない、要素数を超える、改行を含む、などの値はこの時点で 400（ポインタの先のようにその時のメモリで決まるものは、書くときに `state` の `error` になる） |
| `GET /api/stream` | Server-Sent Events。下記 |
| `POST /api/load-csv` | 本文にテスト CSV。読み込んで先頭から再生する（入力列を毎周期書き込み、監視に全列を加える）。`{"rows":N,"names":[...]}`。関数や入力列が使えなければ 400 で、以前の関数・引数・再生をそのまま残す |
| `GET /api/export.csv` | 開始（またはリセット）からの記録を WinAMS 形式の CSV で返す（固定・書き込みした変数が入力列、監視変数が出力列）。下記「記録と CSV 保存」 |

### ストリーム（SSE）

- `event: hello` — `{"periodMs","func","names":[監視名...]}`。接続時と監視一覧が変わったとき。
- `event: samples` — `{"step0":先頭のステップ番号,"names":[...],"rows":[[値,...],...]}`。約 50ms ごとにまとめて送る。
  値は数値、読めなければ `null`。
- `event: state` — `{"running":bool,"step":現在のステップ,"speed":倍率,"holds":[{"name","value"}],"overrun":bool,
  "periodMs","func","playback":bool,"error":文字列,"dropped":[{"name","kind":"hold"|"watch","message"}],
  "pending":[{"name","value"}]}`。変化時と 1 秒ごと。`/api/control` の応答と `/api/info` の `state` も同じ形。
  `dropped` は直近の `/api/control`・`/api/load-csv` で外した固定・監視（次の `/api/control`・`/api/load-csv` で空に戻る）。
  `pending` は次の周期の開始時に書く単発書き込み（`value` は書いたセルの文字列。`"7"`、`"'A'"`、`"0x78"` など）。
  同じ名前に書き直すと置き換わり、ステップでの反映・リセット・関数の変更・その名前の固定と解除で消える。
- `event: values` — `{"step":現在のステップ,"names":[監視名...],"values":[値,...]}`。監視変数のメモリの現在値（ステップは進めない。
  反映待ちの値は混ぜない）。接続時、監視一覧の変更時、リセットの後に送る（一時停止中でも変数モニタに値を出すため）。
  停止中に書き込んでも次のステップまでメモリは変わらないので、値は変わらない。
  約 50ms ごとの送信の間に何度か変われば最後の値だけを送る。読めなければ `null`。

`reset` は「初期状態」（スタートアップ完了時点の CPU とメモリ）に戻す。ステップを 0 にし、記録と未消化の単発書き込みを捨てる
（固定は残す）。

### 関数を変えたときの固定と監視

固定（`hold`）と監視の名前は、対象関数が変わるたびに（`/api/control` の `func`、`/api/load-csv` の `mod` 行）新しい関数で
解決し直す（`reset` のときも同じ手順を通す）。`@引数` は引数の番号で覚えているので、前の解決結果を使い続けると
別の引数を読み書きしてしまう（`eng_judge_gear` の `@rpm` の固定が `mul16` の `@a` を上書きする）。

- 解決し直せない固定・監視は外す。新しい関数にない `@引数`、前の関数の戻り値 `前の関数@@` など。
  固定は書き込めなくなったときも外す。関数の変更そのものは受け付ける。
- 外したものは `state`（`/api/control` の応答と SSE の `event: state`）の `dropped` に
  `{"name","kind":"hold"|"watch","message":理由}` で載せる。`holds` と `event: hello` の `names` は外した後の内容になる。
- 外した固定は書かないので記録の入力列にも出ず、監視は出力列に出ない。保存した CSV に新しい関数にない列は残らず、
  `sim run` でそのまま再実行できる。
- `/api/control` で関数を変えたときは、読み込み済みの CSV の再生もやめる（入力列は前の関数で解決しているため）。

### 記録と CSV 保存

保存した CSV を `sim run` で（`--expect-actual` なしで）実行し直すと、全行 OK になるように記録する。

- 入力列には、その周期に書いた**セルの元の文字列**を残す（`'XYZ'`、`1|2|3`、`0x78` など。数値に直して丸めない）。
  ','・'"'・前後の空白を含む値は `"..."` で囲む。
- **書き込み（`/api/write` の単発・固定、CSV の再生）は、止まっているときも含めて、すぐにはメモリへ反映しない。
  常に次の周期（ステップ）の開始時に、入力列の順に、列ごとに最後の 1 個だけを書いて記録する。** これは `sim run` が
  CSV の 1 行を処理する規則（入力列を左から順に 1 回ずつ書いてから関数を呼ぶ）と同じなので、記録と再実行が
  構造的に一致する。止まっている間に書いた値は `state` の `pending` に出し、メモリ（`values`）は次のステップまで変わらない。
- 入力列の順は列番号の昇順。受け付けた順や種類の順に書くと、同じメモリを指す入力（`P1` の固定と `P1_bit.no0` の
  単発書き込みなど）で結果が再実行と変わる。
- 同じ周期に同じ変数（同じ名前）へ何度か書いたときは、最後の 1 個だけを書いて記録する。単発どうしは後から書いたものが
  前のものを置き換え（反映待ちは名前ごとに 1 個）、種類が違えば単発 → 固定 → 再生の順で後のものを採る（固定した名前への
  単発書き込みは、その周期も固定の値になる）。前のものも書くと、`$` の確保が二重になる、長い文字列の残りが残るなど、
  1 列 1 セルの CSV の再実行と合わない。空の値（空セル）は書かず、記録もしない（空文字列 `''` は書く）。
- 固定を外す（`release`）と、その名前の反映待ちも捨てる。次の周期までに固定して外した値は書かれず、記録にも残らない。
- 入力列の番号は、記録が空になったとき（リセット・関数の変更・CSV の読み込み）に組み直す。読み込んだ CSV を再生して
  いるなら、その CSV の入力列をその順で先頭に並べ、続けていま残っている固定（CSV にない名前）を並べる。
  その後に初めて書き込んだ名前は後ろに足す。以前に書いた順の番号を使い続けると、再生が CSV の入力列と違う順に
  書いてしまい、`sim run` の結果と変わる（`P1`、`P1_bit.no0` の順に書いた後で `P1_bit.no0,P1` の CSV を再生するなど）。
  出力列は監視の順で組み直す。
- 出力列は `sim run` が結果 CSV に書くのと同じ表記で残す（配列や `&arr` は全要素、文字なら `'...'`）。
  SSE の `samples` と `values` はこれまでどおり数値（配列なら先頭の要素）か `null`。
- **対象関数を変えると、ターゲットをリセットして記録を区切る**（それまでの記録は消え、ステップは 0 から数え直す）。
  `sim run` は `mod` ブロックの初めにリセットするので、前の関数の続きの状態から記録を始めると、保存した CSV の再実行と合わない。
  関数ごとに別の `mod` ブロックとして出す方法もあるが、その場合も各ブロックの初めの状態を揃えるにはリセットが要るため、
  関数を変えたらリセットする方を採った。保存する CSV は常に `mod,<今の関数>` の 1 ブロック。
- 記録は最大 `--record-max`（既定 20 万）周期。超えると古い周期から捨てるので、その場合の保存結果は途中の状態から始まり、
  再実行と合わないことがある。
実時間に追いつけないときは `overrun` を立て、周期を詰めずに続行する。`speed` は 0.1〜100 と「最速」(0)。

### 画面

SignalViewer2（`https://github.com/hironoa/SignalViewer2`）のソースを `gui/` に取り込み、次を加える。

- ストアに追記用の `appendSamples`。ライブ中は直近 N 点（既定 2000）の窓で描く。停止中は全区間を従来どおり操作できる。
- 接続バー: 実行/一時停止/ステップ/リセット、速度、周期、現在ステップ、オーバーラン表示。
- 入力パネル: 変数を検索して追加し、数値入力・スライダ・トグル（0/1）・押している間だけ 1 のボタンで値を変える。固定の ON/OFF。
- 変数モニタ: 監視変数の現在値を 10 進/16 進で一覧表示。追加・削除。波形に出すかどうかを切り替え。
- 記録の CSV 保存、テスト CSV の読み込みと再生。
- サーバなしで開いた場合は、従来の SignalViewer2（ファイルを読む Viewer）としてそのまま動く。
