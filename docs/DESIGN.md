# 設計書

RL78 向け組み込みソフトを、CS+ / CC-RL でビルドしたロードモジュール（`.abs`）のまま PC 上で実行するシミュレータ。
WinAMS と同じ命令シミュレータ方式だが、CPU コアを速度優先で自作し、テスト CSV の実行と結果 CSV の出力、
リアルタイム GUI を備える。

機械語をそのまま解釈実行するので、`int` 16 ビット、ポインタ幅、構造体の配置、SFR のアドレス、
アセンブラで書かれた処理は、すべて実機と同じに動く。対象ソフトの再ビルドやスタブの追加は要らない。
WinAMS 用にビルドした `.abs`（テストドライバとスタブ入り）をそのまま使う。

## 1. 全体構成

```
rl78/           RL78 CPU コア（命令デコードと実行、1MB メモリ、ミラー領域、乗除算器）。単体でテストできる
runtime/        シミュレータ本体（C11、外部依存なし）
  src/            CSV の読み書き、変数名式、HTTP/SSE サーバ、周期実行ループ、sim.cfg、バックエンド抽象（include/sim_backend.h）
  backends/rl78/  本物のバックエンド: .abs（ELF/DWARF）と .map の読み込み、CC-RL の呼び出し規約での関数呼び出し、
                  スタブ、CPU コアとの接続
  backends/mock/  共通部分のテスト用のモック
build.bat       Windows 用ビルドスクリプト（clang / MinGW-w64 gcc を直接呼ぶ。CMake も Python も使わない）
build.sh        macOS / Linux 用の同じもの
example/        sim.cfg の見本など
gui/            リアルタイム GUI（SignalViewer2 を取り込んだ React アプリ）。単一 HTML にビルドしてコミットする
tests/          自動テスト（run_tests.sh / run_tests.bat）。rl78/ に本物のバックエンドのテスト、
                fixtures/renesas/ にルネサス公式サンプルの .abs（BSD-3）、tools/mkabs.c にテスト用 .abs の生成器
docs/
```

ビルドすると実行ファイル `sim`（Windows では `sim.exe`）と、その隣に `sim_gui.html` ができる。

- バッチ: `sim run --abs <ロードモジュール.abs> [--cfg sim.cfg] <テスト.csv>... [-o 出力フォルダ]`
- GUI: `sim gui --abs <ロードモジュール.abs> [--port 8765] [--period-ms 5] [--speed 1] [--record-max 200000]`。
  数値は文字列全体を読み、`--port` は 1〜65535、`--period-ms` は 0.01〜60000、`--speed` は 0（最速）か 0.1〜100、
  `--record-max` は 1 以上の整数。範囲外や `8765x` のような末尾のごみは終了コード 2 のエラー。
- 一覧: `sim list --abs <X.abs> [--where] [文字列]`（変数と関数、アドレス、型、定義ファイル。`--where` でヘッダ定義の行番号）
- 概要: `sim info --abs <X.abs>`（ELF/DWARF の概要、コア種別、ミラー・RAM・スタック・ヒープ、セクション、
  スタートアップの命令数、リンクマップとの照合）
- 共通オプション `--verbose`（`-v`）で読み込み中の警告（知らない DWARF 属性など）を表示する。
- 設定ファイル `sim.cfg`（KEY=VALUE、`#` 以降はコメント）。`--cfg` の指定を優先し、指定がなければロードモジュール（`.abs` / `.lmf`）と同じフォルダ、
  開けなければ実行したフォルダの `sim.cfg` の順に探し、最初に開けたものだけを読む。探索は `sim_cfg_locate` にまとめる。
  `sim info` の「設定ファイル:」行で読まれたファイルが分かる。`abs =` を書けば `--abs` を省ける。キーの一覧と説明は `example/sim.cfg`。
  数値の設定は 10 進、`0x` 16 進、末尾 `H` の 16 進（`0FFF0H`）で書き、値全体を読む。符号付き（`-1`）、単位付き（`32MHz`）、
  0 で始まる 10 進（`010`。8 進と紛れる）、64 ビットや各設定の範囲（アドレスは 0x00000〜0xFFFFF、`ram_fill` は 1 バイト、
  `sentinel`・`call_sp` は偶数）を超える値は、既定値や自動の値に置き換えたり下位ビットに切り詰めたりせず、
  `sim.cfg: KEY = 値 を読めません` のエラー（終了コード 2）にする。`cpu_hz` は正の 10 進の数（指数可）。
- ビルドは `build.sh` / `build.bat`（既定は本物のバックエンド。`mock` を付けるとモック版）。

シミュレータ自体のビルドには、Windows の配布物は MinGW-w64 gcc（`set CC=gcc`）、macOS は Apple clang を使う。
Windows は clang でもビルドでき、`CC` 未設定なら従来どおり clang を使う（LLVM、MSVC の C ランタイムと Windows SDK が要る）。
GUI はビルド済みの単一 HTML をコミットしておく（作り直すときだけ Node が要る）。

## 2. 実行モデルと変数名の解決

WinAMS と同じ流れで動かす。

1. `.abs` を読み込み（PT_LOAD の物理アドレスへ。RAM はその前に `ram_fill` の値で埋める）、リセットベクタから
   スタートアップルーチンを実行する。
2. 初期設定終了アドレス（既定 `main` の先頭、`init_end` で変更可）に達したら止める。この時点の CPU とメモリを
   「初期状態」として控える（リセット用。mod ブロックごと、GUI の reset で戻す）。
   上限（`startup_max_insns`、既定 2 億命令）までに着かなければ、PC と逆アセンブルを添えたエラーで終わる。
3. CSV の 1 行ごとに、入力変数を書き込み、対象関数を CC-RL の呼び出し規約で呼び出し、戻ってきたら出力変数を読む。

### 関数の呼び出し（CC-RL の呼び出し規約）

- SP は初期設定終了時の SP（`call_sp` で変更可）から積む。AX/BC/DE/HL は 0 から始める。
- 引数は左から順に空いている最優先のレジスタへ（1 バイト: A, X, C, B, E, D、2 バイト: AX, BC, DE、
  far ポインタ: A-DE, X-DE, C-DE, B-DE, X-BC（上位レジスタの下位 4 ビットがページ）、4 バイト: BC-AX, DE-BC）。
  入らなければスタック（左ほど低いアドレス、2 バイト境界）。8 バイト型と 5 バイト以上はスタック。
- 戻り値: 1 バイト A、2 バイト AX、3 バイト C-AX、far ポインタ A-DE、4 バイト（float を含む）BC-AX。
  5 バイト以上（long long など）は呼び出し側の領域への near ポインタを第 1 引数として渡し、そこから読む。
- 戻り番地（4 バイト）には番兵アドレス（既定 0xEFFF0、プログラムと重ならない場所を自動で選ぶ）を積み、
  そこに置いたブレークポイントで戻りを検出する。4 バイト目には PSW を入れるので、RETI で終わる割り込み関数も呼べる。
- 1 回の呼び出しは `max_insns`（既定 1 億命令）が上限。超えたとき、未定義命令、`halt = stop` で HALT に当たったときは、
  PC と逆アセンブル（またはバイト列）を添えたエラーにし、その行を NG にして次の行へ進む。
- ポインタの値はアドレスに換算して参照する: near データポインタ（2 バイト）は 0xF0000 + 値、far（4 バイト）は下位 20 ビット。
  `$ptr` のヒープは、ELF のセクションとスタック（`__STACK_ADDR_START/END`）が使っていない RAM から選ぶ
  （なければスタックの底から最大 2KB。`heap` で指定可）。確保は 2 バイト境界に揃え、ヒープの終端（排他的。奇数でもよい）を
  越える確保は「ヒープが足りません」のエラーにする。`heap` / `ram` の範囲が RL78 のアドレス空間（0x00000〜0xFFFFF）に
  収まらなければ、読めない設定として警告し、`heap` は自動の選び方に戻す。
- アドレス直接指定の書き込みは、0xFFFF8〜0xFFFFF（SP/PSW/CS/ES/PMC）だけ CPU のレジスタとして書き、
  ほかはメモリへそのまま書く（ROM も書ける。SFR の副作用は起こさない）。

### デバッグ情報の読み取り

- DWARF 2〜4（CC-RL は 2 と 3 が混在）。5 は見出しだけ読み、文字列の一部（strx）は読めない。
- 型: 基本型、typedef（名前を残す）、const（型に保持し、メンバ・配列要素・指す先の書き込み可否にも適用）、volatile（剥がす）、
  ポインタ（大きさは DW_AT_byte_size、なければ DW_AT_address_class。CC-RL の near データポインタは 4 → 2 バイト。
  知らない値は 4 バイトとして警告し、`addr_class.N = 2|4` で変えられる）、配列（多次元、DW_AT_count / upper_bound）、
  構造体・共用体（匿名メンバを含む）、enum（負の値がなければ符号なし）。
- ビットフィールドは構造体先頭からのビット位置（LSB = 0）に換算する。DWARF4 の DW_AT_data_bit_offset はそのまま、
  DWARF2/3 の DW_AT_bit_offset は記憶単位（DW_AT_byte_size）の MSB から数える標準どおりに
  `単位の先頭 * 8 + 単位のビット数 - bit_offset - bit_size`。CC-RL が非標準なら `bitfield_order = lsb`。
- 変数: DW_AT_location が DW_OP_addr（＋ DW_OP_plus_uconst）のもの。関数内（lexical_block の中を含む）なら関数内 static。
  ロケーションリストの局所変数は対象外。別の CU に同じ変数（extern 宣言）があれば 1 つにまとめる。
- 関数: low_pc のある subprogram。CC-RL の static 関数名に付く `(void)` などは除く。アセンブラの外部ラベル
  （DW_TAG_label）と、.symtab の FUNC / 実行セクションのグローバルラベルも引数なしの関数として加える。
- 知らない属性・タグは読み飛ばし、`--verbose` で警告する。大きさの分からない form があればその CU だけ飛ばす。
- DWARF にない変数は .symtab（`_name`、ファイル内 static は `_name@N`、関数内 static は `_name@N@func`）と
  .map の Symbol List から、型なしで加える（`name:バイト数` で使う。ファイル名は .map の FILE= から）。
  .map は ELF のセクションと照合して `sim info` に結果を出す。

変数と関数は `.abs` のデバッグ情報（DWARF）から解決する。DWARF の読み取りは自前で行い、外部ツールを使わない。

- 対象: グローバル変数、ファイル内 static、関数内 static、関数（アドレス、引数の名前と型、戻り値の型）。
- 型: 基本型（サイズ、符号、浮動小数か）、near/far ポインタ、配列、構造体/共用体（メンバのオフセット、
  ビットフィールド）、enum。typedefは名前を残す写し、constは `sim_type.is_const` に保持、volatileは剥がす。
- デバッグ情報がない場合の補助として、リンクマップ（`.map`）からシンボルのアドレスを読む（型は CSV 側で `名前:バイト数` と指定）。

### スタブへの置換

WinAMS の「置換」と同じく、元の関数が呼ばれたらスタブへ飛ばす。対象ソフトは書き換えない。
置換する関数は `sim.cfg` に書く（CSV 実行でも GUI 実行でも同じ設定が効く）。

```
stub = func3_sub_read_io:AMSTB_func3_sub_read_io
stub = read_adc:AMSTB_read_adc
stub_auto = off     # on にすると、AMSTB_<関数名> がある関数をすべて置換する
```

### CPU コア種別

品種が分からなくても動くよう、既定は `core = auto`（S3 の命令と S2 の乗除算器 SFR の両方を有効にした上位互換。
CPU コアに上位互換モードはないので、S3 を選んで乗除算器 SFR（`mdu`）を有効にしている。S3 の MACR（FFFF0H〜）と
乗除算器の MDAL/MDAH は同じアドレスなので、MACH/MACHU の結果を書くと MDB が掛け算の結果で上書きされる）。
`sim.cfg` の `core = S1|S2|S3` で固定できる（S2 は乗除算器あり、S1/S3 はなし。`mdu = on|off` で変更可）。
ミラー領域は PMC.MAA に従う。範囲は既定で `.const` の置き場所（その手前はデータフラッシュとみなす）から RAM の先頭まで
（S1 は F8000H〜）。`mirror = 開始-終了[@写し元]` か `off` で変えられる。

名前の書式は WinAMS に合わせる。

| 書式 | 意味 |
|---|---|
| `name` | グローバル変数。見つからなければ一意なファイル内 static |
| `file.c/name` | ファイル内 static |
| `file.c/func@name`、`func@name` | 関数内 static。引数名と一致すれば引数 |
| `@name` | テスト対象関数の引数 |
| `func@@` | テスト対象関数の戻り値 |
| `a.b`、`a[2]`、`p[0].m`、`a->b` | メンバ、配列要素、ポインタの先 |
| `$ptr` | 値の個数だけ実体を確保してポインタに設定。0 なら NULL |
| `&arr`、`*ptr` | 1 セルに `'文字列'` または `1|2|3` で複数要素（個数に上限はなく、書き込みも期待値の比較も全要素を対象にする） |
| `0xFFF01`、`0xFFF01:2` | アドレス直接指定（`:バイト数`、既定 1）。SFR などデバッグ情報にない場所用 |
| `name:2` | 型を「2 バイトの符号なし整数」として読み書きする（デバッグ情報がなく型の分からないシンボル用） |

`パス/` の部分はファイル名の末尾一致で照合する。

添字（`a[2]`）とアドレス直接指定（`0xFFF01`）の数は、10 進か `0x` の 16 進で書く。`010` のように 0 で始まる 10 進は、
C の 8 進（8）と 10 進（10）のどちらの意味か決められないのでエラーにする（以前は 8 進として読んでいた）。
64 ビットを超える添字・アドレス、要素の大きさを掛けると 64 ビットを超える添字もエラー（飽和や桁あふれで別の場所にしない）。

## 3. テスト CSV と結果 CSV

WinAMS チュートリアルの記述に合わせる。バイト列をそのまま扱い、文字コード（Shift_JIS/UTF-8）と改行コードは入力のまま保つ。

```
mod,func1,func1単体テスト,3,2
#COMMENT,@enable,@mode,@input,gb_result.data,gb_result.ret_code
;,自由なコメント
,1,1,10,100,1
```

- 1 行目: `mod`、対象関数名、題名、入力数、出力数。それより右のセルはそのまま保つ。
- 2 行目: `#COMMENT` に続けて入力変数、出力変数の順。
- データ行: 1 列目が `;` で始まる行（`;$L$`、`;$D$`、`;$C$` を含む）は実行せずそのまま出力へ写す。
  1 列目が `#` で始まる行も同じ（`#COMMENT` 行の後の `#` 行）。
- 1 列目はコメント欄（通常は空）。`;`・`#` で始まらず `mod` でもない文字列が書いてある行は、ほかのセルがすべて空でも
  **データ行として実行する**（入力は何も書かず、出力は期待値なしなので `NO Check`）。1 列目はそのまま結果 CSV に写す。
- 空行（実行せずそのまま写す）は、**1 列目も含めて全セルが空（空白だけを含む）の行**に限る。Excel が末尾に付ける
  `,,,,` などがこれに当たる。`sim gui` の保存では、入出力のセルがすべて空になる周期の行の 1 列目に `step N` を入れて、
  空行として読み飛ばされないようにしている（5 節「記録と CSV 保存」）。
- 値: 10 進、`0x` 16 進、`0b` 2 進、負数（`-0x10` も可）、先頭の `+`、浮動小数（`1.5`、`1e3`）、`'文字列'`、`|` 区切り。
  10 進の `007` は 7（値のセルでは 8 進と読まない）。整数の末尾の `u`/`l` は読み飛ばす。
  `nan`・`inf`・16 進の浮動小数・`12abc` や `0x`・`1e`・`--5` のような途中までしか数でないもの・空白だけは読めない（入力ならエラー）。
- 値が大きすぎて別の値にならないようにする（入力なら終了コード 2 のエラー、期待値なら下記と同じく不一致）。
  - 64 ビットを超える整数（`18446744073709551616`、`-0x8000000000000001` より小さい負数）。飽和した値（-1 と同じビット列）や
    折り返した値にしない。
  - `INT64_MAX` を超える 10 進・2 進（`18446744073709551615` など）は 16 進と同じく 64 ビットの符号なしとして扱う。
    64 ビットの変数には書けるが、8 ビットの変数には収まらない（-1 として 255 にしない）。
  - double であふれる浮動小数（`1e400`）や、0 でないのに 0 になるほど小さいもの（`1e-400`）。float の変数では
    float であふれる値（`1e39`）も収まらない（inf にしない）。
- 入力の空セルは「設定しない」（前の値を保つ）。出力の空セルは期待値なし（`NO Check`）。
- 空文字列 `''` は空セルとは別の値。入力なら終端の 0 だけを書き（前の文字列を消す）、期待値なら先頭の要素が 0
  （空文字列）かを比べる。空でない `'文字列'` の期待値は書いた文字の数だけ比べる（終端は比べない）。
- 期待値は入力と同じ規則で解釈する（負の値を符号なしの型に書く、16 進、`1.0` のような整数値の小数、ビットフィールド、
  enum、bool、`|` 区切りの各要素）。例えば uint8 の入力に `-1` を書くと 255 になるので、期待値の `-1` も 255 と比べる。
  入力ならエラーになる値（対象のビット幅に収まらない値、整数の型への `0.5` など）は、下位ビットだけで比べずに不一致
  （`NG`、結果セルは `実測?(期待)`）にする。期待値の書き間違いで他の行を止めないよう、テスト全体のエラーにはしない。
- 1 行 = 対象関数 1 回の呼び出し。行をまたいで変数は保持される。
- 1 つのファイルに `mod` 行が複数あれば、それぞれを別のテストとして順に実行する。

### 文字コードと行の識別

WinAMS がどこまで表記揺れを許すかは分からないので、`mod` 行・`#COMMENT` 行を見落としてブロックが黙って
実行されない（0 件で成功扱いになる）ことがないよう、次のどちらかにする: 寛容に受け付ける、または分かるエラー・警告にする。
`sim gui` の `/api/load-csv` も同じ規則で読む（エラーなら 400）。

| ケース | 扱い |
|---|---|
| 先頭の UTF-8 BOM（EF BB BF） | 受け付ける。行の識別では読み飛ばし、結果 CSV には BOM を含めて元のバイト列のまま写す（結果を読み直しても同じ） |
| 先頭の UTF-16 BOM（FF FE / FE FF） | エラー（終了コード 2）「UTF-16 の CSV には対応していません」。結果 CSV は書かない |
| NUL バイト（0x00）を含む行 | エラー（終了コード 2、行番号付き）。BOM のない UTF-16 もここで止まる。結果 CSV は書かない |
| `mod` 行が 1 つもない（空のファイルを含む） | エラー（終了コード 2）「mod 行がありません」。結果 CSV は書かない |
| `mod` 行の後に `#COMMENT` 行がない | エラー（終了コード 2）。`#COMMENT` 行の前に `;` 行・`#` 行・空行以外の行があってもエラー |
| ブロックはあるが実行するデータ行が 0 行（すべて `;` 行・`#` 行・空行） | 警告（標準エラー）。コメントアウトだけの雛形 CSV を壊さないよう、エラーにはせず終了コードも変えない |
| 最初の `mod` 行より前に `;` 行・空行以外の行がある | 警告（標準エラー、行番号の範囲付き）。その行は実行せずにそのまま写す |
| 大文字小文字（`MOD`、`Mod`、`#Comment`、`#comment`） | 受け付ける |
| 1 列目の前後の空白・タブ（` mod `、`\t#COMMENT\t`） | 受け付ける |
| 二重引用符で囲んだセル（`"mod"`、`" #comment "`） | 受け付ける（引用を外し、内側の空白も除く） |
| 1 列目の前後の全角空白（UTF-8 の E3 80 80、Shift_JIS の 81 40） | 受け付ける（Shift_JIS の全角空白は 2 バイト文字の 2 バイト目と区別できないので、行頭側だけ） |
| 末尾の余分なカンマ（`mod,f,t,2,1,,,`、`#COMMENT,a,b,,`） | 受け付ける。`mod` 行の右のセルはそのまま保つ |
| CR だけの改行（古い Mac 形式）、改行のない最終行 | 受け付ける。改行コードは入力のまま保つ |

`;` 行・`#` 行・空行の判定も同じく 1 列目の前後の空白（全角空白を含む）と引用を除いてから行う。
警告は `警告: ファイル:行: ...`、エラーは `エラー: ファイル:行: ...` の形で標準エラーに出す。
複数のファイルを渡したときは、エラーのファイルがあってもほかのファイルの実行を続け、最後の終了コードに反映する
（エラーが 1 つでもあれば 2、なければ NG があれば 1、どちらもなければ 0。警告は終了コードを変えない）。

結果 CSV は入力と同名で出力フォルダに作る。すべての入力の出力パスをターゲットの初期化・実行より前に求め、
出力先同士が衝突すれば、何も実行せず、出力フォルダ・ファイルも作らず終了コード 2 にする。
ファイル名は ASCII の大文字小文字を区別しない（`Test.csv` と `test.csv`、同じ入力の重複指定も衝突）。
エラーには入力 2 つと出力先を示し、別々に実行するか出力フォルダを分けるよう案内する。
この検査を先に行い、衝突がなければ各ファイルの既存の入力保護検査を行う。
出力先が入力のファイル（同じ実行で渡したどの入力でも）と同じなら、
書かずにエラー（終了コード 2）にする。同じかどうかはパスの文字列ではなくファイルそのもの（POSIX は st_dev/st_ino、
Windows はボリュームシリアルとファイルインデックス）で判定するので、`./`・`..`・相対と絶対・リンク・大文字小文字の
違いがあっても入力を上書きしない。

- 入力セルはそのまま（元のバイト列を変えない）。出力セルは実測値。期待値と違えば `実測?(期待)`。出力セルは組み立てた
  セル全体を CSV として書く（`,`・`"`・前後の空白を含めば `"..."` で囲み、`"` は二重にする）。期待値の文字列は読み込むときに
  引用を外すので、そのまま `?(...)` に足すと `'A,B'` のような期待値で列が割れる。
- 出力列の右に判定（`OK` / `NG` / `NO Check`）と実行時間（`0.0003ms`）。実行時間は対象関数の実行クロック数を
  `cpu_hz`（既定 32000000）で割ったもの（モックでは実時間）。
- 呼び出しが暴走・未定義命令などで失敗した行は、出力セルを入力のまま写して `NG` にし、次の行へ進む。
- 結果 CSV を入力として読み直せる（判定・時間の列は無視し、`実測?(期待)` は既定で期待側を採る。
  `--expect-actual` で実測側を採る）。WinAMS の結果を期待値にして、このシミュレータとの差を調べる用途。
- 整数は 10 進で出す。期待値セルが `0x` 表記ならその列は同じ桁数の 16 進で出す。

終了コード: NG が 1 つでもあれば 1、実行できないエラーは 2。標準出力に件数（総数、OK、NG、NO Check）を出す。
本物のバックエンドでは最後に、実行命令数（スタートアップを除く）、呼び出し回数、対象関数の所要時間、命令/秒を出す。

対象関数の呼び出しは、整数/ポインタ引数 8 個までと、戻り値 void/整数/ポインタ/float/double に対応する。
浮動小数や構造体の値渡し引数は対応外とし、分かるエラーにする。

### パスの文字コード（Windows）

プログラムの中では、パスを UTF-8 で持つ。コンソールへの表示を UTF-8（`SetConsoleOutputCP`）にしているので、
`main` の `argv`（ANSI コードページ。日本語 Windows では Shift_JIS）をそのまま持つと、日本語のファイル名が表示で化ける。

- 引数は `GetCommandLineW` から取り直して UTF-8 にする（`sim_utf8_args`）。
- ファイルを開く・フォルダを作る・列挙する・同じファイルか調べるときは、直前にワイド文字へ直して W 系の API を使う
  （`sim_fopen` など）。UTF-8 として読めないパスは ANSI コードページとして解釈する。
- `sim.cfg` が UTF-8 として読めなければ、ANSI コードページから UTF-8 に直してから読む（中のパスを UTF-8 に揃える）。
- フォルダの列挙（`defines`）で得た名前も UTF-8 にする。

Windows 以外では何も変換しない。

### 初期化つき CSV（modi）

`modi` を `mod` と同じ規則（大文字小文字・空白・引用）で認識する。
最初のデータ行より前の `#Init...` と直後の初期値行を1組だけ読む。
`#COMMENT` はその組の前後どちらでもよい。初期値行の先頭セルはコメント、2列目以降は初期化変数の値。
値の解析・型の範囲・空セルは通常の入力と同じ。初期化行・値の行・modi行は結果へバイト列のまま写す。
複数の初期化見出し、初期値の余分なセル、COMMENT前の複数の値行、データ開始後の初期化行はエラー。
COMMENT後の通常データ行と初期値行の区別は、見出しの直後の1行だけを初期値とする規則による。
`mod` に初期化行があると受け付けて警告、`modi` にないと初期化せず警告する。

`sim.cfg` の `csv_init = auto | once | every`（既定auto）。`--csv-init=...` が設定より優先する。
onceはブロックの最初のデータ行の前だけ、everyは各行で、入力列より先に初期値を書く。
autoは見出しが `#InitWheneverCall`（大小文字不問）のときevery、それ以外はonce。
ブロック開始時のリセットはmodと同じ。初期化対象と入力が重なれば入力が後で書かれる。

GUIの先頭ブロック再生も同じパーサと設定を使う。初期化を先頭の独立した入力列へ展開し、
onceは1行目だけ、everyは全行に値を置く。初期化と入力の同名列も独立して記録するため、
文字列・配列を部分的に上書きする場合も保存CSVの再実行順序を維持する。
保存形式は従来どおりmod。この同名列を含む保存CSVも、GUIで再読み込みする場合は従来の重複入力列チェックで拒否されるため、
`sim run` で再実行する。入力検証が失敗した読み込みでは既存のGUI状態を変えない。
波形デコーダはmodiもブロックとして認識し、初期化見出しと次の値行を周期に数えない。

### 置換の指定（% 行）

1 列目が `%` だけの行は `%,スタブ関数,元の関数`。WinAMS が `#COMMENT` の前に書く置換（スタブ）の指定で、
`mod` / `modi` 行から最初のデータ行までの間ならどこでも受け付ける（複数行可）。データ行の後にあればエラー。
2 列目か 3 列目が空ならエラー。結果 CSV へはバイト列のまま写す。
関数は `ファイル名/関数名`（例: `%,"AMSTB_xx","XXX.c/xx"`。static 関数を指す WinAMS の書き方）でも書ける。
RL78 バックエンドは、定義ファイルのパスの末尾がそのファイル名に一致する関数を選ぶ（大文字小文字と `\` `/` の違いは無視）。
定義ファイルが分からない同名の関数（デバッグ情報のないシンボル）しかなければそれを使い、
同名の関数が別のファイルにしかなければエラーにする（別の関数を黙って置き換えない）。

`sim run` はブロックの初めにバックエンドの `set_csv_stubs` でそのブロックの置換に入れ替え、ブロックの終わりに解除する。
`%` 行のないブロックでは解除だけを行うので、前のブロックや前の CSV の置換は持ち越さない。
RL78 バックエンドは `sim.cfg` の置換とは別の表に持ち、元の関数の先頭にブレークポイントを置いて、`sim.cfg` の
`stub` / `skip`（先頭を `BR !!` に書き換えたものを含む）より先に見る。解除のとき、自分で足したブレークポイントだけを外す。
関数が見つからないときはエラーにして、そのブロックを実行しない（WinAMS の期待値と比べられない結果を黙って出さない）。
`set_csv_stubs` を持たないバックエンド（モック）は、`%` 行のあるブロックをエラーにする。

GUI は CSV の読み込みで同じ置換を有効にし、次の読み込みか対象関数の変更まで保つ（どちらも記録を消すので、
記録はすべて同じ置換のもとで取ったものになる）。読み込みが 400 で失敗したら、以前の CSV の置換に戻す。
保存する CSV には `mod` 行の次に `%` 行を書き出すので、`sim run` で再実行しても同じ置換になる。
波形デコーダは `%` 行を周期に数えない。

### ヘッダ定義と名前付き直アドレス

共通の文脈へ取り込むため、モックとRL78のCSV・初期化・GUI検索／監視／入力・一覧に同じ名前が使える。
`defines` の走査、型の解決、推定、優先順位と対応限界は [HEADER_DEFINES.md](HEADER_DEFINES.md) を参照。
`defines` は `#if` / `#ifdef` を評価して有効な枝だけを取り込む（`defines_cond = off` で従来の全枝読み）。
定義マクロは `cdef = 名前[=値]` / `--cdef`、`cundef = 名前`、CS+ のプロジェクトファイル `mtpj = パス` / `--mtpj`
（`mtpj_mode = ビルド・モード名`）と、ロードモジュールの種類で決まる暗黙の定義から作る。
実装は `sim_defines.c`（指令の切り出し、起点ごとの評価、`#include` の展開と結果の再利用）、
`sim_ppexpr.c`（`#if` の式。32 / 64 ビットの両方で評価して真偽が一致したときだけ採る）、
`sim_mtpj.c`（プロジェクトファイルの最小限の XML 走査）に分けてある。
`defines_scope = mtpj` では、読むファイルを「プロジェクトに登録されたビルド対象のファイルと、そこから `#include` で
たどれるファイル」に絞り、`#include` をインクルード元のフォルダ・インクルード・パスの順に探す（docs/HEADER_DEFINES.md）。
通常のSFRは周辺機能を持たないメモリであり、監視はプログラムが書いた値、入力はプログラムが読む値を扱う。
CPU内蔵のSP/PSW等や設定で有効にした乗除算器は例外。

## 4. CPU コアと周辺機能

- 対応コア: RL78-S1 / S2 / S3。全命令、レジスタバンク、ES/CS、ミラー領域、S2 の乗除算器・積和演算器 SFR、S3 の乗除積和命令。
- 周辺機能（タイマ、シリアル、A/D など）は模擬しない。SFR は読み書きできるただのメモリとして扱う（WinAMS と同じ）。
  割り込みは、テストドライバがハンドラ関数を直接呼ぶ前提。
- `HALT` / `STOP` は読み飛ばす（設定で停止にもできる）。未定義命令、暴走（命令数の上限超過）、
  対象関数から戻らない場合は、PC と逆アセンブル結果を添えたエラーにして、その行を NG とする。
- 結果 CSV の実行時間列は、実行したクロック数と `sim.cfg` の CPU クロック周波数から換算する。

## 4.1 速度

CPU コアは 1 億命令/秒以上を目標にする。`sim run` は終了時に、実行した命令数、所要時間、命令/秒を表示する。

ビルドには必ず `-fno-unroll-loops` を付ける（`build.sh` / `build.bat` に入っている）。clang 20.1.8（x86-64）の素の `-O2` は
ループ展開で命令実行ループを約 10 倍遅くする（GitHub の Windows ランナーで、コア単体のベンチマークが 27 → 254 百万命令/秒。
同じ機械で `-O1` は 241、MinGW の gcc `-O2` は 318）。arm64 の macOS では差が出ないので、手元の測定だけでは気づけない。
命令実行ループ（`rl78/src/rl78_exec.c` の `rl78__exec`）は、命令の `switch`（`rl78_exec_ops.inc`）を 2 回取り込む。
通常の命令はセグメントを定数 F0000H とした系統で実行し、ES プレフィックスの付いた命令と、ブレークポイントの下の
元の命令の実行だけを、セグメントが変数の系統へ `goto` で渡す。1 つの `switch` へ戻って再ディスパッチしていたときは、
そのための準備のコードが毎命令実行されていた（x86-64 の clang で 25% 前後の差。arm64 では差が出ない）。
ブレークポイントのマスク（`bptrap`）はメモリ本体と同じ領域に続けて確保し、1 本のベースポインタで両方を読む
（x86-64 ではレジスタが足りず、主要な状態がスタックへ追い出されるため）。
GitHub のランナーは機種の差が大きい（同じ日のうちに、同じビルドで 250〜600 百万命令/秒の幅があった）ので、
速度は必ず同じジョブの中で新旧を並べて比べる。

速度を優先し、Windows の配布物は MinGW-w64 gcc でビルドする。GitHub のランナーの遅い機種では gcc のほうが速い
（ループを 2 系統に分ける前は clang 254 に対し gcc 318、分けた後は clang 272 に対し gcc 350 百万命令/秒）。
速い機種ではほぼ同じになる（clang 582〜605、gcc 530〜569）。
gcc でも `-O2 -fno-unroll-loops` を維持する。`-static` で gcc のランタイムを静的リンクし、libgcc / libwinpthread 等の DLL は不要にする。
clang のビルドも残し、CI では別の出力フォルダへビルドして互換性を確かめる。

再発を見逃さないよう、CI の Windows では速度の下限を確かめる（コア単体のベンチマークは `BENCH_MIN`、配布する `sim.exe` の
性能テストは `PERF_MIN`。どちらも 100 百万命令/秒）。

## 4.2 C への変換方式（exec = xlate / verify）

解釈実行（`exec = interp`、既定）のほかに、機械語を C に変換して実行する方式を持つ。切り替えは `sim.cfg` の `exec` と
`--exec`。コア側（変換と実行）は `rl78/README.md`「C への変換」、バックエンド側は `runtime/backends/rl78/rl78_xl.c`。

- **変換する関数**: CALL の飛び先の記録、`call` で呼び出した対象関数、前回までの一覧の和。バックエンドを閉じるとき
  （`sim run` の終わり）に、新しい関数があれば全体を変換・コンパイルし直す。`sim xlate` はシンボルにある全関数を足す。
- **コンパイル**: 関数の入口の番地 >> 10 ごとに 1 つの C ファイルにまとめ、clang を並列（`xlate_jobs`、既定は CPU の数）に
  起動する。内容が前回と同じファイルはコンパイルし直さない。C ライブラリを使わないので、LLVM の配布物の clang と
  lld-link だけで DLL にできる（Windows SDK は要らない）。変換に使うソースは実行ファイルの隣の `xlate/` に置く。
  全実行枠を 15 ms 間隔で確認して空き次第補充し、ファイル終了時は前の表示から 5 秒以上、終了がなくても 10 秒ごとに進捗と長く実行中のファイルを表示する（5 秒以内なら表示せず、quiet でも非表示）。
  今回コンパイルしたファイルの所要秒数はキャッシュの `cc_times.txt` に長い順で記録し、30 秒以上のものは終了後に最大 5 件表示する。
- **キャッシュ**: ロードモジュールの隣の `.simxl/<名前>-<鍵>/`。鍵は「0〜`rom_size` のメモリの中身、`rom_size`、コアの設定、
  変換に使うソース、素の RAM の範囲（変換したコードがページの表を引かずに読み書きする範囲）」のハッシュ。鍵が違えば別のフォルダになり、同じロードモジュールの古いフォルダは消す。
  読み込み中の DLL は上書きできないので、作るたびに `xl-N` の番号を進め、`current.txt` で切り替える。
- **書き込み禁止**: 変換したコードは書き換わらないことが前提なので、`rom_size` の指定がなければ 0xF0000 より下を
  書き込み禁止にする。フラッシュから読むときのクロックの加算の対象は変わらないので、クロック数は解釈実行と同じ。
- **外からの書き換え**: 変換はいつも「開いたときのメモリ」から作る（鍵もそこから計算する）。テスト CSV の入力などで
  コードフラッシュが書き換わっていても、その内容で変換結果を作らない。変換した命令のバイトが開いたときと違う値に
  なっている間は、変換したコードを使わず解釈実行する（元の値に戻るか、リセットすれば使い直す）。
- **照合（verify）**: 呼び出しごとに、直前の状態を控えて変換したコードで実行し、状態を戻して解釈実行でやり直し、
  レジスタ・命令数・クロック数・メモリ全体を比べる。残すのは解釈実行の結果。食い違えばその呼び出しをエラーにする。
- **失敗したとき**: clang がない、コンパイルに失敗、変換結果を読み込めない、のどれでも、理由を表示して解釈実行で続ける。
- **GUI**: `sim gui` は閉じるときに変換しない（Ctrl+C で終わるため）。先に `sim xlate` か `sim run` で変換しておく。
- **関数の呼び出し**: 変換済みの関数への `CALL` は、その場で相手を実行する（小さな関数は呼び出し元に埋め込む）。
  詳細は `rl78/README.md`。呼び出しの多いコードで効く（arm64 の Mac、4〜5 命令ごとに関数を呼ぶループで 1.7 倍）。
- **確認の位置**: 命令数の上限とブレークポイントの確認は、関数の入口、ループの戻り先、`CALL` の戻り先に絞ってある
  （前へ進む分岐の先では確かめ直さない）。止まる命令は変わらない。関数の入口以外にブレークポイントを置くと、
  その間は変換したコードを使わず解釈実行になることが増える。詳細は `rl78/README.md`。
- **コンパイル時間**: 長い関数は複数の C の関数に分けて書く（1 つの関数が長いと、コンパイル時間が長さの 2 乗に近い
  伸び方をするため）。詳細は `rl78/README.md`。
- **速度**: 試作の測定で、解釈実行に対して Windows の CI で 2.7〜3.0 倍、Linux で 3.3〜3.4 倍、arm64 の Mac で 4.2〜4.9 倍。
  コンパイルは Windows の CI で 1 命令あたり 6〜7 ms（1 コア）。

## 4.3 PC 用 DLL の方式（exec = native）

製品の C のソースを clang で PC 用にコンパイルした DLL を読み込み、関数を直接呼ぶ方式（hironoa/Simulater#27）。
RL78 の命令は再現しない。目的は速さで、解釈実行・変換方式（実機と同じ結果を確かめる）とは使い分ける。
実装は `runtime/backends/native/native_backend.c`。今の方式のバックエンドの入口が、ロードモジュールを読む前に
`exec` を見て分かれる（命令の実行にロードモジュールは要らない。`native_layout` で変数の番地を読むときだけ使う）。**段階 3（スタブへの置換まで）は完了。Windows でだけ動く。**

- **ソースの一覧**: CS+ のプロジェクトファイル（`mtpj`）の登録ファイルのうち、選んだビルド・モードでビルド対象の `.c`。
  インクルード・パスと定義マクロも mtpj から取る（`cdef` / `cundef` / `--cdef`、`native_include` で足せる）。
  定義マクロは mtpj の定義・定義解除 → `cdef` → `--cdef` → `cundef` の順に渡す（ヘッダーの番地の定義の読み取りと同じ順）。
  製品とは別に管理するソース（ドライバ、スタブ）は `native_src`（`.c`、またはフォルダ。フォルダは直下の `.c`）で足す。
  製品を入れ替えるときは `mtpj` だけを書き換える。
- **アセンブラ**: `.asm` / `.s` はコンパイルせず、`sim info` に一覧を出す。中の関数や変数は DLL に入らないので、
  C から使われている名前には代わりを作る（次の項）。
- **直アドレス定義の自動読み込み**: `defines_scope` が未指定で `defines_auto` が on（既定）なら、
  `sim_defines.c` が mtpj のビルド対象の .h / .c / .inc と `native_src` のファイルを起点に `#include` をたどる。
  `native_src` のフォルダは直下の .c / .h / .inc だけを起点にし、インクルード・パスは mtpj、`defines_include`、
  `native_include` から取る。mtpj がなくても使え、`defines` / `--defines` は追加で読む。
  `defines_auto = off` または明示した `defines_scope` では従来の範囲に従う。
- **定義のない名前の代わり**（runtime/backends/native/native_coff.c と native_backend.c の build_undef）:
  - 名前の集合: リンクの前に、製品、`native_src`、`sim_native_rt.c` の COFF オブジェクトのシンボル表を読み、
    どこかで未定義として参照され、どこにも定義がない外部名を集める。未定義は SectionNumber 0 かつ Value 0。
    共通・絶対・デバッグのシンボルは定義とし、弱い外部は数えない。`__ImageBase` はリンカが解決するので除く。
    bigobj など読めない形式なら、1 行警告して代わりを作らずにリンクする（リンカのエラーがそのまま出る）。
  - 関数か変数か: シンボル表の Type では分からない（clang は未定義のシンボルに関数の印を付けない。実物の .obj で確かめた）。
    そこで、その名前を未定義として参照しているソース（製品と `native_src`）の LLVM IR の宣言を読む。IR は、コンパイルの
    2 段目（下の「プリプロセスと書き直し」）で作る `<名前>.ll`（読み替えの前、最適化の前）をそのまま使い、clang を
    もう一度起動しない（以前は、該当のソースだけ `.pp.c` を `-S -emit-llvm` にかけていた）。宣言の整列や戻り値の種類は
    フロントエンドが決めるので、LLVM の最適化の前の IR でも同じになる（tests/native の `undef.txt` と `sim_native_undef.c` が
    `native_opt` の 0 / 2 とも以前と同じになることを確かめた）。
    `declare … @名前(` は関数、`@名前 = external … global|constant 型` は変数。宣言せずに呼んだ関数（gnu89 の暗黙の宣言）も
    `declare` に出る。関数のアドレスを表に入れるだけの使い方も、宣言から関数と分かる。
  - 変数の大きさ: 型が `iN`、`ptr`、`float`、`double` とその配列なら C の宣言どおりの大きさ。構造体など、
    それ以外と大きさ 0（`extern u1 t[];`）は不明として 4096 バイト。ソースによって食い違えば大きいほう、
    関数と変数で食い違えば関数として警告する。どの宣言にも見つからない名前は関数として警告する。
  - 変数の整列: external の行の型のあとの `align N` を読む（なし、2 の累乗でない、4096 を超えるものは不明）。
    ソースによって食い違えば大きいほう。代わりの整列は max(読んだ整列, 16)。clang は 16 バイト以上の配列を
    `align 16` と宣言し（-O0 でも -O2 でも。clang 18.1.8 で確かめた）、-O2 ではそれを前提に `movaps` でコピーするので、
    8 バイト境界に置くと整列の例外で止まる。
  - 戻り値の種類: `declare` と `@名前` の間で最初の型の形の字句（属性・呼び出し規約・`align N`・`range(…)` などは飛ばす）
    から決める。`float` → F32、`double` → F64、`void`・`iN`・`ptr` → INT、それ以外（`x86_fp80`、ベクタ、構造体の値、
    `half` など）→ OTHER。引数に `sret(` があれば SRET（構造体を隠れた第 1 引数の置き場所に返す）。
    Windows x64 では float / double は XMM0、整数とポインタは RAX で返るので、代わりの戻り値の型を合わせる。
    ソースによって食い違えば、最初に見つかったものを使って警告する。
  - 代わり: 関数は INT・OTHER・SRET なら `long long 名前(void) { return 0; }`、F32 なら `float`、F64 なら `double` を返す
    同じ形。OTHER と SRET は 0 を返せない（SRET は置き場所に何も書かない）ので警告し、`sim info` に添える。
    変数は `__attribute__((aligned(整列))) char 名前[大きさ];`（整列は上のとおり 16 以上）。
    C の識別子として書けない名前は飛ばして件数を出す。キャッシュに `sim_native_undef.c` / `.obj` を置き、
    `sim_native_rt.c` と同じ引数でコンパイルする（ヘッダーの差し込み・書き直しはせず、デバッグ情報も付けない）。
    内容が同じでオブジェクトもあれば使い回し、対象がなくなれば両方を消す。集合（名前・種類・戻り値の種類・大きさ・整列）を
    `link.sig` に混ぜる。
  - キャッシュ: ソースごとの宣言を `<名前>.decl`（「F 戻り値の種類 名前」または「D 大きさ 整列 名前」。その `.ll` のすべての
    declare と external の変数）に保存する。`.decl` はソースをコンパイルするたびに `.ll` から作り、コンパイルし直さない
    ソースは `.decl` を読む。`.decl` がない、または読めない行（古い形式など）があるソースは、使い回さずにコンパイルし直す。
    キャッシュの鍵の版の文字列は `rewrite-4`。一覧は `undef.txt` に保存し、`sim info` に出す。
    それでも `.decl` を読めないときは、1 行警告して代わりを作らずにリンクする。
  - 同名の定義を C で書いて `native_src` に置けば、集合から外れてそちらが使われる。代わりは DWARF を持たないので、
    CSV の対象関数として指定すると「関数が見つかりません」になる。
- **差し込むヘッダー**: 各ソースの先頭に `sim_native_pre.h` を `-include` で差し込む（製品のソースは書き換えない）。
  `__far`、`__near`、`sreg`、`callt`、`norec`、`__interrupt` などを空に、`boolean` / `bit` を 1 バイトの型に、
  `DI()` / `EI()` / `NOP()` などを何もしない式にする。`int` と `__asm` は定義しない。
  `__K0R__`、`__CA78K0R__`、`__SIM_NATIVE__` も定義する。ヘッダーの番地の定義の読み取り（`defines`）も、
  `exec = native` のときは同じ 3 つを暗黙の定義マクロにして、`#if` で同じ枝を選ぶ（`abi =` を書けばそちらが優先）。
- **プリプロセスと書き直し**: ソースごとに 4 段でコンパイルする。各段は、変更したソースすべてについて並列に行う
  （`sim_cc_run_jobs`）。失敗したらその段で止め、失敗したソースの名前と `cc.log` の場所を出す。
  1. `clang -E` で `.i` にする。行の情報と `-MD -MF` の依存ファイルを残す。
  2. 順に `native_rewrite` で `.pp.c` を作り（`int` と `__asm`。下に書く）、`-x cpp-output -S -emit-llvm` で
     LLVM IR の `<名前>.ll` にする。
  3. 順に、`.ll` から定義のない名前を調べるための宣言（`.decl`）を取り、`native_near` で inttoptr を読み替えて
     `<名前>.near.ll` を作る（次の項）。
  4. `.near.ll` を `-c` でオブジェクトにする。`native_near = off` なら 3 段目の読み替えを飛ばし、`.ll` をそのまま
     コンパイルする（キャッシュの鍵に `near-on` / `near-off` を混ぜるので、フォルダが分かれる）。
  2 段目と 4 段目の引数は、以前の 3 段（`.pp.c` を直接 `-c`）と同じ言語・コード生成の引数で、`-include`、`-D`、`-U`、
  `-I`、`-MD` を付けない。最適化の水準: `native_opt = 0` は 2 段目・4 段目とも `-O0`（IR の関数に `optnone` が付き、
  4 段目もそれに従う）。`native_opt = 2` は 2 段目を `-O2 -Xclang -disable-llvm-passes`（フロントエンドは -O2 のまま、
  LLVM の最適化だけを止める。`optnone` は付かない）、4 段目を `-O2` にする。2 段目を `-O2` のまま出すと、
  読み替えの前に番地の定数がたたまれる（`&((T *)0x300)->m` が `inttoptr (i64 812 …)` になり、整列も番地から決まる）
  ので、最適化は読み替えのあとにかける。`-O0 -Xclang -disable-O0-optnone` は、フロントエンドが -O0 の IR を出すので、
  一部のソースで以前の -O2 と違うコードになった。tests/native の全ソースで、読み替えなし（`native_near = off`）の
  オブジェクトの逆アセンブルと DWARF（`.debug_info` / `.debug_line`）が、以前の 3 段と同じになることを
  `native_opt` の 0 / 2 とも確かめた（clang 18.1.8）。`.ll` と `.near.ll` はキャッシュのフォルダに残す（調べるときに使う）。
  DLL に入れる部品（`sim_native_rt.c`）と `sim_native_undef.c` は、今までどおり 1 回のコンパイル（書き直さない）。
- **整数からポインタへの変換の読み替え**（runtime/backends/native/native_near.c）: RL78 の near のデータのポインタは
  16 ビットで、実際の番地は 0xF0000 を補ったもの。製品のソースが 5 桁の番地をマクロで 16 ビットに切り詰めてから
  near のポインタにする（`((tC __near *)(vuint16)0x0FFFD4u)->Int`。#27 で報告された形）と、PC では 0xFFD4 を指して
  例外になる。そこで、LLVM IR の段階で整数からポインタへの変換（`inttoptr`）をすべて捕まえ、値 v が 1〜0xFFFF なら
  v + 0xF0000 にする。0（NULL）と 0x10000 以上は変えない。clang 18 の C のフロントエンドは inttoptr を i64 でしか
  出さない（-O0 でも `-disable-llvm-passes` でも）。形は 2 つ:
  - 定数の形 `inttoptr (iN V to ptr)`: 命令のオペランド、`getelementptr` の定数式の中、グローバルの初期値など、
    1 行の中のどこに現れても書き換える。V は 10 進（LLVM は符号付きで書くので、iN の幅で符号なしに直してから判定する）。
    書き換えたものは `inttoptr (i64 V' to ptr)` にする（i16 では 0xFFFD4 が入らないので型も i64 にする）。
    関数の中の `((T *)0x300)->m` は `getelementptr (… inttoptr (i64 768 …) …)` になり、768 を書き換えればメンバも
    0xF0300 台になる。グローバルの初期値の `&((T *)0x300)->m` はフロントエンドが `inttoptr (i64 770 …)` にたたむので、
    メンバの位置を足したあとの値で判定する（0xFFFF の近くでは、足したあとで 0x10000 を超えると読み替えない）。
  - 命令の形 `%x = inttoptr iN %v to ptr`（値が実行時に決まる。16 ビットの表に入れた番地など）: `%v` を i64 に広げ
    （N < 64 なら `%sim.near.z<番号> = zext`）、`%sim.near.<番号> = call i64 @__sim_near(i64 …)` を通してから
    `%x = inttoptr i64 %sim.near.<番号> to ptr` にする。名前付きの値なので、番号だけの値（`%0` …）の並びは崩れない。
    差し込んだ命令には元の命令の `!dbg` を付ける（止まった行の表示のため。宣言だけの関数への呼び出しなので、
    なくても検証は通る）。命令の形が 1 つでもあれば、ファイルの最後に `declare i64 @__sim_near(i64) nounwind willreturn
    memory(none)` を 1 つ足す（すでにあれば足さない）。`memory(none)` なので、-O2 では同じ呼び出しがまとめられる。
    本体は `sim_native_rt.c` の `__sim_near`（`(v - 1 < 0xFFFF) ? v + 0xF0000 : v`）。
  - 文字列（`c"…"`、`!"…"`、`"…"` の名前）とコメント（`;` 以降）の中は見ない。名前の一部（`%inttoptr`、`@x_inttoptr`）も
    語として見ない。知らない形（ベクタ、値が定数式、`addrspace`、i65 以上）は書き換えずに残して数える。
  - 関数へのポインタに変える場合（`((void (*)(void))0x1234)()`）も区別せず同じ規則がかかる（PC ではどのみち呼べない番地）。
    PC の本物のポインタ（64 ビットの整数に入れて戻したもの）は 0x10000 以上なので変わらない。16 ビットに切り詰めた
    PC のポインタは、上位が失われているので直せない。
  - 数（定数、実行時、残したもの）はソースごとに `.rw` に保存し、コンパイルし直さなかったソースの分も合計して
    `sim info` に出す（`native near=1 const=N dyn=M kept=K`）。
  - 実行時間: tests/native（ソース 10 個）の初回のビルドは、以前の 3 段の約 1.1〜1.2 倍（1 段増えて clang の起動が
    ソースの数だけ増える。定義のない名前の宣言を調べるための clang の起動はなくなった）。
  型の語の並びの `int` を `short` に置換し、`long` / `short` があれば `int` を削除する。
  `unsigned` / `signed`（`__signed` / `__signed__` を含む）だけの型には `short` を補う。修飾子・指定子
  （`const` / `volatile` / `restrict` / `inline` とその GNU の別名 `__const` / `__const__` / `__volatile` /
  `__volatile__` / `__restrict` / `__restrict__` / `__inline` / `__inline__`、`__extension__`、`static` /
  `extern` / `register` / `auto` / `typedef`）は並びを切らず、判定にも影響しない。`char` / `_Bool` / `float` /
  `double` / `void` / `_Complex` / `__int8` / `__int16` / `__int32` / `__int64` / `__int128` は並びを切らず、
  その並びでは `int` の書き換えも `short` の補いもしない。かっこを取る語（`__attribute__` /
  `__attribute` / `__declspec` / `_Alignas` / `__alignas` / `__alignas__` / `__pragma`）は、語と続くかっこの組を
  並びを切らないものとして判定の先読みで読み飛ばす。`__typeof__` / `__typeof` / `typeof` / `_Atomic` にかっこが
  続く形は別の型の語と同じに扱う（かっこなしの `_Atomic` は修飾子として読み飛ばす）。それ以外の、表にない
  `__` または `_` + 英大文字で始まる語（`__asm` は除く）は、`(` が続けば関数や変数の名前とみなしてそこで並びを
  終え（`int __legacy(a) long a;` の `int` と `long` を一つの並びにしない）、続かなければ語だけを読み飛ばす
  （`__cdecl`、`__near` など）。読み飛ばした語とかっこは出力から消さず、かっこの中は通常どおり書き直す。文字列・文字定数・数値は保護する。
  `__asm("…")` は関数の内外とも、対応するかっこまで空にして `;` を残す。かっこの入れ子と引用符を考慮する。
  行頭の `#` 行はそのまま写し、行の情報のフラグ 3 があるシステムヘッダーは書き直さない。`clang -E` は空行が
  続くと宣言の途中や `__asm` と `(` の間にも行の情報を出すので、`#` 行は型の語の並びを切らず、`__asm` のあとの
  `(` を探すときも飛ばし、`__asm` の消す範囲の中にあっても残す。
  閉じていない文字列・文字定数は行末で終える。
  削除した範囲も改行を残し、行の数を変えない。元の製品ソースは変更しない。
  4 種類の統計を、inttoptr の読み替えの 3 種類の数とともにソースごとの `.rw` に保存し、再利用分も合計して
  `sim info` に出す。`.rw` がなければ再コンパイルする。
- **マイコンの番地の範囲のクリア**（runtime/backends/native/native_layout.c、native_backend.c の load_layout / build_layout /
  host_clear、`sim_native_rt.c` の `sim_native_clear_range`。#27）: 製品のアセンブラの「RAM の範囲をクリアする」関数は、
  番地を数字で受け取る。native では C の変数がマイコンの番地にないので、そのままでは 0 にならない。
  - 番地の読み取り: `native_layout = <ロードモジュール>` を、コンパイルの前に今の方式と同じ関数で読む（`.lmf` は
    `rl78_lmf_load` と `rl78_sym_load`、`.abs` は `rl78_elf_load`、`rl78_dwarf_read`、`rl78_symtab_from_elf`。CPU と
    メモリのイメージは作らない。`char_unsigned` など番地と大きさに関係しない設定は既定のまま）。読めなければエラー。
  - 対応づけ（`native_layout_match`）: ロードモジュールの変数の名前で、DLL のデバッグ情報の変数を探す。関数名
    （関数内 static）はいつも合わせる。候補ごとの一致の強さは、どちらもグローバルならいちばん強い（ファイル名を見ない）、
    それ以外はパスの末尾から同じ部分がいくつ続くか（`native_layout_common_tail`。区切りの / と \ を同じとみなし、
    Windows では大文字小文字を区別しない。0 は候補にしない）。製品と `native_src` の候補をまとめて強さの順に並べ、
    同じ強さの組ごとに、まだ決まっていないロードモジュールの変数と、まだ使っていない DLL の変数の組だけを見る。
    どちらから見ても相手が 1 つなら確定し、そうでなければ
    あいまい（`ambiguous`）にして対応づけず、その DLL の変数も弱い組には使わない。確定の印は同じ強さの組を全部見て
    から付けるので、結果はロードモジュールの変数の並びに左右されない（PR #46 のレビューの指摘: 以前は製品の側だけで
    「末尾の一致 → ファイル名の部分の一致」を試してから `native_src` を見ていたので、製品の弱い一致が `native_src` の
    強い一致より先に選ばれ、テストドライバの変数の番地が製品の変数に結び付くことがあった）。CA78K0R の `.lmf` は
    変数のファイルをパスなしの名前で持つ（probe の `.lmf` で確かめた）ので、同じファイル名のソースが製品と
    `native_src` の両方にあって同じ名前の static があれば、あいまいになる。
    対応づいた変数は製品・`native_src` ともに「マイコンの番地 [lo, hi) → PC の番地と大きさ、書けるか」の表に入れる。
    表を lo の順に並べ、先頭からの hi の最大を持たせる（二分探索で、範囲に重なる最初の項目を探す）。
    書き込みには DLL の書けるセクションにあることが必要で、const の変数はクリアしない。
    毎回クリアする一覧（`src_always`）には、対応づけに使われず、あいまいな組の候補にもならなかった `native_src` の変数のうち、
    大きさが分かる書き込み可能なものを入れる。変数の file（コンパイル単位の `.pp.c` を元のパスに直したもの）を `z->srcs` と照合する。
    先頭 `from_mtpj` 個が製品、その後が `native_src`。実行時の部品や自動生成の代わりは一覧に入らない。
    表と一覧を作ったらロードモジュールは閉じる。
  - 部品と sim.exe のつなぎ: `sim_native_rt.c` にグローバルの関数ポインタ `__sim_host_clear` を置き、
    `sim_native_clear_range(first, end)` / `sim_native_clear_range_incl(first, last)` はそれを呼ぶだけ（空なら何もしない）。
    1〜0xFFFF の値には部品の側でも 0xF0000 を足す（`native_near = off` のため）。sim は DLL の COFF のシンボル表から
    `__sim_host_clear`（書けるセクションの外部シンボル）の番地を取り、DLL のセクションの中身を控える（リセットで戻す）前に、
    自分の関数 `host_clear` の番地を書き込む。宣言は `sim_native_pre.h` にあり、型は `int` の書き直しに関わらない
    `unsigned long long`（書き直したあとの `.pp.c` で変わらないことを確かめた）。
  - クリアの規則（`host_clear`）: 範囲 [first, end)（`_incl` は end = last + 1）。先頭 ≧ 終わりや 0x100000 を超える範囲は、
    何もせず警告を 1 度だけ出す。有効な範囲で `native_layout` があれば、一覧の変数は毎回全体を 0 にする。
    対応表にあり、範囲に全部入る変数は PC の大きさで全体を 0 に、一部だけ入る変数は、マイコンと PC で大きさが
    同じなら重なったバイトの位置をそのまま PC の側に当てて 0 に、違えば何もせず変数ごとに 1 度だけ警告する。
    0xF0000〜0xFFFFF の確保したメモリのうち範囲に入る部分も 0 にする（番地を直接書いたデータ。製品のソースでも
    `native_src` の `#define` でも同じ）。`native_layout` がなければ、確保したメモリだけを 0 にして警告を 1 度出す。
    呼ばれた回数とクリアした変数の延べ数を数え、`-v` のとき、閉じるときに標準エラーに 1 行出す。
  - 監視と復帰との関係: `host_clear` は製品の関数の実行中（`b_call` の中）に、DLL を呼んだスレッドで動く。時間切れの
    監視のスレッドは、止めた位置が DLL の範囲（`g_code_lo`〜`g_code_hi`）の中のときだけ文脈を書き換えるので、
    sim.exe の中を実行している間に期限が来ても書き換えず、20 ミリ秒後に判定し直す（DLL に戻ったところで止まる）。
    `host_clear` の中では、警告の 1 回を除いてロックを取る処理（printf、malloc）を行わない（止めたスレッドが
    ロックを持ったまま復帰させない）。表は二分探索で、該当の変数だけを触る。
- **`int` の読み替えの限界**: 変数・引数・戻り値・`sizeof(int)` は 16 ビットになるが、計算の途中は PC の
  `int`（32 ビット）に広がる（`unsigned short` の 40000 + 40000 を比較すると、マイコンでは 14464、PC では 80000）。
  型を書かない宣言（`static x;`、戻り値の型を省いた関数）は PC の `int` のまま。`INT_MAX` など標準ヘッダーの値も PC のもの。
- **コンパイル**: ソースごとに clang を並列（`native_jobs`、既定は CPU の数）に起動し、1 つの DLL にまとめる。
  C ライブラリを使わないので、LLVM の配布物の clang と lld-link だけで作れる（Windows SDK は要らない）。コンパイラが
  構造体の代入などで呼ぶ `memcpy` / `memset` / `memmove` / `memcmp` は `sim_native_rt.c` で DLL に入れる。
  差し込むヘッダーと `sim_native_rt.c` は実行ファイルの隣の `native/` に置く。clang を並列に起動する部分と進み具合の
  表示は変換方式と共通（`runtime/src/sim_cc.c`）。
- **キャッシュ**: 設定ファイルの隣の `.simnative/<mtpj の名前>-<鍵>/`（`native_dir` で変えられる。製品のフォルダには
  書かない）。鍵は「コンパイラの版の表示、コンパイルの引数（定義マクロとインクルード・パスを含む）、差し込むヘッダー、
  `sim_native_rt.c`、書き直し規則の版（`rewrite-4`）、`native_near` の on / off」のハッシュ。鍵が違えば別のフォルダになり、同じ mtpj の古いフォルダは消す。
  ソースごとに、clang が書いた「読んだファイルの一覧」（`-MD`）を使って、ソースと読んだヘッダーすべての中身の
  ハッシュを控える。次に開いたとき、それが同じソースはコンパイルし直さない（ヘッダーを 1 つ変えると、それを
  読むソースだけコンパイルし直す）。DLL は、オブジェクトの組と呼ぶ関数の一覧が前回と同じなら作り直さない。
  依存ファイルごとに、ほかの探索フォルダに同じつづりのファイルが存在するかも控え、探索順で先に当たる場所に
  同名のファイルが置かれた場合や消えた場合もコンパイルし直す。
  読み込み中の DLL は上書きできないので、作るたびに `native-N` の番号を進め、`current.txt` で切り替える。
- **関数の呼び出し**: 一覧・型・番地は DWARF から取り、static の関数も呼べる。整数とポインタの引数は
  x64 の 64 ビットの枠で渡す（8 個まで）。浮動小数の戻り値は float / double 用の関数ポインタで受け、ビット列を返す。
- **デバッグ情報**: 製品ソースを `-gdwarf-4` 付きでコンパイルし、`/debug:dwarf` と `/opt:noref` でリンクする。
  DLL のファイルから `.debug_info` / `.debug_abbrev` / `.debug_str` を読み、既存の DWARF 読み取りに渡す。
  `.pp.c` をコンパイルすると、コンパイル単位の名前（`DW_AT_name`）は `.pp.c` のパスになる（変数・関数の
  `DW_AT_decl_file` は行の情報により元のソースを指す）。CSV の `vars.c/名前` はコンパイル単位の名前で照合するので、
  ファイル名の部分が自分で生成した `<名前>-<ハッシュ>.pp.c` と一致するものは、変数・関数の `file` を元のソースのパスに
  直す（clang は先頭の `./` を省くなど、渡したパスと同じつづりにならないので、ファイル名の部分だけで照合する）。
  文字列はシンボル表のアリーナに複製する。
  COFF の長いセクション名は文字列表で解決する。番地はロード先 +（DWARF の番地 - ImageBase）に直す。
  イメージの範囲外のシンボルは除く。ポインタの既定幅は 8 バイトで、今の方式の 2 バイトは変えない。
  `native_opt` は 0（既定）/ 2。2 では書き換えない static 変数などが最適化で消えることがある。
  どこからも使われない static 変数は 0 でも DLL に入らない。
- **番地**: 0xF0000〜0xFFFFF に、同じ番地のメモリを確保する。`#define REG (*(volatile unsigned char *)0xFFF01)` の形の
  レジスタや、番地を直接書いた RAM のアクセスが、ソースのまま動く。CSV の `0xFFF01:1` の形の番地指定と、ヘッダーの
  番地の定義（`defines`）で読み書きできる。**0x10000 より下の番地は Windows が使わせないので再現できない。**
  整数からポインタへの変換で 1〜0xFFFF の値は 0xF0000 台に読み替えるので（上の項）、4 桁で書いた near の番地も
  この範囲に入る。
  バックエンドの読み書き（`read` / `write`）が受け付けるのは、この範囲、DLL の変数の領域、`$` で確保した領域だけ。
  この範囲がプロセスのほかの用途にすでに使われていて確保できないときは、エラーにする。
- **リセット**: DLL の書き込めるセクションを読み込んだときの中身に戻し、0xF0000〜0xFFFFF と `$` の領域を 0 にする。
- **失敗したとき**: clang を起動できない、コンパイルに失敗した、DLL を作れない、番地を確保できない、のどれも
  エラー（終了コード 2）にする。対象関数の実行中の例外（確保していない番地の読み書き、0 での割り算など）は、
  理由を返してその行だけ NG にし、次の行へ進む。共通 CSV 処理の集計に合わせ、呼び出し失敗は「エラー」件数ではなく NG、終了コードは 1。
  DLL の変数は途中の状態のまま残し、mod のブロックが変わるとリセットする。
  - `b_call` 自身で `__builtin_setjmp` に戻り先を控える。例外ハンドラは理由を静的な変数に控え、文脈の
    Rip / Rsp / EFlags を書き換える。OS が例外の配送を終えると、同じスレッドが復帰用の関数 `native_recover` から再開し、
    `__builtin_longjmp` で `b_call` に戻る。ハンドラから直接 longjmp はしない。
  - `native_timeout_ms` は 1 回の呼び出しの上限（既定 10000 ミリ秒、0 は無効、最大 86400000）。単調増加の
    `sim_now_ns` で期限を設定し、監視のスレッドが 20 ミリ秒ごとに確認する。期限を過ぎたら対象のスレッドを停止し、
    文脈を書き換えて再開する。`SuspendThread` は止まるのを待たないので、先に `GetThreadContext` で止まるのを待ち、
    止まった位置（Rip）が製品の DLL の中のときだけ書き換える（`b_call` の前後や例外の配送中に止まったときは、次の確認で判定し直す）。呼び出すスレッドのハンドルは初回とスレッドが変わったときだけ複製する。
  - 例外ハンドラと監視のスレッドは `g_in_call` の CAS で、どちらが復帰させるかを決める。理由の文面は復帰後に作る。
    復帰用のスタックは `b_call` のフレーム位置から 1024 バイト下を 16 バイト境界に切り下げ、8 を引く。方向フラグも落とす。
  - スタックの使い切りはガードページの復旧が必要なので対象外。理由を表示し、sim 全体を終了コード 2 で終了する。
  - 止まった場所: 例外ハンドラは `ExceptionAddress`、監視のスレッドは書き換える前の Rip を控えるだけにし、`b_call` に
    戻ってから LLVM の配布物の `llvm-symbolizer` を起動して、番地をソースのファイル名・行番号・関数名にする（自前で
    `.debug_line` は読まない）。番地が DLL の範囲の中のときだけ、優先ベース（PE ヘッダーの ImageBase）での番地に直して
    `--obj=<DLL> --output-style=LLVM --functions=linkage --inlines <番地>` で渡す。出力は 1 段ごとに「関数名」「パス:行:桁」の
    2 行で、いちばん内側（実際に止まった行）が先、インライン展開した呼び出し元が続く（4 段まで読む）。パスに ':' が入るので
    行番号は末尾側から読み、`??` と行番号 0 は不明とする。デバッグ情報の行は、プリプロセスの行の情報を通して `.pp.c` ではなく
    元のソースとヘッダーを指す（clang 18.1.8 で確かめた。ヘッダーのマクロは使った行、ヘッダーの関数はヘッダーの行になる）。
    理由の文の末尾に「止まった場所: io.c の 24 行目（<フルパス>:24）」の形で足す（関数が呼んだ関数と違えば関数名も）。
    道具は `native_symbolizer`、なければ clang と同じフォルダの `llvm-symbolizer.exe`、clang がフォルダなしなら PATH の
    `llvm-symbolizer`。出力はキャッシュのフォルダの一時ファイル（`symbolize-<プロセスの ID>-<通し番号>.tmp`。同じ設定の sim が同時に動いても重ならない。コンパイラの版を取る `ccver-…tmp` と、定義のない名前を調べる `.ll` も同じ形）に取り、読んで消す。起動は 1 回の実行で 20 回まで
    （1 回 35〜45 ミリ秒ほど。21 件目で 1 度だけ標準エラーに知らせ、以後は足さない）。直前と同じ番地は調べ直さない。
    起動できない・読めないときは DLL の中の位置（優先ベースでの番地）を足す。起動の時間は、その行の実行時間に含まれる。
- **変わること**: `int` の計算の途中の桁、ポインタの幅（64 ビット）、構造体のすき間とビットフィールドの並び
  （clang のもの）。実行クロック数とスタックの使用量は出ない。結果 CSV の実行時間は実時間。
- **スタブ**（段階 3）: `stub`、`stub_auto`、`skip` と CSV の `%` 行を使える。
  DLL の読み込みとデバッグ情報の取得後、元の関数の入口を
  `48 B8 <スタブの番地 8 バイト> FF E0`（mov rax, imm64 / jmp rax、12 バイト）にする。
  `skip` は `48 B8 <戻り値 8 バイト> C3`（ret、11 バイト）。省略時は 0。戻り値を書くときは、今の方式と同じく
  型の分かる整数・ポインタで、その大きさに収まる値だけ（真偽値は 0 / 1）。
  浮動小数を返す関数は 0 だけ指定でき、先頭に `0F 57 C0`（xorps xmm0, xmm0）を足す（14 バイト）。
  書き込み時は `VirtualProtect` で PAGE_EXECUTE_READWRITE にして元の保護へ戻し、`FlushInstructionCache` を呼ぶ。
  元の命令を番地ごとに保存し、解除時に戻す。呼び出し中には書き換えず、変数のリセットでは置換を変えない。
  CSV は設定より優先し、ブロック終了・指定の失敗時は CSV の置換をすべて解除して設定だけに戻す。
  関数名はデバッグ情報（名前だけなら外部優先、static だけなら最初）から探す。
  `ファイル名/関数名` は CU のファイル名の末尾を照合する。デバッグ情報になければ DLL の COFF 表の
  セクション VirtualAddress + Value + 読み込みベースから探し、sim が作ったアセンブラ関数の代わりも対象にする。
  書き換える範囲は、次の関数の先頭（デバッグ情報と COFF の表の両方）とコードのセクションの終わりを越えないこと、
  関数の大きさが分かり命令より短いときは、関数の終わりから書き換える範囲の終わりまでが埋め草
  （clang の関数は 16 バイト境界に並び、間は `0F 1F …` / `66 2E 0F 1F 84 …` の複数バイトの nop、
  セクションの継ぎ目は 0xCC）であることを確かめ、そうでなければエラーにする。
  同じ中身の関数が 1 つにまとめられると片方の置換がもう片方に及ぶので、リンクに `/opt:noicf` を付ける
  （`/opt:noref` だけでも lld-link はまとめないが、明示する）。同じ DLL の中の呼び出しは直接の call で、
  関数へのポインタからの呼び出しも入口を通るので置き換わる。
  `native_opt = 2` では、同じファイルの中から呼ぶ小さな関数が呼び出し元に埋め込まれて入口の置換が効かず、
  埋め込まれて使われなくなった static 関数は DLL に残らず、置き換え元として見つからない（エラーになる）。
- **残りのできないこと**: GUI（段階 4）、製品のソースで出る個別の問題、
  `#asm`〜`#endasm` と `__asm { … }`。型を省いた宣言と標準ヘッダーの定数は PC の規則のまま。
  Windows 以外では、エラーにして実行しない。
- **確認**: `tests/native/` の合成のプロジェクト（CA78K0R の書き方をまねたソース、合成の mtpj、別フォルダのドライバ）
  を `tests\rl78\run_rl78_tests.bat` で実行する。製品のソースでは確かめていない。

## 5. GUI モード

`sim gui` は 127.0.0.1 だけで待ち受ける HTTP サーバを立て、既定のブラウザを開く。
対象関数が未設定なら、起動は続け、標準エラーに画面または `--func` での指定を促す案内を 1 行出す。
この間 `/api/control` の `run`・`step` は、速度や周期など同時指定の項目も含め何も変えず、
対象関数が未設定で `func` による指定が必要な旨の 400 を返す。有効な `func` と `cmd` の同時指定は受け付ける。
対象関数が未設定かつ記録がない場合の `/api/export.csv` も、再実行できない空の `mod` 行を返さず同様の案内で 400。
`/api/write`・`/api/watch`・`/api/symbols`・`/api/info` は従来どおり利用でき、`/api/load-csv` は `mod` 行の関数を設定する。
画面は対象関数が空の間「実行」「ステップ」を無効にし、対象関数の選択を促す。

1 行 = 1 周期の対象関数（既定はテストドライバの関数。`--func` または画面で指定）を、周期タイマで呼び続ける。

### HTTP API

すべて JSON。文字コードは UTF-8。double であふれる数（`1e400`）や 0 になるほど小さい数は壊れた JSON として 400。
`Content-Length` が 10 進の数字でなければ 400。

| メソッド パス | 内容 |
|---|---|
| `GET /` | `sim_gui.html` を返す |
| `GET /api/info` | `{"version","periodMs","func","functions":[名前...],"state":{...}}` |
| `GET /api/symbols?q=文字列&limit=200` | 名前の部分一致検索（`limit` は 1 以上の整数で、5000 を超える指定は 5000 件まで。数値でなければ 400）。`[{"name","type","size","kind":"int|uint|float|ptr|struct|array","writable":bool,"members":[...子の名前]}]`。`members` は子の**完全名**（`g_cmd.mode`、`arr[2]`。配列は最大 256 要素、入れ子の匿名メンバは全階層を省略して展開。ポインタ先の構造体は `p->m`）。部分一致の走査は深さ 8・訪問数 500000 まで。完全な式は走査上限と独立して先に解決し、`members` の各完全名を再検索できる。型・サイズ・書き込み可否は watch/write と同じ式解決から取得する（構造体・配列自体は書き込み不可）。空白は式パーサが受け付ける位置で使用可（例: `a [ 1 ] .lo`） |
| `POST /api/control` | `{"cmd":"run"|"pause"|"step"|"reset","steps":N,"speed":倍率,"periodMs":周期,"func":"関数名"}`。不明な `cmd` や対象にできない関数（浮動小数・構造体の引数など）は 400 で、そのときは関数・引数・速度・周期を何も変えない。`steps` は 1 以上の整数、`speed` は 0（最速）か 0.1〜100、`periodMs` は 0.01〜60000 で、範囲外・数値でない値は丸めずに 400（何も変えない）。`func` で対象関数が実際に変わったときは、`cmd` の前に `reset` と同じことをする（下記）。要リセット中の `run`・`step` は他の指定も含め何も変えず 400（直前の失敗理由とリセットの案内）を返す。応答は `state` と同じ形で、解決し直せずに外した固定・監視を `dropped` に載せる（下記「関数を変えたときの固定と監視」）。`step` は周期を待たずに続けて N 回実行し、終わるまで（最大 5 秒）待って応答する。応答には `state` に加えて `"stepsDone":この要求の後に進んだステップ数,"timedOut":bool` を付ける。5 秒で終わらなければ `timedOut` が真で、残りは続けて実行する（`stepsLeft` が 0 でなく `running` が真。`pause` で止める） |
| `POST /api/watch` | `{"names":["変数",...]}` 監視する変数の一覧を置き換える。解決できなかった名前は `{"errors":[{"name","message"}]}` で返す |
| `GET /api/variants` | `{"path","exists":bool,"doc":JSON または null,"error"}`。ファイルなしは exists:false。壊れた JSON は exists:true, doc:null と理由を返す（HTTP 200） |
| `POST /api/variants` | variants 配列を持つ JSON オブジェクトをサーバの固定保存先に一時ファイル経由で保存。JSON・オブジェクト・配列の違反は 400。応答は `{"ok":true,"path"}`。既定は sim.cfg 基準の sim_gui_variants.json、gui_variants 設定も同じ基準で解決 |
| `GET /api/signals` | `{"path","exists":bool,"text":文字列 または null,"error"}`。ファイルなしは exists:false、読めない場合は exists:true, text:null と理由を返す（HTTP 200） |
| `POST /api/signals` | 生のテキストを固定保存先へ一時ファイル経由で保存。空本文は可、NUL を含む本文は 400、保存失敗は 500。成功は `{"ok":true,"path"}`。Content-Type は問わない |
| `POST /api/init` | `{"values":[{"name","value":文字列,"mode":"once"または"every"}]}` で初期化一覧を置換。空で解除。write と共通の検査を行い、1 件でも不正なら何も変えず 400 `{"errors":[{"name","message"}]}`。要リセット中も 400 |
| `POST /api/write` | `{"name":"変数","value":数値または文字列,"hold":bool}` 要リセット中は単発・固定・解除とも 400（直前の失敗理由とリセットの案内）。次の周期の開始時に書き込む（止まっているときもすぐには書かない）。`hold` が偽なら単発（反映待ち。同じ名前に書き直すと置き換わる）、真なら毎周期書き続ける（入力の固定。同じ名前の反映待ちは捨てる）。`{"name","release":true}` で固定を解除し、その名前の反映待ちも捨てる。`value` の整数は書いた表記のまま読む（2^53 を超える整数を double に丸めない）。名前が解決できない・書き込めない、型に収まらない、`$` の値が 0 以上の整数でない、要素数を超える、改行を含む、などの値はこの時点で 400（ポインタの先のようにその時のメモリで決まるものは、書くときに `state` の `error` になる） |
| `GET /api/stream` | Server-Sent Events。下記 |
| `POST /api/load-csv` | 本文にテスト CSV。成功時は要リセットとエラーを解除し、初期状態に戻して先頭から再生する（入力列を毎周期書き込む。監視と応答の `names` には通常の入力列・出力列の名前を列順に一度ずつ加える。初期化専用の列は再生と入力の記録に使う）。`{"rows":N,"names":[...]}`。関数や入力列が使えなければ 400 で、以前の関数・引数・再生をそのまま残す。同じ名前（前後の空白を除いて完全一致）の入力列が複数ある CSV も、重なっている名前と列番号を示して 400（関数・再生・記録・固定・監視は変えない。`sim run` では実行できる）。`mod` ブロックが複数あれば先頭のブロックだけを再生し、応答に `"blocks":<ブロック数>,"warning":"..."` を足して知らせる |
| `GET /api/export.csv` | 開始（またはリセット）からの記録を WinAMS 形式の CSV で返す（固定・書き込みした変数が入力列、監視変数が出力列）。下記「記録と CSV 保存」 |

### ストリーム（SSE）

- `event: hello` — `{"periodMs","func","names":[監視名...]}`。接続時と監視一覧が変わったとき。
- `event: samples` — `{"step0":先頭のステップ番号,"names":[...],"rows":[[値,...],...]}`。約 50ms ごとにまとめて送る。
  値は数値、読めなければ `null`。
- `event: state` — `{"running":bool,"step":現在のステップ,"speed":倍率,"holds":[{"name","value"}],"overrun":bool,
  "periodMs","func","playback":bool,"error":文字列,"needReset":bool,"initStale":bool,"dropped":[{"name","kind":"hold"|"watch"|"init","message"}],
  "pending":[{"name","value"}],"stepsLeft":N,"inits":[{"name","value","mode"}]}`。変化時と 1 秒ごと。`/api/control` の応答と `/api/info` の `state` も同じ形。
  `holds` の `value` は固定したときに書いたセルの文字列（`"800"`、`"0x78"`、`"9007199254740993"`、`"'A'"` など。`pending` と同じ。
  数値に直さないので、2^53 を超える整数が丸まったり 16 進が 10 進になったりしない）。
  `stepsLeft` は `step` の残りのステップ数（0 でなければ `step` を実行中で、`running` も真）。
  `dropped` は直近の `/api/control`・`/api/load-csv` で外した固定・監視（次の `/api/control`・`/api/load-csv` で空に戻る）。
  `pending` は次の周期の開始時に書く単発書き込み（`value` は書いたセルの文字列。`"7"`、`"'A'"`、`"0x78"` など）。
  同じ名前に書き直すと置き換わり、ステップでの反映・リセット・関数の変更・その名前の固定と解除で消える。
- `event: values` — `{"step":現在のステップ,"names":[監視名...],"values":[値,...]}`。監視変数のメモリの現在値（ステップは進めない。
  反映待ちの値は混ぜない）。接続時、監視一覧の変更時、リセットの後に送る（一時停止中でも変数モニタに値を出すため）。
  停止中に書き込んでも次のステップまでメモリは変わらないので、値は変わらない。
  約 50ms ごとの送信の間に何度か変われば最後の値だけを送る。読めなければ `null`。

`reset` は「初期状態」（スタートアップ完了時点の CPU とメモリ）に戻す。ステップを 0 にし、記録と未消化の単発書き込みを捨てる
（固定は残す）。初期状態へ正常に戻ると `needReset:false` にし、`error` も空にする。

### 関数を変えたときの固定と監視

固定（`hold`）と監視の名前は、対象関数が変わるたびに（`/api/control` の `func`、`/api/load-csv` の `mod` 行）新しい関数で
解決し直す（`reset` のときも同じ手順を通す）。`@引数` は引数の番号で覚えているので、前の解決結果を使い続けると
別の引数を読み書きしてしまう（`eng_judge_gear` の `@rpm` の固定が `mul16` の `@a` を上書きする）。

- 解決し直せない固定・監視は外す。新しい関数にない `@引数`、前の関数の戻り値 `前の関数@@` など。
  固定は書き込めなくなったときも外す。関数の変更そのものは受け付ける。
- 外したものは `state`（`/api/control` の応答と SSE の `event: state`）の `dropped` に
  `{"name","kind":"hold"|"watch"|"init","message":理由}` で載せる。`holds` と `event: hello` の `names` は外した後の内容になる。
- 外した固定は書かないので記録の入力列にも出ず、監視は出力列に出ない。保存した CSV に新しい関数にない列は残らず、
  `sim run` でそのまま再実行できる。
- `/api/control` で関数を変えたときは、読み込み済みの CSV の再生もやめる（入力列は前の関数で解決しているため）。

### 仕向（初期化の値）

`POST /api/init` で受けた初期化の値は、テスト CSV の `#Init...` 行（3 節の `csv_init`）と同じ規則で書く。

- 周期の開始時、単発・固定・CSV 再生の入力より前に並べる。同じ入力列は最後のものだけを書くので、同じ変数に入力があれば入力が勝つ。
- `once` はステップ 0 の周期（起動直後とリセットの後）だけ、`every` は毎周期書く。途中で `once` の値を変えても次のリセットまで書かない
  （WinAMS で `#InitWheneverCall` を初回だけ書く設定と同じにするため）。
- 書いた値は固定と同じく記録の入力列に残す（`once` は最初の行だけ）。保存した CSV を `sim run` で再実行しても同じになる。
- 関数の変更・リセットのときは固定と同じく解決し直し、できないものは外して `dropped` に `kind:"init"` で載せる。
- `state` の `inits:[{"name","value","mode"}]` に今の一覧を載せる（`value` は受けたセルの文字列のまま）。
- `state.initStale` は、ステップが 0 でないときに `once` の name・value の組が変わると真になる（順序は無視）。同じ一覧の再送や `every` だけの変更では変えず、リセットで偽に戻す。ステップ 0 での変更では立てない。GUI は真の間「リセットして反映」を表示し、ブラウザの再読み込み後も維持する。
- 初期化の一覧が空なら、今までの動きを変えない。

起動時の `/api/init` の失敗は、404（未対応の旧 sim）だけ無視する。それ以外は全体と名前ごとの反映エラーを仕向パネルに表示し、ファイル読み込みエラーとは分ける。

仕向のファイル（`GET`/`POST /api/variants`）は `{"version":1,"selected":名前,"variants":[{"name","values":[{"name","value","mode"}],"inputs":[…],"watch":[…]}]}`。各仕向の `inputs`（入力パネル）と `watch`（監視一覧）は任意。
保存先はサーバが起動時に決めた 1 か所だけで（sim.cfg の `gui_variants`、既定は sim.cfg と同じフォルダの `sim_gui_variants.json`）、
要求からパスを受け取らない。一時ファイルに書いてから置き換える。中身の検査は `variants` が配列であることまでで、残りは GUI が読むときに捨てる。

信号情報ファイル（`GET`/`POST /api/signals`）も起動時に決めた 1 か所に保存する。
`sim.cfg` の `gui_signals` で指定し、相対パスは `sim.cfg` のフォルダから解決する。
既定は同じフォルダの `sim_gui_signals.yaml`。要求からパスは受け取らない。
中身は YAML の生テキストで、サーバは解析せず、GUI が信号の意味（lsb・offset・単位・状態名）と見た目（グループ・高さ・色）を解釈する。
GET は日本語・改行・タブ・引用符・バックスラッシュを JSON 文字列として返し、POST は本文をそのまま保存する。
ファイルがなければ `exists:false,text:null,error:""`、読めなければ `exists:true,text:null,error:"信号情報ファイルを読めません"`。
保存は仕向と共通の処理で `<path>.tmp` を書いてから置き換え、NUL を含む本文は拒否する。

### 記録と CSV 保存

保存した CSV を `sim run` で（`--expect-actual` なしで）実行し直すと、全行 OK になるように記録する。

- 入力列には、その周期に書いた**セルの元の文字列**を残す（`'XYZ'`、`1|2|3`、`0x78` など。数値に直して丸めない）。
  ','・'"'・前後の空白を含む値は `"..."` で囲む。
- **書き込み（`/api/write` の単発・固定、CSV の再生）は、止まっているときも含めて、すぐにはメモリへ反映しない。
  常に次の周期（ステップ）の開始時に、入力列の順に、列ごとに最後の 1 個だけを書いて記録する。** これは `sim run` が
  CSV の 1 行を処理する規則（入力列を左から順に 1 回ずつ書いてから関数を呼ぶ）と同じなので、記録と再実行が
  構造的に一致する。止まっている間に書いた値は `state` の `pending` に出し、メモリ（`values`）は次のステップまで変わらない。
- 入力適用前に、その周期で採用する全入力の値をメモリを変えずに検証する。1 個でも入力の解析・検証・書き込みに
  失敗した周期は関数を呼ばず、記録行を作らず、ステップ番号も進めない。実行・CSV 再生・残りの `step` を停止する。
  `state.error` に入力名・値・失敗理由を入れ、CSV の入力なら先頭ブロック内のデータ行番号（1 始まり）も示す。
  `step N` の応答は、失敗前に進んだ数を `stepsDone`、失敗を `error` で示す（待ち時間超過でなければ `timedOut:false`）。
  試行した周期の単発入力は消費し、固定は残す。
  NULL ポインタの先など、メモリ状態に依存する失敗は実際に書く時点で分かる。この場合はそれまでに書いた入力や
  確保した領域を巻き戻さず、途中まで書かれた状態で止まり、`needReset:true` にする。失敗した周期は記録に含まれないため、
  初期状態に戻すまで `run`・`step` と `/api/write`（単発・固定・解除）を 400 で拒否し、何も変えない。
  監視・シンボル検索・info・SSE・CSV 保存は使え、失敗までの正常な記録はそのまま保存して再実行できる。
- 対象関数の呼び出しが未定義命令・命令数上限などで失敗した周期も、記録行を作らずステップ番号を進めない。
  実行・CSV 再生・残りの `step` を停止し、`stepsDone` は失敗前に進んだ数を返す。
  `state.error` にバックエンドの失敗理由（PC・逆アセンブルなど）とリセットの案内を出す。
  入力の書き込みと関数の途中までの実行は巻き戻さないため、失敗後は同じく `needReset:true` にして実行・書き込みを拒否する。
  要リセットと `error` を解除するのは、`reset`、実際の対象関数変更、`/api/load-csv` の成功だけ。
  いずれも初期状態へ戻して記録を消し、ステップを 0 から数え直す。pause・速度や周期の変更では解除しない。
- 入力列の順は列番号の昇順。受け付けた順や種類の順に書くと、同じメモリを指す入力（`P1` の固定と `P1_bit.no0` の
  単発書き込みなど）で結果が再実行と変わる。
- 同じ周期に同じ変数（同じ名前）へ何度か書いたときは、最後の 1 個だけを書いて記録する。単発どうしは後から書いたものが
  前のものを置き換え（反映待ちは名前ごとに 1 個）、種類が違えば単発 → 固定 → 再生の順で後のものを採る（固定した名前への
  単発書き込みは、その周期も固定の値になる）。前のものも書くと、`$` の確保が二重になる、長い文字列の残りが残るなど、
  1 列 1 セルの CSV の再実行と合わない。空の値（空セル）は書かず、記録もしない（空文字列 `''` は書く）。
- 固定を外す（`release`）と、その名前の反映待ちも捨てる。次の周期までに固定して外した値は書かれず、記録にも残らない。
- 入力列の番号は、記録が空になったとき（リセット・関数の変更・CSV の読み込み）に組み直す。読み込んだ CSV を再生して
  いるなら、その CSV の入力列をその順で先頭に並べ、続けていま残っている固定（CSV にない名前）を並べる。
  その後に初めて書き込んだ名前は後ろに足す。以前に書いた順の番号を使い続けると、再生が CSV の入力列と違う順に
  書いてしまい、`sim run` の結果と変わる（`P1`、`P1_bit.no0` の順に書いた後で `P1_bit.no0,P1` の CSV を再生するなど）。
  出力列は監視の順で組み直す。
- 記録は**入力 1 名 = 1 列**なので、`/api/load-csv` は同じ名前（前後の空白を除いて完全一致）の入力列が複数ある CSV を
  400 で拒否する。`sim run` は `P1,P1_bit.no0,P1` のような列を左から順に別々に書く（`0,1,2` なら `P1 = 2`）が、
  GUI で同じ列にまとめると最後の値を先頭の列の位置で書くことになり（`P1 = 3`）、再実行と合わない。列を別々に
  持つと保存した CSV との往復が複雑になるため、拒否する方を採った。そうした CSV は `sim run` で実行する。
  表記が違うだけで同じメモリを指す入力列（`P1` と `P1_bit.no0`、`a[0]` と `a[ 0 ]`、`g.x` と `g .x`）は別の列として受け付け、
  列の順に書く。出力列どうし・入力列と出力列が同じ名前なのは受け付ける。
- `/api/load-csv` は先頭ブロックの全データ行の入力セルを、状態を変えずに解析・型検証する。解析できない値や
  型に収まらない値は、データ行番号・CSV 列番号（コメント列が 1 列目）・入力名・値・理由を示して 400 で拒否する。
  先頭ブロックのデータ行が 0 行でも「再生するデータ行がありません」と 400 で拒否する。
  どちらも関数・引数・実行・再生・記録・固定・監視を変えない。再生開始後の入力失敗はメモリ状態に依存するものだけ。
  N 行の CSV は最後の行を実行・記録した時点で一時停止し、残りの `step` も打ち切る。余分な周期は実行しない。
- `/api/load-csv` が再生するのは先頭の `mod` ブロックだけ（2 つ目以降は読まない）。ブロックが複数あれば、応答の
  `blocks`（ブロック数）と `warning`（メッセージ）で知らせる。
- 1 周期 = 1 行。入出力のセルがすべて空になる周期（監視・入力を登録する前の周期、途中で外した後の周期、監視も入力も
  ないまま保存したときの入力数 0・出力数 0 のブロックの全行）は、1 列目（コメント欄）に `step N`（N はその周期の
  ステップ番号）を入れる。全セルが空の行は `sim run` が空行として読み飛ばし、関数の呼び出し回数が記録と合わなくなるため。
  入出力の列が 1 つもなければ `step N,` と区切りのカンマを付ける。Viewer はカンマのない `step N` も 1 周期として数える。
  ほかの行の 1 列目は空のまま（以前の保存結果・WinAMS との互換のため）。
- 出力列は `sim run` が結果 CSV に書くのと同じ表記で残す（配列や `&arr` は全要素、文字なら `'...'`）。
  SSE の `samples` と `values` はこれまでどおり数値（配列なら先頭の要素）か `null`。
- **対象関数を変えると、ターゲットをリセットして記録を区切る**（それまでの記録は消え、ステップは 0 から数え直す）。
  `sim run` は `mod` ブロックの初めにリセットするので、前の関数の続きの状態から記録を始めると、保存した CSV の再実行と合わない。
  関数ごとに別の `mod` ブロックとして出す方法もあるが、その場合も各ブロックの初めの状態を揃えるにはリセットが要るため、
  関数を変えたらリセットする方を採った。保存する CSV は常に `mod,<今の関数>` の 1 ブロック。
- 記録は最大 `--record-max`（既定 20 万）周期。超えると古い周期から捨てるので、その場合の保存結果は途中の状態から始まり、
  再実行と合わないことがある。
予定より遅れたステップは、次の周期を待たずに始めて取り戻す。遅れが 4 周期ぶん（最低 20 ms）を超えたら、
実時間に追いつけないとみなして `overrun` を立て、その時刻から数え直す（OS の起床の遅れや 1 ステップだけの重い計算では立てない）。`speed` は 0.1〜100 と「最速」(0)。

### 周期の待機と制御要求

Windows の GUI 起動時は `timeBeginPeriod(1)` でタイマ刻みを 1 ms にし、既定の約 15.6 ms への Sleep(1)・条件変数待ちの切り上げによる遅れの蓄積を抑える。
実行時に API を取得できない場合は従来の刻みで動作し、設定成功時は正常終了・起動失敗時に `timeEndPeriod(1)` で戻す（`sim run` には適用しない）。

1 周期の間隔は `periodMs / speed`（最大 60000 / 0.1 = 10 分）。周期実行のスレッドは次の期限まで条件変数で待ち、
`/api/control`（run / pause / step / reset、`speed`・`periodMs`・`func` の変更）と `/api/load-csv` の通知ですぐに起きて、
実行状態と期限を確かめ直す。古い周期の終わりまで待たされることはない。

- `pause`・`step`・`reset`: 待つのをやめる。`step` はすぐに N 回実行する。
- `speed` を 0（最速）にした: すぐに次のステップを始める。
- 実行中に `periodMs`・`speed` を変えた: 次のステップは「前のステップの予定時刻 + 新しい間隔」に始める。
  それがもう過ぎていればすぐに始める（変更による遅れなのでオーバーランにはしない）。その後は新しい間隔で数える。
  短くすればすぐに新しい周期で進み、長くすれば前のステップから新しい間隔だけ空ける。
- 記録をやり直す操作（`reset` 以外で実行中のままのもの: `func` の変更、CSV の読み込み）: すぐに 1 ステップ目を始め、そこから数え直す。
- それ以外（書き込み、実行中の `run` など）: 期限は変えない。

期限の精度を落とさないよう、期限の少し手前（POSIX 2ms、Windows 25ms。Windows の条件変数の時間切れはタイマの刻み
15.6ms 単位で遅れるため）までを条件変数で待ち、残りは従来どおりの高精度な待ち方（POSIX は `nanosleep`、Windows は
高分解能の待機タイマ）で待つ。この最後の短い区間に来た制御要求は、その区間の分（最大でこの幅）だけ遅れて効く。
1ms・0.01ms などの短い周期では従来と同じ待ち方になる。条件変数の 1 回の待ちは最大 1 秒に区切る（POSIX の時間切れは
実時間の時計で数えるので、時計を戻されても待ちすぎない）。

サーバは Ctrl+C（既定のシグナル処理）でプロセスごとすぐに終わる。標準入力は見ていない。
HTTP の接続は受信・送信とも 10 秒で時間切れにし、読まずに止まったクライアントへの SSE の送信スレッドも残さない。

## CA78K0R / LMF

`--abs` と sim.cfg の `abs` は、拡張子によらず先頭バイト `7F 45 4C 46` を ELF、`48 11` を LMF として読む。
それ以外は先頭4バイト（短いファイルでは実際に読めた長さも）を示してエラー。
`abi = auto`（既定）は ELF→`ccrl`、LMF→`ca78k0r`。明示指定でも上書きできる。
`sim info` はファイル種類と選択ABIを表示する。読み込むデバッグ形式はABI上書きでは変わらない。

LMF は `rl78_lmf.c` でヘッダ・セクション・20Bシンボル/補助・文字列表を境界確認して読む。
`fsize>0` のセクションの内容だけ物理アドレスへ置く。RAM初期値はリセットからスタートアップを実行してコピーする。
`_main` 等のC名の先頭 `_` を外し、関数・引数、グローバル、静的アドレスを持つstatic変数を登録する。
モジュール寄与範囲から変数の所属ファイルを選ぶ。同じ開始ならリンク順で最後を選ぶ。
関数内staticは `.bf`〜`.ef` の間（入れ子ブロックを含む）のstaticエントリから登録する。
`file.c/name`、`file.c/func@name`、`func@name` で参照でき、別関数の同名staticも区別する。
`_@STBEG/_@STEND` とセクションの割当をスタック・ヒープ・番兵の自動選択に使う。

[LMF_FORMAT.md](LMF_FORMAT.md) の実測コードに従い、char/short/int/long と unsigned 各種、
float/double（ともに4B）、1/2Bの符号付きenum、構造体・共用体・入れ子・無名タグ・ビットフィールド、
最大4次元配列、near（2B）/far（4B）ポインタとその派生型の鎖、関数ポインタを復元する。
typedef名は残らないので展開した型として扱う。メンバの配置は記録されたバイト/ビット位置を使う。
タグ参照は補助込みのエントリ番号を使い、範囲、種別、終端リンク、サイズ、メンバの範囲を検証する。
循環参照や過度に深い入れ子も有限の深さで打ち切り、型不明として警告する。
farポインタは `{offset16, page8, 0}` の4B。式の間接参照では下位20bitを物理アドレスへ変換する。
nearデータポインタは下位16bitに0xF0000を補う。const/volatileは表示に残し、constとROM変数は書き込み不可。
charとsigned charは同じ型コードなので既定は符号付き、`char_unsigned = on`（-qu相当）で両方を符号なしにする。

残る制限:
- signed int のビットフィールドはLMFでunsigned intと区別できず、unsignedとして読む（-3の4bit値は13）。
- bit変数（0x034C、記憶クラス0x27）のビット位置、5次元以上の配列、未観測の派生型・修飾の組合せは推測せず型不明。
- 関数ポインタの引数型はLMFに残らない。関数補助にはポインタ種別/寸法がないため派生型の戻り値も型不明。
- スモール/ラージモデルの呼び出し全体は未確認。実測したミディアムモデルを基準とする。
未対応・不正な型は名前・アドレスと判明したサイズを残し、`--verbose` で型コード・記憶クラスを警告する。
型なしのランタイムラベル(typ=0,x=0)自体は既知なので警告しない。`名前:バイト数` で明示的に読み書きできる。

CA78K0R ABI は第1引数の1/2B整数・nearポインタをAX（1BはX）、4B整数・farポインタをAX=下位/BC=上位へ置く。
第2引数以降は右から左に積むのと同じ配置で、戻り番地4Bの次から宣言順に1B→2、2B→2、4B→4の枠を置く。
4Bの下位ワードは低位アドレス。戻り値は1BがC、2BがBC、4BがBC=下位/DE=上位。
`skip = 関数:値` も型幅に応じて同じ戻り値レジスタへ生ビット列を設定する。
3B、構造体/共用体の値渡しと戻り値、未知型、可変引数は明示エラー。
実測の6B構造体戻り値は関数固有のstaticな一時領域へコピーし、そのnearアドレスをBCで返すが、今回は未対応。
float/doubleは変数として読み書きできる。floatは4B整数と同じ引数/戻り値レジスタを使うが、
共通部分の浮動小数引数の制限を維持する。CA78K0Rのfloat/doubleの関数引数・戻り値は今回は対応外。
BOOL戻り値を型表現で持つ場合はCYだが、LMFのbit型自体は復元しない。
`rl78_abi.c` にCC-RLのレジスタ割当とCA78K0Rの型制約・戻り値処理を分離する。
PCを20bitのまま設定し、4B戻り番地を積む部分を共有する。

同名 `.sym` があれば `rl78_sym.c` で名前・公開/ローカル・アドレスをLMFの生シンボルと照合し、不一致は警告する。
シンボル表が全く無ければ `.sym` の属性01を引数なし関数、02を未知型変数、00をアドレス解決用の定数として補う。
`.sym` は型を持たないので、変数には `名前:バイト数` が必要。bit属性03は位置を推測せず読み飛ばす。
`.sym` 単独/HEXの入力、部分デバッグ情報への不足シンボル追加、モジュール順・属性の完全照合は未対応。

CIの自己完結テストは `tests/tools/mklmf.c` と手書き `lmfprog.s` の埋込機械語、および
`tests/ca78k0r_probe/DefaultBuild/ca78k0r_probe.lmf` を使う。probeの57変数の表示・アドレス・サイズと
17関数の引数/戻り値を参照解析器由来のテキストに照合し、CSVで初期値・呼び出し・書き込みを確認する。
期待値は開発時に `python3 -I tests/rl78/make_probe_expected.py` で生成する。
CIはCのチェッカと `cmp` / `fc /b` だけで比較し、Pythonは使わない。期待値の改行はLF固定（.gitattributesの-text）。
実物の任意検証は `LMF_SAMPLES` を指定して `tests/rl78/check_lmf_samples.sh`（開発機のPython/clangを使用）を実行する。
未設定なら明示的にスキップする。サンプルをリポジトリにコピーしない。
機械語の根拠と発振待ちの回避設定は [CA78K0R_NOTES.md](CA78K0R_NOTES.md) を参照。


## スタートアップが通らないときの調べ方

周辺機能（クロック、A/D、リセット要因など）の状態・リセット値は模擬しない。
CPU 内蔵レジスタ・演算器を除く SFR は通常 0 から始まるメモリであり、発振待ちが終わらなかったり、
実機では呼ばれないリセット関数へ分岐したりすることがある。機密のソースを共有せず、次の診断で場所を絞れる。

```
sim info --abs project.lmf --trace-startup
sim info --abs project.abs --cfg sim.cfg --trace-startup --trace-head 50 --trace-tail 100
```

診断時だけスタートアップを1命令ずつ実行する。通常実行は従来の一括実行を使う。
診断は標準出力、通常のエラーは標準エラーに出る。起動に失敗したときは診断オプションを付けなくても
再実行の案内が出る。`startup_max_insns` は診断時も有効で、まず `10000` など小さくして調べてもよい。
診断なしで失敗した実行を自動で再実行はしない。診断オプション指定時は成功時も診断を出す。

出力の読み方:

- 呼び出し履歴はシンボルの先頭へ来た順。`#` は実行しようとする命令の番号（先頭は1）、
  `SP` とインデントはスタック差を4で割った深さの推定。同じ先頭・SPの連続訪問を `×N` にまとめる。
  再帰は SP が異なるため別件となる。単なる分岐による関数先頭の再訪も含み、CALLだけの厳密な履歴ではない。
  表示は既定で先頭50件と末尾100件。`--trace-head N` / `--trace-tail N` は各1〜10000件。
- 停止位置は PC と関数名+オフセット。直前32命令は実際に実行した PC 順の逆アセンブルで、
  未定義命令などの未実行の停止命令は別に出す。AX/BC/DE/HL、SP/PSW/ES/CS/PMCも表示する。
  関数名は直前のシンボルから推定するため、シンボル間の空き領域では所属が確実とは限らない。
- バックトレースは現在の SP から2バイト単位で最大64枠を探索し、4バイトの戻り番地の下位3バイトを20ビットの候補として表示する。
  PUSHや局所変数を読み飛ばし、CALL命令直後の番地だけを候補にする（4バイト枠の重複は除外）。
  残る1バイトは通常RETでは読み飛ばす領域。局所変数やPUSHされたレジスタを誤認することもあり、
  フレーム情報を使う厳密な復元ではない。インデントも局所変数・PUSHによって深く見える。
- 失敗時、直近256命令（最低64命令）が幅256バイト以内を回り、停止PCが3回以上現れるとループ候補を表示する。
  アドレス範囲・関数と、その区間で実際に読んだメモリ番地・最後に読んだバイト値・読出PCを出す。
  直近2048バイト分の読出履歴から番地を重複排除し最大64番地を表示する。大きなループや長い待ち処理の内外を
  必ず検出できるわけではなく、値の変化を待っているという表示は推測。メモリ全体のダンプは出さない。
- 未設定SFRは `0xFFF00〜0xFFFFF` と拡張SFR `0xF0000〜0xF07FF` のうち、
  プログラムの書き込み前に読んだ番地。番地ごとに初出順で初回の値・命令PC・関数・書き込み前の読出回数を表示する。
  ワードアクセスは2番地に分ける。RAMは含まない。`poke` で指定した番地は設定済みとして扱う。
  SP・PSWなどのCPU内蔵レジスタは0以外の場合があり、この一覧だけで不具合とは判断しない。
  CPU内部で直接更新されるレジスタや演算器の内部アクセスはバスフックに来ない場合がある。

診断後、原因に合わせて `sim.cfg` を設定する（以下の番地は書式の例。製品のマニュアルで確認する）。

```
# 状態ビットの初期値を与えたい
poke = 0xFFFA2:1
poke = 0xF00A8:0x1234:2
# ハードウェア待ちの関数を実行しない
skip = R_CGC_Create
# 型が分かる整数の戻り値を与えて即時復帰
skip = read_adc:0x1234
# 別のソフトウェア処理へ置き換えたい
stub = read_port:AMSTB_read_port
# 初期状態を控える位置を変えたい
init_end = main
```

`poke = 番地:値[:バイト数]` はリセット直後・スタートアップ前に、20ビットの物理番地へ値をリトルエンディアンで書く。
バイト数は既定1、1〜4。数値は10進または`0x`16進、符号・末尾のごみ・8進と紛れる先頭0はエラー。
値は指定バイト数に収まり、書き込み全体が1MB内に収まる必要がある。SFRはCPUのバス経由、他は直接ロードする。
複数指定は上から順番に適用する。書いた値を後でソフトがクリアした場合は再度セットされない（`poke_hold` は未対応）。
その後の起動完了状態をスナップショットに含め、CSVのmod切り替えやGUIのresetでその状態へ戻る。

`skip = 関数名[:戻り値]` は関数先頭にブレークポイントを置き、スタックの4バイトを消費して戻り先へPCを移す。
スタートアップにも、CSV・GUIからの関数呼び出しにも効く。通常のCALL/RET専用で、**RETI/RETBで戻る割り込み関数には使わない**。
戻り値を省略すると戻り値レジスタを設定しない。指定する場合はデバッグ情報で型が判明した整数・bool・2バイトnearポインタのみ。
値は符号拡張前の生ビット列で、例えば16ビットの-1は`0xFFFF`とする。
CC-RLは1バイトがA、2バイトがAX、4バイト整数がBC:AX。
CA78K0Rは1バイトがC、2バイトがBC、4バイト整数がDE:BC、boolがCY（既存ABIで対応している割付け）。
構造体・float・farポインタ・型不明などは戻り値指定をエラーにする。
存在しない関数、同じ先頭番地へのstub/skipの重複、戻り値の範囲外、ブレークポイント不足も起動エラー（終了コード2）。
skipはコードを書き換えず、既存stubと合わせた個数によりブレークポイントが不足する場合がある。
有効なskip/pokeは`sim info`に一覧を出す。

ブレークポイントはプログラムから見えるメモリを書き換えない。1MB の別配列に置くトラップマスクを
先頭オペコードのフェッチ時だけ OR し、命令オペランド・データ読み出し・`rl78_peek*` / `rl78_read*`・
`rl78_memory`・スナップショットには適用しない。ミラー（PMC.MAA 切り替えを含む）や `ES:` 経由でも同じ。
RAM のコードへ書き込んだ値はそのまま読み戻せ、ブレークからの再開は最新の命令を実行する。
通常のフェッチとデータ読み出しには、ブレークの有無を調べる分岐を追加しない。
スナップショットの保存・復元は生のメモリをコピーし、復元時点のブレークポイント設定を保持する。

プログラム自身の命令コード `FFH` は、実機では不正命令による内部リセットを起こす。
シミュレータでは `RL78_STOP_UNDEFINED` で停止し、内部リセットと意図的なソフトリセットの可能性を
通常の未定義命令と区別して表示する。PC と命令数は停止命令の実行前のまま保持し、リセットは模擬しない。
スタートアップのエラー、関数呼び出しのエラー、`--trace-startup` を使ったときのエラーにも同じ説明を出す。

通常起動と `--trace-startup` は同じ `run_to` を使う。両方とも、現在 PC が `init_end` なら終了し、
それ以外では stub / skip を適用してから命令を実行する。置換は各1回の命令予算を消費するが、
CPU が実行した命令数には数えない。`poke` は両経路とも起動前に設定順で適用する。
HALT/STOP の方針と命令予算も共有し、割り込みはコアの同じ境界処理に従う
（バックエンドは起動時に割り込みを投入しない）。診断の全域バスフックは、読み出しを `peek`、
書き込みをフック解除後の通常バスへ委譲する。ブレークの旧実装では、このフックがある診断時だけ
ミラーの高速経路からの FFH 漏れを回避していた。ELF / LMF のチェックサム起動テストは、
stub・skip・init_end の先頭を含む範囲を読み、両経路で main 到達・命令数・クロック数が一致すること、
実際に ROM を壊すと両経路とも FFH の診断で止まることを確認する。


`skip` は副作用も全て省くため、必要な初期化まで消さないよう診断で対象を絞る。
`stub` は戻り値以外の副作用を実装したい場合に使う。`init_end` を早めると後続の初期化が済んでいない状態を
初期状態にするので、単に上限を避ける目的で変更せず、その状態で対象関数を実行できるか確認する。
固定読出値の`poke_hold`は未対応。条件分岐履歴は下記の診断起動で採取する。

### 通常起動と診断起動の比較

`--trace-startup` は、通常経路を1回実行した後、起動前（poke適用・ブレーク設定後）の
スナップショットへ戻して診断経路を1回実行する。先頭の `startup compare` に両経路の成功／失敗、
停止PC、実行命令数を並べる。メモリ全体・レジスタ・クロック数も比較し、不一致はMISMATCHとする。
比較後は通常経路の状態を復元する。いずれかが失敗した場合や不一致は起動エラー。
エラーは通常／診断のどちらのものかを明記し、FFH経路では最後の分岐・CALLと条件分岐の末尾64件を表示する。
各分岐は実行前後のPCから向きを判定し、直近のバス読み出し番地・値・読出PC・命令番号を併記する。
これは条件との因果関係を保証するものではなく、読み出しがない場合はnoneとする。
エラーの `original bytes` はマスクを含まないバイトで、ブレークの登録有無と役割、関数+オフセットを併記する。

以前のコードは診断指定時には診断経路だけを1回実行していた。
またCPU内部のPSW書き込み等によるループ分割で、次のPCにあるブレークを公開APIからの再開と誤認していた。
再開扱いを公開rl78_runの開始時だけに限定し、通常経路だけがinit_endやstub/skipを飛ばす問題を修正した。
製品LMFでの原因は、この内部境界を通っていたかの確認が必要。

明示的な直アドレス変数は `var = 名前 : 型 @ 番地`、別ファイルは `varfile = パス` で設定する。
型は u8/s8/u16/s16/u32/s32/f32、`u8[16]` の配列、`u8.0` や `u8.4-6` のビット範囲を扱う。
番地は20ビット物理番地で、ヘッダやロードモジュールより明示定義を優先する。
通常のSFRは周辺機能を模擬しないメモリで、監視にはプログラムが書いた値が見え、入力として書けばプログラムが読む値になる。

### 型の const と参照の書き込み可否

`sim_type.is_const` は型自身の修飾で、`sim_member.type`、配列の `target`、ポインタの `target` にも保持する。
`sim_var.is_const` は変数自身やROM配置による既存の制限として併用する。
メンバと配列要素は、経路上の const を引き継ぐ（const の構造体のメンバ、const の配列の要素は書き込み不可）。
ポインタをたどった先は、指す先の型の const だけで決まる。ポインタ自身の const（`T * const p`）は `p` への書き込みだけを禁じ、`p[0]` や `*p` には引き継がない（C の規則）。
グローバル変数、ファイル内static、関数内staticは、変数自身・経路上の型・指す先の型の
いずれかがconstなら書き込み不可。ROM配置も引き続き書き込み不可とする。
位置を解決できない自動ローカル変数は従来どおり未対応で、constを理由に使用可能にはしない。
これをCSV入力、GUI書き込み、シンボルのwritable照会で共用する。

例外は呼び出し側で準備する引数（`@p`、`関数@p`）を起点とする参照。
LMF・DWARFの関数登録では、共有型を変更せず、引数型の最上位constだけを除去する。
指す先のconstは型情報として保持するが、共通参照処理は引数とその先のconstを
書き込み制限に使わない。`T * const`、`const T *`、`const T * const`、値渡しの`const T`を
渡せるほか、`$@p`で領域を確保し、`@p[0]`、`@p->member`、`*@p`から入力データを準備できる。
確保したかどうかによらず、引数を起点とするポインタの先に適用し、モックも同じ扱いとする。
型による制限の例外であり、バックエンドのアドレス・ROM書き込み制限は解除しない。
通常の変数を起点とする`$ptr`、`ptr[0]`、`*ptr`にはこの例外を適用しない。
戻り値（`func@@`）自身はconstの有無によらず入力不可・読み取り可能で、
`skip = 関数:値`の戻り値も型の幅と種類に従う。
ヘッダとDWARFのconst型（typedef経由のメンバ・配列要素も含む）を保持する。
LMFはオブジェクト自身の修飾 `0x5000`（near付き `0x5100` も同様）を型に保持し、ROM配置の制限も従来どおり併用する。
LMFに残らない指す先のconstは復元しない。
